# Day 14 数字电压表 - 校准记录

> 电路参数：R_HI = 10kΩ，R_LO = 1kΩ，分压比 11:1，量程 0~36.3V
>
> `CAL_SCALE` 在 .ino 里搜 `const float CAL_SCALE` 即可找到（行号会随注释变动）。

---

## 一、校准源怎么选

| 源 | 能用吗 | 原因 |
|----|--------|------|
| 板上 **5Vin** 引脚 | ❌ | 它是电源**输入**脚，不是稳压输出，没有驱动能力。万用表（10MΩ）能量到 4.4V，但接上 11kΩ 分压负载后电压直接 collapses 到 0 |
| 板上 **3V3** 引脚 | ✅ | 板载 LDO 输出，有驱动能力 |
| 剪掉充电头的 **USB 线**（红 5V / 黑 GND） | ✅ | 真正的电源，有驱动能力。**黑线必须与 ESP32 共地** |
| 5 号电池 / 18650 | ⚠️ | 电压已知且稳定，但每节都不同，得先量 |

## 二、原始读数（CAL_SCALE = 1.000）

用板上 3V3 引脚，万用表真实值 3.33 V：

| 次序 | 本表原始读数 | 误差 |
|------|------------|------|
| 第 1 次 | 3.24 V | −2.7% |
| 第 2 次（几分钟后） | 3.31 V | −0.6% |
| 第 3 次（重新上传后） | 3.23 V | −3.0% |

⚠️ **同一个 3V3，三次读数散 ±1.2%**（3.24 → 3.31 → 3.23）。这是后面所有麻烦的根源。

## 三、三次系数尝试

### 尝试 1：`1.0538` ❌ 过校正

当时把原始读数误记成 3.16 V（截图实际是 3.24 V）：

```
CAL_SCALE = 3.33 / 3.16 = 1.0538
```

上传后 3V3 读数变成 **3.49 V（+4.8%）**，比不校准的 −2.7% 还差。

### 尝试 2：`1.0055`（当前值）

按第 2 次读数 3.31 V 重算：

```
CAL_SCALE = 3.33 / 3.31 = 1.0055
```

上传后实测（截图 [`校准后的读数.png`](./校准后的读数.png)，12:05）：

| 被测源 | adc | v_pin | 本表读数 | 万用表真实值 | 误差 |
|--------|-----|-------|---------|------------|------|
| 板上 3V3 | 327 | 0.292 | **3.23 V** | 3.33 V | **−3.0%** |
| USB 线 5V | 510 | 0.451 | **4.99 V** | **没量过** ⚠️ | 未知 |
| 表笔悬空 | 0 | 0.000 | 0.00 V | 0 V | — |

**5V 读 4.99 不代表它准。** USB 充电器空载输出 5.1~5.2 V 很常见（USB 规范允许到 5.25 V）。
如果那根线实际输出 5.14 V，那么 4.99 恰好也对应 −3.0% 误差 —— 和 3V3 点完全一致。

也就是说：**两个点并不矛盾，只是 5V 那点的真值未知，没法用来校准。**

### 尝试 3：`1.0367`（按第 3 次读数算，暂不采用）

```
CAL_SCALE = 3.33 / 3.23 × 1.0055 = 1.0367
```

能把 3V3 点修到 ~0%，但**先别改**，理由见下一节的坑 1。

## 四、踩过的坑

### 1. 校准后反而更不准 —— 因为真值和读数不是同一时刻取的

已经栽了两次（1.0538 → 3.49 V），根源是同一个：

> 先拿万用表量一次 3V3（得 3.33 V），**过一阵子**再看串口读数（得 3.23 V），
> 然后拿这两个数算系数。

但读数本身就在漂（±1.2%），这两个数不是同一时刻的电压，算出来的系数必然带偏差。

**正确做法：同时测量。** 万用表表笔直接夹在**分压器的 VIN 输入端**（就是你的表笔尖 / 10kΩ 电阻靠外的那个脚），
一边看万用表一边看串口，同一时刻读两个数。这样基准漂移就被消掉了，也是唯一可信的校准方式。

### 2. 别拿未知真值的源当基准

USB 线写着 5V，实际可能是 4.9~5.25 V。4.99 这个读数看着漂亮，但它什么都没证明。
**只有万用表量过的点才能当基准。**

### 3. 单点乘性校准修不了零点偏移

`adc 327` 按理是 `327 / 4095 × 3.3 = 0.264 V`，但 `v_pin` 报 **0.292 V**，差约 **28 mV**。
这是 ESP32 ADC 低端非线性带来的偏移，`vin = vPin × k` 这种纯乘法形式在原理上消不掉它 ——
乘得越大，偏移跟着一起放大。要连偏移一起修，得做**两点标定**：

```
vin = a × vPin + b

a = (V2_true - V1_true) / (V2_read - V1_read)
b = V1_true - a × V1_read
```

### 4. 两点标定现在也做不了

用 v_pin 0.292 / 0.451 两点、假设 USB 真值 5.00 V 拟合：

```
a = (5.00 − 3.33) / (0.451 − 0.292) = 10.50
b = 3.33 − 10.50 × 0.292           = +0.263 V
```

校验 3V3 → 3.330 ✓、5V → 5.000 ✓，看着完美，但两个理由说明它不可信：

1. 斜率 10.50 比标称 11.06（11 × 1.0055）低 5%，等于说 R_HI 偏小约 13%，超出 ±5% 电阻公差；
2. 截距 **+0.263 V 意味着表笔接地时应报 0.263 V**，但实测接地/悬空都是 `adc 0 → 0.00 V`，直接矛盾。

根子：两点只跨 v_pin 0.292~0.451（输入 3.2~5.0 V），这么窄的一段去外推 0 V 和 12 V / 24 V 不成立。

**结论：保持 `1.0055`，先别改，也别做两点标定。**

## 五、下一步（按优先级）

1. **做一次同时测量**：万用表夹在表笔尖，同读 3V3。若万用表 3.33 / 串口 3.23，
   则 `CAL_SCALE = 3.33 / 3.23 × 1.0055 = 1.0367`，写入后重新上传验证
2. **用万用表量一下 USB 线的红黑线电压**，把 5V 那点变成可用基准（第二个校准点）
3. 有了两个可靠点且跨度够大（比如 0 V 和 12 V），再考虑两点标定
4. 量 5 号电池（~1.5 V）、18650（3.0~4.2 V）做交叉验证
5. 用万用表直接量两个分压电阻的真实阻值，填进 R_HI / R_LO，进一步降误差

## 六、误差预算

| 误差来源 | 量级 | 状态 |
|---------|------|------|
| Vref 不准 | ±5% | ✅ 已用 `analogReadMilliVolts()` 读 eFuse 出厂校准值 |
| ADC 噪声 | ±1~2 LSB | ✅ 16 次采样平均 |
| 源阻抗过高 | −5~15% | ✅ 改用 10kΩ+1kΩ（909Ω），根子上解决 |
| **读数漂移** | **±1.2%** | ⚠️ 当前主要误差源，靠同时测量解决 |
| 电阻公差 | ±10% | ⚠️ 靠单点校准 |
| ADC 低端非线性 | ~28 mV 偏移 | ⚠️ 避开，代码已标 `LOW` + 蓝灯 |

## 七、已知限制（不用修）

- **< 1V 读数不可信**：ESP32 ADC 低端线性度差，代码已标 `LOW` + 蓝灯
- **量程上限 36.3V**：超过会烧 GPIO，≥30V 时红灯预警
- **只能测直流**：本表无隔离，严禁测市电
