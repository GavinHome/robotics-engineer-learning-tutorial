## 第 1 天 — 欧姆定律

### 目标
理解电压、电流和电阻。搭建并仿真你的第一个电路。用实际测量值验证欧姆定律。

### 仿真截图

- **Falstad 仿真 — 单电阻 (220 Ω @ 5 V):** [`day-01/220Ω.png`](day-01/220Ω.png)
- **Falstad 仿真 — 单电阻 (10 kΩ @ 5 V):** [`day-01/10kΩ.png`](day-01/10kΩ.png)
- **Tinkercad 注册成功:** [`day-01/tinkercad.png`](day-01/tinkercad.png)

### Falstad 电路文件

- **可复用电路模板：** [`day-01/series-resistor-circuit.txt`](day-01/series-resistor-circuit.txt)
  - 从 Falstad 导出的 1 kΩ 串联电路
  - 导入方法：打开 https://www.falstad.com/circuit/ → File → Import → 粘贴文件内容
  - 修改电阻值：找到 `<r ... r="1000"/>`，将 `1000` 改为目标电阻值（单位 Ω），即可快速重现不同电阻的仿真

### 实测数据对比

| 电阻值 | 电流 (I) | 功率 (P) | 计算验证 |
|--------|----------|----------|----------|
| 1 kΩ | 5 mA | 25 mW | I = 5V/1kΩ = 5mA, P = V×I = 25mW ✅ |
| 220 Ω | 22.727 mA | 113.636 mW | I = 5V/220Ω ≈ 22.7mA, P = 25/220 ≈ 113.6mW ✅ |
| 10 kΩ | 500 µA | 2.5 mW | I = 5V/10kΩ = 0.5mA, P = 25/10000 = 2.5mW ✅ |

> 验证结论：所有实测值与欧姆定律 I = V/R 和功率公式 P = V²/R 完全吻合。

### 计算公式

**1. 欧姆定律**
```
V = I × R
```
- `V` = 电压，单位伏特 (V)
- `I` = 电流，单位安培 (A)
- `R` = 电阻，单位欧姆 (Ω)

> 来自我的 Falstad 仿真验证：
> - 5 V 接 1 kΩ → I = 5 V / 1000 Ω = **5 mA**
> - 5 V 接 220 Ω → I = 5 V / 220 Ω ≈ **22.727 mA**
> - 5 V 接 10 kΩ → I = 5 V / 10000 Ω = **0.5 mA (500 µA)**

**2. 功率消耗**
```
P = V × I = I² × R = V² / R
```
- `P` = 功率，单位瓦特 (W)
- 常见直插电阻额定功率为 1/4 W（0.25 W）

> 来自我的 Falstad 仿真验证：
> - 5 V 接 1 kΩ → P = 25 / 1000 = **25 mW**
> - 5 V 接 220 Ω → P = 25 / 220 ≈ **113.6 mW**
> - 5 V 接 10 kΩ → P = 25 / 10000 = **2.5 mW**（远低于 1/4 W 额定值）

### 快速参考

| 符号 | 含义 | 单位 |
|------|------|------|
| `V` | 电压 | 伏特 (V) |
| `I` | 电流 | 安培 (A) |
| `R` | 电阻 | 欧姆 (Ω) |
| `P` | 功率 | 瓦特 (W) |

### 实测数据

**1. 串联电路 (1 kΩ + 2 kΩ)**

| 参数 | 实测值 | 计算值 | 验证 |
|------|--------|--------|------|
| 总电阻 | 3 kΩ | 1k + 2k = 3k Ω | ✅ |
| 总电流 | 1.667 mA | 5V / 3kΩ ≈ 1.667mA | ✅ |
| 中间点电压 (Vout) | 3.333 V | 5 × 2k / (1k+2k) = 3.33V | ✅ |
| 1kΩ 功率 | — | I² × R = (1.667m)² × 1k ≈ 2.78mW | — |
| 2kΩ 功率 | — | I² × R = (1.667m)² × 2k ≈ 5.56mW | — |

> 分压公式验证：Vout = Vin × R2 / (R1 + R2) = 5 × 2000 / 3000 = **3.333 V**

**2. 并联电路 (1 kΩ // 1 kΩ)**

| 参数 | 实测值 | 计算值 | 验证 |
|------|--------|--------|------|
| 等效电阻 | 500 Ω | (1k × 1k) / (1k + 1k) = 500Ω | ✅ |
| 总电流 | 10 mA | 5V / 500Ω = 10mA | ✅ |
| 各支路电流 | 5 mA | 5V / 1kΩ = 5mA | ✅ |

> 并联公式验证：1/Req = 1/R1 + 1/R2 → Req = 500 Ω，总电流 10mA = 5V/500Ω ✅

### 公式总结

**分压公式**
```
Vout = Vin × R2 / (R1 + R2)
```
- 适用于串联电路，R2 是下端电阻（靠近 GND）

**串联等效电阻**
```
R_eq = R1 + R2 + ...
```

**并联等效电阻**
```
1 / R_eq = 1/R1 + 1/R2
或
R_eq = (R1 × R2) / (R1 + R2)
```

## 第 3 天 — 基尔霍夫定律（KCL/KVL）与功率计算

### 目标
理解 KCL（基尔霍夫电流定律）和 KVL（基尔霍夫电压定律），计算每个元件的功耗，并理解电阻额定功率的意义。

### 仿真截图

- **Tinkercad 仿真 — KVL（串联分压 1 kΩ + 2 kΩ @ 5 V）:** [`day-03/电路A-KVL.png`](day-03/电路A-KVL.png)
- **Tinkercad 仿真 — KCL（并联分流 1 kΩ // 1 kΩ @ 5 V）:** [`day-03/电路B-KCL.png`](day-03/电路B-KCL.png)

### 实测数据

**1. KVL 验证 — 串联电路 (1 kΩ + 2 kΩ)**

| 参数 | 实测值 | 计算值 | 验证 |
|------|--------|--------|------|
| 总电阻 | 3 kΩ | 1k + 2k = 3k Ω | ✅ |
| 总电流 | 1.667 mA | 5V / 3kΩ ≈ 1.667mA | ✅ |
| 1kΩ 电压 (V1) | 1.667 V | I × R = 1.667m × 1k ≈ 1.667V | ✅ |
| 2kΩ 电压 (V2) | 3.333 V | I × R = 1.667m × 2k ≈ 3.333V | ✅ |
| V1 + V2 | 5.000 V | 1.667 + 3.333 = 5V | ✅ |
| 1kΩ 功率 | 2.78 mW | I² × R = (1.667m)² × 1k ≈ 2.78mW | — |
| 2kΩ 功率 | 5.56 mW | I² × R = (1.667m)² × 2k ≈ 5.56mW | — |

> KVL 验证：沿回路一周，电压降之和 = 1.667V + 3.333V = 5V = 电源电压 ✅

**2. KCL 验证 — 并联电路 (1 kΩ // 1 kΩ)**

| 参数 | 实测值 | 计算值 | 验证 |
|------|--------|--------|------|
| 等效电阻 | 500 Ω | (1k × 1k) / (1k + 1k) = 500Ω | ✅ |
| 总电流 | 10 mA | 5V / 500Ω = 10mA | ✅ |
| 支路 1 电流 | 5 mA | 5V / 1kΩ = 5mA | ✅ |
| 支路 2 电流 | 5 mA | 5V / 1kΩ = 5mA | ✅ |
| I_total = I1 + I2 | 10 mA | 5mA + 5mA = 10mA | ✅ |
| 各支路功率 | 25 mW | V² / R = 25 / 1k = 25mW | — |

> KCL 验证：流入节点总电流 = 流出各支路电流之和 = 10mA ✅

**3. 功率对比（理解额定功率）**

| 电阻值 | 接 5V 时的功率 | 1/4W 额定值 | 是否安全 |
|--------|----------------|-------------|----------|
| 1 kΩ | 25 mW | 250 mW | ✅ 安全（仅 10%） |
| 100 Ω | 250 mW | 250 mW | ⚠️ 已达上限（100%） |

> 思考：100Ω 电阻在 5V 下功耗 250mW，正好等于 1/4W 额定值。实际使用中应留有余量，通常选择额定功率 ≥ 实际功耗 2 倍的电阻。

### 公式总结

**KVL（基尔霍夫电压定律）**
```
∑V = 0 （沿闭合回路，电压升 = 电压降）
V_source = V1 + V2 + ...
```

**KCL（基尔霍夫电流定律）**
```
∑I = 0 （对任意节点，流入电流 = 流出电流）
I_total = I1 + I2 + ...
```

**功率公式**
```
P = V × I = I² × R = V² / R
```

## 第 4 天 — RC 电路与电容充放电

### 目标
理解 RC 时间常数，观察电容充电/放电的指数曲线，掌握时间常数 τ = R × C 的计算方法。

### 工具选择
- **Falstad**：内置示波器可实时观察电容电压随时间变化的指数曲线

### 仿真截图

- **Falstad 仿真 — RC 充电电路 (1 kΩ + 10 μF @ 5 V，示波器显示指数充电曲线):** [`day-04/电容电压变化.png`](day-04/电容电压变化.png)

### Falstad 电路文件

- **RC 充电电路模板：** [`day-04/电路-电容电压变化.txt`](day-04/电路-电容电压变化.txt)
  - R = 1 kΩ，C = 10 μF，电源 = 5 V
  - 导入方法：打开 https://www.falstad.com/circuit/ → File → Import → 粘贴文件内容
  - 示波器已配置：通道 0 = 电容电压，通道 3 = 电源

### 实测数据（仿真验证）

| 参数 | 数值 | 单位 |
|------|------|------|
| 电阻 (R) | 1,000 | Ω |
| 电容 (C) | 10 | μF |
| 电源电压 (Vcc) | 5 | V |
| 时间常数 τ | 10 | ms |
| 5τ (约 99% 充满) | 50 | ms |

> τ = R × C = 1,000 Ω × 10 μF = 1,000 × 10×10⁻⁶ = 0.01 s = **10 ms**
>
> 经过 5τ = 50 ms 后，电容电压达到约 99% 的电源电压（Vc ≈ 5V × (1 - e⁻⁵) ≈ 4.97 V）

### 仿真观察

- **初始状态 (t = 0)：** 电容电压 = 0 V（未充电）
- **τ = 10 ms 时：** 电容电压 ≈ 5V × (1 - e⁻¹) ≈ **3.16 V** (63.2%)
- **2τ = 20 ms 时：** 电容电压 ≈ **4.32 V** (86.5%)
- **3τ = 30 ms 时：** 电容电压 ≈ **4.75 V** (95%)
- **4τ = 40 ms 时：** 电容电压 ≈ **4.91 V** (98.2%)
- **5τ = 50 ms 时：** 电容电压 ≈ **4.97 V** (99.3%)

### 公式总结

**RC 充电公式**
```
Vc(t) = Vcc × (1 - e^(-t/τ))
```
- `Vc(t)` = t 时刻电容电压 (V)
- `Vcc` = 电源电压 (V)
- `t` = 时间 (s)
- `τ` = 时间常数 = R × C (s)

**RC 放电公式**
```
Vc(t) = V0 × e^(-t/τ)
```
- `V0` = 初始电容电压 (V)
- 放电时电容通过电阻释放储存的能量

**时间常数规则**
```
τ = R × C
5τ ≈ 99% 充满/放完
```

### 关键观察

1. **指数上升曲线：** 电容电压不是线性上升，而是指数增长，开始时快，后来慢
2. **τ 的物理意义：** 电容电压从 0 上升到 63.2% 所需的时间
3. **电阻越大充电越慢：** R 增大 → τ 增大 → 曲线更平缓
4. **电容越大充电越慢：** C 增大 → τ 增大 → 充电时间延长

### R、C 组合对比实验

| 实验 | 电阻 R | 电容 C | τ = R×C | 充满时间 (5τ) | 仿真观察 |
|------|--------|--------|---------|---------------|----------|
| ① 基准 | 1 kΩ | 10 μF | 10 ms | 50 ms | 中等速度 |
| ② 小电阻 | 100 Ω | 10 μF | 1 ms | 5 ms | 约 5 ms 充满 |
| ③ 大电阻 | 10 kΩ | 10 μF | 100 ms | 500 ms | 约 0.5 s 充满 |
| ④ 大电容 | 1 kΩ | 100 μF | 100 ms | 500 ms | 约 0.5 s 充满（与③相同 τ） |
| ⑤ 小电容 | 1 kΩ | 1 μF | 1 ms | 5 ms | 约 5 ms 充满 |

> **关键发现：**
> - τ 与 R 成正比：R 增大 10 倍 → τ 增大 10 倍
> - τ 与 C 成正比：C 增大 10 倍 → τ 增大 10 倍
> - 不同 R、C 组合只要 τ 相同，充电曲线形状完全相同（只是时间轴缩放）
> - **经验法则：约 5 τ 后电容基本充满（99%）**

**2. LED（发光二极管）**

**4. NPN 晶体管开关（2N3904）**

| 参数 | 计算值 | 实测值 | 验证 |

> **关键发现：**
> - 晶体管 C-E 压降仅 **6.91 mV**，说明完全饱和导通，相当于理想开关
> - 集电极电流（3.1mA）< 基极电流（2.59mA），因为这里晶体管作为**开关**使用，不是放大模式
> - 开关模式下，β 值没有意义，晶体管要么完全导通（C-E 压降极小），要么完全截止

### 公式总结

**限流电阻计算**
```
R = (Vin - Vd) / I
```
- `Vin` = 电源电压 (V)
- `Vd` = 二极管/LED 正向压降 (V)
- `I` = 期望电流 (A)

**功率计算**
```
P = I² × R
```

### 关键观察

1. **二极管正向压降固定**：无论电流微小变化，压降基本稳定（普通管约 0.6-0.7V，LED 约 1.8-3.3V）
2. **限流电阻保护二极管**：没有电阻，二极管会因电流过大烧毁
3. **LED 需要更大限流电阻**：因为 LED 压降更高，相同电流下电阻功耗更低
4. **Tinkercad 模型差异**：普通二极管实测 0.57V，低于理论值 0.7V，但作为学习完全可接受
5. **晶体管开关特性**：导通时 C-E 压降极小（6.91mV），相当于理想闭合开关
6. **基极电流控制开关**：基极有 2.59mA 电流时，晶体管导通，LED 亮；基极无电流时，LED 灭
7. **小电流控制大电流**：基极用小电流（2.59mA）控制集电极回路（3.1mA），实现电平转换和开关功能
8. **为什么 3.3V GPIO 不能直接驱动 12V 电机**：
   - ESP32-S3 GPIO 最大输出电流约 **20-40 mA**，电压 **3.3V**
   - 12V 电机典型工作电流 **500 mA-2A**
   - GPIO 无法提供足够电流，且电压不匹配
   - **解决方案**：GPIO → 晶体管基极（小电流控制），12V 电源 → 集电极（电机负载），发射极 → GND
   - 晶体管作为"开关"，用小电流控制大电流，实现电平转换和功率放大

## 第 7 天 — 第一周复习与答疑

### 目标
巩固前 6 天知识，通过手算和 Tinkercad 仿真检验对电路基础的理解，并整理问题清单。

### 任务一：手算电路题

> 以下 5 道题覆盖串并联、分压、KCL、RC、晶体管，均基于前 6 天所学知识。
> 计算时假设：白光 LED 正向压降 ≈1.8V，NPN 硅管 Vbe ≈0.7V，β = 100。

**题目 1 — 串联电路**
5V 电源，串联 1kΩ 电阻 + 白光 LED（Vf≈1.8V），求：
- 回路电流
- 电阻两端电压

![题目1-串联电路](day-07/题目1-串联电路.svg)

**解：**

> 1. 设回路电流为 I（未知量）
> 2. 回路里：Vin = Vr + Vled → 5V = I × 1kΩ + 1.8V
> 3. 解方程：I = (5V - 1.8V) / 1kΩ = 3.2V / 1kΩ = **3.2mA**
> 4. 电阻电压：Vr = I × R = 3.2mA × 1kΩ = **3.2V**

**题目 2 — 并联电路**
5V 电源，3 个 LED 并联，每个串联 330Ω 限流电阻，求总电流（LED 压降按 1.8V 计）

![题目2-并联电路](day-07/题目2-并联电路.svg)

**解：**

> 1. 并联电路各支路电压等于电源电压：V_branch = 5V
> 2. 每条支路应用 KVL：Vr + Vled = 5V → Vr = 5V - 1.8V = 3.2V
> 3. 每条支路电流：I_branch = Vr / R = 3.2V / 330Ω ≈ 9.7mA
> 4. 总电流（KCL）：I_total = I1 + I2 + I3 = 9.7mA × 3 = **29mA**

**题目 3 — 分压电路**
5V 电源，1kΩ + 2kΩ 串联分压，求：
- 2kΩ 电阻两端电压
- 若在 2kΩ 两端接一个 10kΩ 负载电阻，负载两端实际电压是多少？

![题目3-分压电路](day-07/题目3-分压电路.svg)

**解：**

**第一问：空载分压**

1. 串联电流相等：
   ```
   I = 5V / (1kΩ + 2kΩ) = 5V / 3kΩ ≈ 1.67mA
   ```
2. 2kΩ 电阻电压：
   ```
   V2 = I × 2kΩ = 1.67mA × 2kΩ ≈ 3.33V
   ```
   或直接用分压公式：V2 = 5V × 2kΩ / 3kΩ = 3.33V

**第二问：带 10kΩ 负载（两种解法）**

**方法一：等效电阻法**

1. 并联等效电阻公式：
   ```
   Req = (R2 × Rload) / (R2 + Rload) = (2kΩ × 10kΩ) / (2kΩ + 10kΩ) ≈ 1.667kΩ
   ```
2. 总电流：
   ```
   I = 5V / (1kΩ + 1.667kΩ) ≈ 1.875mA
   ```
3. 负载电压（即等效电阻电压）：
   ```
   V_load = I × Req = 1.875mA × 1.667kΩ ≈ 3.125V
   ```

**方法二：节点电压法（KCL + KVL）**

1. 设并联部分电压为 V2，1kΩ 电阻电压为 V1
2. KCL：流入 = 流出
   ```
   V1 / 1kΩ = V2 / 2kΩ + V2 / 10kΩ
   ```
3. KVL：
   ```
   V1 + V2 = 5V
   ```
4. 代入解得：
   ```
   V2 ≈ 3.125V
   ```

**题目 4 — KCL（基尔霍夫电流定律）**
一个节点，3 个支路电流分别为 2mA（流入）、3mA（流入），求第三支路（流出）的电流。

![题目4-KCL](day-07/题目4-KCL.svg)

**解：**

```
流入 = 流出
2mA + 3mA = 5mA
```

第三支路电流为 **5mA**。

**题目 5 — RC 电路 + 晶体管**
5V 电源，1kΩ 电阻 + 100µF 电容串联，求充电至 63.2% 所需时间（时间常数 τ = RC）。
NPN 晶体管基极通过 10kΩ 电阻接 3.3V，发射极接地，集电极接 LED+330Ω 到 5V，求 LED 是否亮（假设 β=100，Vbe≈0.7V）。

![题目5-RC与晶体管](day-07/题目5-RC与晶体管.svg)

**解：**

**第一问：RC 充电时间**

1. 基尔霍夫电压定律（KVL）：
   ```
   Vin = I × R + Vc
   ```
2. 电容电流与电压关系：
   ```
   I = C × dVc/dt
   ```
3. 代入 KVL，整理为微分方程：
   ```
   Vin = RC × dVc/dt + Vc
   ```
4. 解微分方程（边界条件 t=0 时 Vc=0）：
   ```
   Vc(t) = Vin × (1 - e^(-t/RC))
   ```
5. 时间常数：
   ```
   τ = R × C = 1kΩ × 100µF = 0.1s
   ```
6. 充电至 63.2%：
   ```
   令 Vc/Vin = 63.2% = 0.632
   0.632 = 1 - e^(-t/τ)
   e^(-t/τ) = 0.368
   -t/τ = ln(0.368) = -1
   t = τ = **0.1s**
   ```

**第二问：晶体管开关**

1. 计算基极电流：基极通过 10kΩ 电阻接 3.3V，Vbe = 0.7V
   ```
   Ib = (3.3V - Vbe) / Rb = (3.3V - 0.7V) / 10kΩ = 2.6V / 10kΩ = 0.26mA
   ```

2. 晶体管电流放大：Ic = β × Ib
   ```
   Ic = 100 × 0.26mA = 26mA
   ```
   这是晶体管理论上能提供的最大集电极电流

3. 计算 LED 支路实际电流（负载限制）：
   - 集电极回路 KVL：5V = Vf + Vce(sat) + Ic × Rc
   - LED 压降 Vf ≈ 1.8V，晶体管饱和压降 Vce(sat) ≈ 0.2V
   - 电阻两端实际电压：Vr = 5V - 1.8V - 0.2V = 3.0V
   - LED 支路最大电流：
   ```
   ILED_max = Vr / Rc = 3.0V / 330Ω ≈ 9.09mA
   ```

4. 判断晶体管状态：比较 Ic（理论）与 ILED_max（负载限制）
   ```
   Ic = 26mA > ILED_max = 9.09mA
   ```
   集电极电流需求（9.09mA）小于晶体管能提供的电流（26mA）

5. 饱和验证：基极电流是否足以使晶体管饱和
   - 饱和所需最小基极电流：
   ```
   Ib_min = ILED_max / β = 9.09mA / 100 = 0.0909mA
   ```
   - 实际基极电流：Ib = 0.26mA
   - 判断：Ib = 0.26mA > Ib_min = 0.0909mA ✓

6. 晶体管集电极电压瞬态分析（含微分方程）：
   - 集电极回路：5V → LED → 330Ω → 晶体管集电极 → 发射极 → 地
   - 设集电极对地电压为 Vc(t)，晶体管饱和时 Vce(sat) ≈ 0.2V
   - 对集电极回路应用 KVL：
   ```
   5V = Vf + I_c(t) × 330Ω + Vc(t)
   ```
   - 整理为微分方程（假设集电极有寄生电容 Cp）：
   ```
   I_c(t) = Cp × dVc/dt
   ```
   ```
   5V - Vf - 330Ω × Cp × dVc/dt - Vc(t) = 0
   ```
   - 整理为标准形式：
   ```
   dVc/dt + (1/(330Ω × Cp)) × Vc(t) = (5V - Vf)/(330Ω × Cp)
   ```
   - 边界条件：t = 0 时，Vc(0) = 5V（晶体管截止，集电极相当于开路）
   - 解微分方程得：
   ```
   Vc(t) = Vce(sat) + (5V - Vce(sat)) × e^(-t/τ_c)
   ```
     其中时间常数 τ_c = 330Ω × Cp

7. 结论：晶体管工作在饱和区，LED 有足够的电流通过，**LED 会亮**
   - 稳态时 Vc ≈ Vce(sat) ≈ 0.2V
   - 瞬态过程按指数衰减至稳态值，时间常数取决于集电极寄生电容

- **白光亮灯（室内光下临界导通）:** [`day-07/面包板电路-白光亮灯.png`](day-07/面包板电路-白光亮灯.png)

> 实物现象与仿真一致：遮光后 LED 明显点亮；室内光照下 LDR 阻值仍在几 kΩ 量级，基极电压落在 0.5-0.8V 临界区，LED 微亮而不完全熄灭——与「关键观察」第 7 条吻合，说明这是 LDR 分压电路的固有特性，而非接线错误。

**光敏控灯原理（我的理解）**

核心链条：**光强 → LDR 阻值 → B 点电压 → 晶体管开关 → LED 亮灭**。

**1. 光敏电阻随光变阻值**

光敏电阻内部是半导体。光子照射会激发出**自由电子**（能导电的载流子），光越强 → 载流子越多 → 电阻越小；光越弱 → 载流子越少 → 电阻越大。

**2. B 点电压由 10kΩ（上拉）+ LDR（下拉）分压决定**

```
5V ──[10kΩ]── B ──[LDR]── GND

Vb = 5V × R_LDR / (10kΩ + R_LDR)
```

- **强光 → LDR 阻值小**（几百 Ω~1kΩ）：
  ```
  Vb ≈ 5V × 0.5k / (10k + 0.5k) ≈ 0.24V   → 低
  ```
- **暗光 → LDR 阻值大**（几十~几百 kΩ，例如 50kΩ）：
  ```
  Vb = 5V × 50k / (10k + 50k) ≈ 4V        → 高
  ```

LDR 是 B 点的**下拉电阻**：阻值越小，B 点越被拉向 GND；阻值越大，上拉 10kΩ 相对把 B 点抬向 5V。暗环境下 LDR 可达几十~几百 kΩ，正是靠这段大阻值把 Vb 抬到 0.7V 以上。

**3. B 点电压是晶体管的开关门槛**

B-E 之间需要约 0.7V 才能打开，本质是用 B 这个「开关」控制集电极电流：

| 环境 | Vb | 晶体管 | Ic | LED |
|------|-----|--------|-----|-----|
| 强光（白天） | ≈ 0.24V，< 0.7V | 截止 | ≈ 0 | **灭** |
| 暗光（夜晚） | ≈ 0.7~4V，> 0.7V | 饱和导通 | ≈ 9~14mA | **亮** |

- Vb < 0.7V → 基极几乎无电流注入 → 集电极回路不通 → LED 灭
- Vb > 0.7V → 基极有电流 → 晶体管 C-E 近似导通 → `5V → 330Ω → LED → C-E → GND` 接通 → LED 亮

**4. 结论**

**光强 → 灯灭，光弱 → 灯亮**：光敏电阻把「光」先转成「电阻变化」，再由 10kΩ+LDR 分压转成「B 点电压」，最后靠晶体管当开关通断 LED 回路。面包板实测的 241mV（白天灭）、696mV（暗光/临界亮）两个读数，正好卡在 0.7V 阈值两侧，验证了这条链条。

### 公式总结

**串联限流**
```
I = (Vin - Vf) / R
```

**分压（空载）**
```
Vout = Vin × R2 / (R1 + R2)
```

**分压（带负载）**
```
Vout = Vin × Rload / (R1 + Rload)   // R2 被负载并联替代
```

**RC 时间常数**
```
τ = R × C
t_63.2% = τ
```

**晶体管开关条件**
```
Ib = (Vbase_source - Vbe) / Rb
Ic = β × Ib
LED 亮条件：Ic > LED_阈值电流（约 1-2mA）
```

### 关键观察

1. **LDR 位置决定电路方向**：10kΩ 在上（接 5V）、LDR 在下（接 GND）才能实现"暗亮灭"；反过来则行为相反
2. **基极电压是开关阈值**：Vb ≈ 0.7V 是晶体管导通的临界点，测量 Vb 就能判断电路状态
3. **饱和时 Vc ≈ 0V**：晶体管深度饱和时集电极电压极低（40mV 左右），LED 得到最大电流
4. **截止时 Vc 浮空**：万用表测截止时的 Vc 会得到不确定值（如 3.68V），不代表真实电位
5. **LDR 两端电压 ≈ Vb**：因为 LDR 下端接地，上端接基极，所以 V_LDR = Vb - GND = Vb
6. **分压决定开关状态**：10kΩ 与 LDR 组成分压器，基极电压随 LDR 阻值变化——暗环境 LDR 阻值大，B 点抬升导通；亮环境 LDR 阻值小，B 点拉低截止。仿真里 LDR 阻值不会真正无穷大，因此截止时基极不会完全悬空
7. **LDR 灵敏度有限**：普通光敏电阻在室内光下阻值仍为几 kΩ，B 点电压落在 0.5-0.8V 临界区，LED 会微亮但不完全熄灭，需要强光（手电筒直射）才能让 Vb < 0.7V 完全截止。这是 LDR 分压电路的固有限制，后续用比较器/施密特触发器可解决临界抖动问题

### 关键观察

1. **两个 Type-C 口分工完全不同**：只有 U2（CH343P → UART0）走串口下载与监视器；插 U1 需要在 IDE 里打开 `USB CDC On Boot`，否则监视器一片空白

6. **ADC 输入不得超过 3.3V**：分压后的信号必须在 ADC 量程内，这也是 Day 14 电压表要重点核对的约束
7. **板载 WS2812B 需额外装库**：GPIO48 控制脚已从原理图确认，但本地 esp32 3.3.10-cn 内置库与 `~/Documents/Arduino/libraries` 中均无 WS2812/NeoPixel 驱动，驱动它需先安装第三方库（如 Adafruit NeoPixel）——该灯已在 Day 9 实际点亮验证（绿 → 蓝 → 红循环），详见 [`day-09/README.md`](./day-09/README.md)

### 实验一：板载 WS2812B 彩灯循环

#### 板载灯珠

| 项目 | 参数 |
| --- | --- |
| 型号 | XL-5050RGBC-WS2812B（位号 U1） |
| 类型 | 单总线可编程 RGB 灯珠（内置驱动 IC + 恒流源） |
| 控制脚 | **GPIO48**（网络名 RGB_CTRL） |
| 协议 | 800 kHz 单线归零码，每颗 24 bit（G8 R8 B8） |
| 驱动库 | Adafruit NeoPixel（第三方，需单独安装） |

> WS2812B 是数字器件，靠 800 kHz 窄脉冲编码通信，**不能 `digitalWrite` 直接驱动**，必须用专用库按时序发送数据。

**电路**：`GPIO48 → 板载 WS2812B（板内走线）→ 灯珠 → GND`，灯珠和驱动 IC 全部焊在板上，无需任何外部接线。

![电路-板载彩灯](day-09/电路-板载彩灯.png)

#### 代码

完整代码：[`day-09/rgb_cycle.ino`](./day-09/rgb_cycle.ino)

```cpp
#include <Adafruit_NeoPixel.h>

#define RGB_PIN   48    // 板载 WS2812B 控制脚（net RGB_CTRL）
#define RGB_COUNT 1     // 板上只有一颗灯珠

Adafruit_NeoPixel rgb(RGB_COUNT, RGB_PIN, NEO_GRB + NEO_KHZ800);

void setup() {
  rgb.begin();
  rgb.setBrightness(50);   // 0-255，先调低亮度，避免直视刺眼
  rgb.show();              // 上电先熄灭，清掉复位期间锁存的随机颜色
}

void loop() {
  rgb.setPixelColor(0, rgb.Color(0, 255, 0));   // 绿
  rgb.show();
  delay(500);

  rgb.setPixelColor(0, rgb.Color(0, 0, 255));   // 蓝
  rgb.show();
  delay(500);

  rgb.setPixelColor(0, rgb.Color(255, 0, 0));   // 红
  rgb.show();
  delay(500);
}
```

`setPixelColor()` 只写内存缓冲区，`show()` 才真正把数据推给灯珠，两者缺一不可。

#### 关键观察

1. **板载灯珠 ≠ 普通 LED**：WS2812B 是数字器件，必须用库驱动，不能 `digitalWrite`
2. **`setPixelColor` + `show()` 缺一不可**：前者写内存，后者才发送
3. **`NEO_GRB + NEO_KHZ800` 是 WS2812B 的固定组合**：数据顺序为 G→R→B
4. **复位期间 GPIO48 悬空会锁存随机色**：这就是"新板子插上就亮一个颜色"的来源，`setup()` 里主动 `show()` 熄灭即可根治
5. **WS2812B 没有掉电记忆**：一次上电只记得最后收到的 24 bit，掉电即忘；要记忆须固件侧做持久化
6. **相机自动曝光会骗人**：绿光相位会被压成近灰白，判断灯珠颜色要用固定区域 + 主通道统计

### 实验二：外接普通 LED 闪烁

板载灯珠走的是 800 kHz 单总线协议，必须用库驱动；为了验证 GPIO 最原始的"直接输出"用法，再接一颗普通 LED，用经典 `digitalWrite` 驱动。

**接线**：`GPIO2 → 220Ω 限流电阻 → LED 长脚（阳极）→ LED 短脚（阴极）→ GND`

| 元件 | 说明 |
| --- | --- |
| 限流电阻 | 220Ω（库存清单中的 220Ω ×10） |
| LED | 普通直插 LED，长脚阳极、短脚阴极 |
| 电源 | 板子 USB 5V，GPIO2 输出 3.3V 逻辑电平 |

![电路-外接LED](day-09/电路-外接LED.png)

```cpp
const int EXT_LED_PIN = 2;   // 外接 LED 控制脚

void setup() {
  pinMode(EXT_LED_PIN, OUTPUT);
  digitalWrite(EXT_LED_PIN, LOW);   // 上电先灭
  Serial.begin(115200);
  Serial.println("ESP32-S3 外接 LED Blink Start");
}

void loop() {
  digitalWrite(EXT_LED_PIN, HIGH);  // 3.3V → 电流经电阻流过 LED → 亮
  Serial.println("LED ON");
  delay(500);

  digitalWrite(EXT_LED_PIN, LOW);   // 0V → LED 两端无压降 → 灭
  Serial.println("LED OFF");
  delay(500);
}
```

- **新板子插上电自己亮、烧完 `day08.ino` 常绿、拔插就不亮**：WS2812B 无 NVM，复位/下载时 GPIO48 悬空，灯珠把噪声当数据锁存成随机色；`day08.ino` 没驱动 GPIO48，颜色就一直卡住。修复：`setup()` 里 `begin()` 后立刻 `show()` 刷成全灭。

## 第 10 天 — PWM 呼吸灯 + 电位器调光

### 目标

Day 9 里 GPIO 只有"全亮 / 全灭"两态（`digitalWrite`）。Day 10 要拿到**第三种状态：任意亮度**——靠 **PWM（脉冲宽度调制）**，引脚高速开 / 关，用"开的时间占比"（占空比）决定平均亮度。占空比从 0 升到满再降回，就是呼吸灯；占空比由旋钮决定，就是电位器调光。

ESP32 的 PWM 由 **LEDC 外设**硬件产生：配置一次后硬件持续输出波形，CPU 去发 WS2812B 数据也不会打断它。这是后续 Day 11（按键）、Day 19（电机）非阻塞编程的硬件基础。

> 完整内容（API 断裂处理、代码、视频、周期验证、踩坑记录）见 [`day-10/README.md`](./day-10/README.md)。
>
> **代码约定（本课起）**：后续实验的代码默认都写成一个和板载彩灯并行的 `loop()`，不再单独交一份"只有灯"的草图。

两个任务一览：

| 任务一 | [`day-10/combined_pwm_blink/combined_pwm_blink.ino`](./day-10/combined_pwm_blink/combined_pwm_blink.ino) | 板载彩灯循环 + 外接 LED 呼吸（亮度由代码自动渐变） | GPIO48 + GPIO2 |
| 任务二 | [`day-10/pot_dimmer/pot_dimmer.ino`](./day-10/pot_dimmer/pot_dimmer.ino) | 板载彩灯循环 + 电位器手动调光（亮度由旋钮决定） | GPIO48 + GPIO2 + GPIO1 |

### 任务一：外接 LED 呼吸灯

**接线**：沿用 Day 9 —— `GPIO2 → 220Ω 限流电阻 → LED 长脚（阳极）→ LED 短脚（阴极）→ GND`，一根线都不用加。

完整代码（最小版）：[`day-10/breath_led/breath_led.ino`](./day-10/breath_led/breath_led.ino)

```cpp
const int LED_PIN = 2;
const int STEP_MS = 4;      // 每档 4ms：256 档 ≈ 1.02s 单向，一个完整呼吸 ≈ 2s

void setup() {
  ledcAttach(LED_PIN, 5000, 8);   // 引脚 2, 5kHz, 8 位分辨率 → duty 0~255
  ledcWrite(LED_PIN, 0);          // 上电从灭开始
  Serial.begin(115200);
  Serial.println("ESP32-S3 PWM 呼吸灯 Start");
}

void loop() {
  for (int b = 0; b <= 255; b++) { ledcWrite(LED_PIN, b); delay(STEP_MS); }  // 渐亮
  for (int b = 255; b >= 0; b--) { ledcWrite(LED_PIN, b); delay(STEP_MS); }  // 渐暗
}
```

两个 API 的分工：

- `ledcAttach(pin, freq, resolution)` — 把引脚绑到 LEDC，设定 PWM 频率与分辨率。8 位分辨率意味着 duty 取 **0~255**。
- `ledcWrite(pin, duty)` — 写占空比。**按引脚写**，不按通道写。

### 任务一的完整版：彩灯 + 呼吸灯双任务并行

完整代码：[`day-10/combined_pwm_blink/combined_pwm_blink.ino`](./day-10/combined_pwm_blink/combined_pwm_blink.ino)

```cpp
#include <RgbCycle.h>   // Day 9 的彩灯循环，已抽成可复用库

const int LED_PIN = 2;

unsigned long lastBreath = 0;
const unsigned long BREATH_INTERVAL = 4;   // 每 4ms 走一档
const int BREATH_STEP = 1;
int brightness = 0;
int breathDir  = 1;

void setup() {
  RgbCycle::begin();            // 彩灯：初始化
  RgbCycle::setInterval(800);   // 彩灯：本任务用 800ms/色（一个循环 2.4s）
  ledcAttach(LED_PIN, 5000, 8); // 外接 LED：绑定 PWM
  ledcWrite(LED_PIN, 0);
}

void loop() {
  unsigned long now = millis();

  RgbCycle::update();   // 任务 A：彩灯，内部自己按 800ms 换色

  if (now - lastBreath >= BREATH_INTERVAL) {   // 任务 B：呼吸灯
    lastBreath = now;
    brightness += breathDir * BREATH_STEP;
    if (brightness >= 255) { brightness = 255; breathDir = -1; }
    if (brightness <= 0)   { brightness = 0;   breathDir =  1; }
    ledcWrite(LED_PIN, brightness);
  }
}
```

关键点：**整个 `loop()` 里没有一处 `delay()`**。两路各自用 `millis()` 判断自己的节奏，互不阻塞。

`millis()` 判断必须用相减写法 `now - lastBreath >= BREATH_INTERVAL`（而不是 `now >= lastBreath + INTERVAL`），前者在 `unsigned long` 溢出回绕时依然正确。

### 任务二：电位器手动调光

**电路**（在任务一基础上只加一个电位器，LED 那一路不动）：

| 电位器引脚 | 接到 |
| --- | --- |
| 一端脚 | **3V3** |
| 另一端脚 | **GND** |
| 中间脚（滑臂） | **GPIO1**（= ADC1_CH0，ADC1 不与 Wi-Fi 冲突） |

> ⚠️ 接反的典型症状是读数恒定或乱跳——`analogRead()` 读的是中间脚电压，只有中间脚接 GPIO1 才会随旋钮在 0~3.3V 之间滑动。

完整代码：[`day-10/pot_dimmer/pot_dimmer.ino`](./day-10/pot_dimmer/pot_dimmer.ino)

```cpp
#include <RgbCycle.h>

const int LED_PIN = 2;
const int POT_PIN = 1;                    // GPIO1 = ADC1_CH0

const unsigned long READ_INTERVAL = 20;   // 每 20ms 采一次
unsigned long lastRead = 0;

void setup() {
  RgbCycle::begin();
  RgbCycle::setInterval(800);
  ledcAttach(LED_PIN, 5000, 8);
  ledcWrite(LED_PIN, 0);
  Serial.begin(115200);
}

void loop() {
  RgbCycle::update();   // 任务 A：彩灯照常循环

  unsigned long now = millis();
  if (now - lastRead >= READ_INTERVAL) {   // 任务 B：读电位器
    lastRead = now;
    int potValue   = analogRead(POT_PIN);              // 0~4095（12 位 ADC）
    int brightness = map(potValue, 0, 4095, 0, 255);   // 压到 duty 的 0~255
    ledcWrite(LED_PIN, brightness);
    Serial.printf("Pot: %4d  Brightness: %3d\n", potValue, brightness);
  }
}
```

链路：`转旋钮 → 滑臂电压 0~3.3V → GPIO1 读到 0~4095 → map() 压到 0~255 → ledcWrite() 输出亮度`

> `map()` 只做**线性**换算，而人眼对亮度的感知是非线性的（任务一观察到的现象），所以实际转旋钮会觉得**低亮度区间变化太快、高亮度区间几乎看不出区别**。本任务先用最直白的线性映射跑通"读 ADC → 控 PWM"的链路，gamma 修正留待后续。

> 状态：**✅ 已上机实测**——三个旋钮位置的读数与 `map()` 公式完全吻合（见下方「运行结果」）。

## 第 11 天 — 数字输入与按键

> 完整内容见 [`day-11/README.md`](./day-11/README.md)。

### 目标

Day 9/10 都是 GPIO **输出**。Day 11 反过来——读 GPIO **输入**：用一个按键控制 LED 亮灭。

核心知识点：
- **INPUT_PULLUP**：用内部上拉电阻，省掉外部电阻
- **消抖**：按键按下瞬间触点弹跳，需延时 20ms 过滤
- **边沿检测**：区分"按下"（FALLING）和"松开"（RISING）

### 电路

| 器件 | 接线 |
| --- | --- |
| 按键 | GPIO1 → 按键 → GND |
| 外接 LED | GPIO2 → 220Ω → LED 长脚 → LED 短脚 → GND |
| 板载彩灯 | GPIO48（不变，代码中 `RgbCycle::update()` 照常） |

万用表实测：

| 按键状态 | GPIO1 电压 |
| --- | --- |
| 松开 | 3.3V（内部上拉） |
| 按下 | 0V（导通到 GND） |

### 代码

完整代码：[`day-11/day11.ino`](./day-11/day11.ino)

```cpp
#include <RgbCycle.h>

const int BUTTON_PIN = 1;   // GPIO1 = 按键输入
const int LED_PIN    = 2;   // GPIO2 = 外接 LED 输出

void setup() {
  RgbCycle::begin();            // 彩灯：初始化
  RgbCycle::setInterval(800);   // 彩灯：800ms/色

  pinMode(BUTTON_PIN, INPUT_PULLUP);  // 启用内部上拉，按键按下 = LOW
  pinMode(LED_PIN,    OUTPUT);         // LED 引脚设为输出
  Serial.begin(115200);
}

void loop() {
  RgbCycle::update();   // 任务 A：彩灯照常循环

  int buttonState = digitalRead(BUTTON_PIN);
  if (buttonState == LOW) {          // 按键按下（被拉低）
    digitalWrite(LED_PIN, HIGH);     // LED 亮
    Serial.println("Button PRESSED");
    delay(200);                      // 简单消抖：按住期间 200ms 只处理一次
  } else {                           // 按键松开（被上拉回 HIGH）
    digitalWrite(LED_PIN, LOW);      // LED 灭
  }
  delay(10);
}
```

### `pinMode()` 详解

这是新手最常问的问题：`setup()` 里写了 `pinMode()`，为什么 `loop()` 里还要写 `digitalWrite()`？

`pinMode()` 和 `digitalWrite()` 干的是完全不同的事：

| 函数 | 作用 | 类比 |
| --- | --- | --- |
| `pinMode(pin, INPUT_PULLUP)` | **配置引脚的工作模式**——"这个脚是输入还是输出？" | 给门贴标签："这是入口" |
| `digitalWrite(pin, HIGH/LOW)` | **向输出引脚写入电平** | 按开关："开"还是"关" |
| `digitalRead(pin)` | **从输入引脚读取电平** | 看指示灯："亮"还是"灭" |

**一句话**：`pinMode()` 只执行一次（`setup()`），决定引脚的"身份"；`digitalWrite()` / `digitalRead()` 在 `loop()` 里反复执行，实际读写电平。

### 三种模式

| 模式 | 引脚行为 | 典型用途 |
| --- | --- | --- |
| `OUTPUT` | 你可以用 `digitalWrite()` 主动驱动它为 HIGH 或 LOW | 点亮 LED、控制继电器 |
| `INPUT` | 引脚高阻抗，既不拉高也不拉低——**必须接外部上拉/下拉电阻** | 读取传感器（外部有上下拉时） |
| `INPUT_PULLUP` | 内部启用一个 ~40–50kΩ 的上拉电阻，默认把引脚拉到 HIGH；外部接地时变为 LOW | **按键/开关的标准接法** |

### 为什么按键用 `INPUT_PULLUP`？

```
内部上拉 40kΩ
    |
GPIO1 ----[按键]---- GND
```

- 按键**断开**时：开关断开，GPIO1 只连着内部上拉电阻，没有电流回路，引脚被拉到 3.3V → `digitalRead()` 读到 **HIGH**
- 按键**闭合**时：开关闭合，GPIO1 通过导线直接连 GND，内部上拉电阻被"短路"，引脚电压 ≈ 0V → `digitalRead()` 读到 **LOW**

这就是"**低电平有效**"——按键按下是 LOW，松开是 HIGH。

**关键点**：40kΩ 电阻在 ESP32 芯片内部，不在按键内部。按键就是一个纯导线开关，按下时两个触点直接导通（电阻约 0.1Ω），相当于用导线"跳过"了上拉电阻，把 GPIO1 直接拉到 GND，所以电压为 0V。

### 按键消抖

机械按键按下瞬间，金属触点会**快速弹跳**几次（微秒级），导致 `digitalRead()` 来回跳变。软件消抖最简单：读到边沿后延时 20ms，让弹跳平息再读取。

本代码用的**超简单版**（适合入门）：`delay(200)` 在按住期间只处理一次。

### 运行结果

- **按键松开**：GPIO1 = 3.3V，LED 灭，串口无输出
- **按键按下**：GPIO1 = 0V，LED 亮，串口打印 `Button PRESSED`
- **按住不放**：每 200ms 打印一次
- **松开后**：LED 立即灭

### 出了什么问题 & 如何修复

- **引脚接错**：把按键接到了 3V3 而非 GND，导致逻辑反转。修复：按键一端接 GND，代码用 `INPUT_PULLUP`。
- **LED 不亮**：长脚/短脚接反，或电阻值太大。220Ω 最保险。
- **按键乱跳**：没加消抖，串口同一按下事件打印好几行。修复：加 `delay(20)` 以上。

## 第 12 天 — ADC 与传感器读数

> 日期：2026-09-14
> 状态：✅ 已上机实测（电位器 raw=0→4095，对应电压 0V→3.3V；raw=2048 ≈ 1.65V）
>
> 接线：**GPIO1（ADC1_CH0）→ 电位器中间脚**，两侧脚分别接 3V3 和 GND

### 目标

Day 11 读的是**数字信号**（HIGH/LOW）。Day 12 反过来——读**模拟信号**：用 ADC（Analog-to-Digital Converter）把连续电压变成数字值。

核心知识点：
- **12 位 ADC**：ESP32-S3 的 ADC 是 12 位，输出 0–4095
- **电压计算**：`V = raw × 3.3 / 4095`
- **ADC1 vs ADC2**：GPIO1–10 属于 ADC1（推荐），GPIO11–20 属于 ADC2（与 WiFi 冲突）
- **attenuation**：`ADC_11db` 让 ADC 能测 0–3.3V 全量程
- **Serial Plotter**：串口绘图器可视化实时数据

### 硬件与电路

| 器件 | 接线 | 说明 |
| --- | --- | --- |
| 电位器 | **3V3 → 电位器左侧**，**GND → 电位器右侧**，**GPIO1 → 电位器中间脚** | 三脚电位器做分压器，中间脚输出 0–3.3V |
| 外接 LED | GPIO2 → 2kΩ → LED → GND | 保持 Day 11 接法，`RgbCycle::update()` 照常运行 |
| 板载彩灯 | GPIO48 | 保持 Day 9 接法 |

电位器原理：左右两侧固定接 3V3 和 GND，旋转中间脚改变分压比：
- 逆时针到底：中间脚 ≈ GND → 0V
- 顺时针到底：中间脚 ≈ 3V3 → 3.3V
- 中间位置：约 1.65V

### `analogRead()` 详解

| 函数 | 作用 |
| --- | --- |
| `analogReadResolution(12)` | 设置 ADC 精度为 12 位，返回范围 0–4095 |
| `analogSetAttenuation(ADC_11db)` | 设置输入衰减，让 ADC 能测量 0–3.3V（默认只能测约 0–1.1V） |

**ADC1 vs ADC2**：
- **ADC1**（GPIO1–10）：稳定，推荐初学使用
- **ADC2**（GPIO11–20）：与 WiFi 共用，WiFi 启用时读数不准，初学阶段**不要用**

### 电压计算

ESP32-S3 的 ADC 输出是**数字量**（0–4095），需要转换成实际电压：

```
电压(V) = 原始值 × 参考电压 / 最大值
电压(V) = raw × 3.3 / 4095
```

实测验证：
- raw = 0 → 0.00V（电位器逆时针到底）
- raw = 2048 → 1.65V（电位器中间位置）
- raw = 4095 → 3.30V（电位器顺时针到底）

### 实验 2：光敏电阻（LDR）测光照

> 日期：2026-09-14
> 状态：✅ 已上机实测（强光 raw≈4095 ≈ 3.3V；遮光 raw≈0 ≈ 0V）
>
> 接线：**3V3 → 光敏电阻 → GPIO1 → 10kΩ → GND**（光敏电阻在上，10kΩ 在下作下拉）

**光敏电阻特性：**

| 光照 | 电阻值 | 说明 |
| --- | --- | --- |
| 强光 | ~1–10kΩ（甚至更低） | 电阻值小 |
| 黑暗 | ~100kΩ–1MΩ | 电阻值大 |

**电压分压原理：**

```
3V3 ──[R_LDR]── GPIO1 ──[10kΩ]── GND
         (上拉)                    (下拉)
         ↑ 光敏电阻                ↑ 固定电阻
```

**核心原理：串联电路中，电阻越大，它两端的电压越大。**

分压公式：`V_GPIO1 = 3.3V × (R_下拉 / (R_LDR + R_下拉))`

**强光时：R_LDR 很小 → GPIO1 电压很大**

强光照射下，光敏电阻阻值很小（约 500Ω–1kΩ）：

```
V_GPIO1 = 3.3V × (10kΩ / (1kΩ + 10kΩ))
        = 3.3V × (10k / 11k)
        = 3.3V × 0.91
        ≈ 3.00V  →  raw ≈ 3720
```

如果光照极强，R_LDR 只有约 100Ω：

```
V_GPIO1 = 3.3V × (10k / (0.1k + 10k))
        = 3.3V × (10k / 10.1k)
        ≈ 3.27V  →  raw ≈ 4050
```

你的实测 raw ≈ 4095（≈3.30V），说明强光下 R_LDR 极小，10kΩ 几乎分到了全部 3.3V。

**关键理解：** 光敏电阻小 → 它两端的电压小（几乎 0V）→ 3.3V 几乎全部"落在"下方 10kΩ 上 → GPIO1 电压高。

**遮光时：R_LDR 很大 → GPIO1 电压很小**

遮光（用手捂住）时，光敏电阻阻值极大（约 1MΩ）：

```
V_GPIO1 = 3.3V × (10kΩ / (1000kΩ + 10kΩ))
        = 3.3V × (10k / 1010k)
        = 3.3V × 0.0099
        ≈ 0.033V  →  raw ≈ 40 ≈ 0
```

1MΩ 远大于 10kΩ，所以几乎全部 3.3V 都"落在"光敏电阻上，下方 10kΩ 只分到约 0.033V → GPIO1 电压接近 0V。

**关键理解：** 光敏电阻大 → 它两端的电压大（几乎 3.3V）→ 下方 10kΩ 只分到一点点 → GPIO1 电压低 → raw 小。

**一句话总结：**

> **光敏电阻小（强光）→ 它"吃掉"的电压少 → 10kΩ 分到的高电压出现在 GPIO1 → raw 大**
> **光敏电阻大（遮光）→ 它"吃掉"的电压多 → 10kΩ 只分到一点点 → GPIO1 电压低 → raw 小**

### UART 通信基础

UART（Universal Asynchronous Receiver/Transmitter）是最基础的串行通信协议。

**硬件连线：**

| 信号 | 方向 | 说明 |
| --- | --- | --- |
| **TX** (Transmit) | ESP32 → 电脑 | ESP32 发送数据 |
| **RX** (Receive) | 电脑 → ESP32 | ESP32 接收数据 |
| **GND** | 共地 | 必须连接，否则通信失败 |

ESP32-S3 开发板内置 USB 转串口芯片（如 CP2102/CH340），通过 USB 线连接电脑即可通信，不需要额外接线。

**波特率（Baud Rate）：**

| 波特率 | 速度 | 适用场景 |
| --- | --- | --- |
| 9600 | 慢 | 调试、长距离 |
| 115200 | 快 | **ESP32 默认，推荐** |
| 921600 | 极快 | 大数据量传输 |

关键：串口监视器和代码中的波特率必须**一致**，否则看到乱码。

**为什么用 JSON？**

### 目标

把 ESP32-S3 变成一个**能用的直流电压表**，把 Day 8（GPIO）、Day 12（ADC）、Day 13（Serial）串起来。

关键认知：ESP32 的 GPIO 只能承受 0~3.3V，直接接 5V 就烧。**分压电路不是可选项，是保护电路。**

### 分压电路

```
   被测电压 VIN
        │
    ┌───┴───┐
    │ 10kΩ  │  R_HI
    └───┬───┘
        │
        ├────────────── GPIO1 (ADC1_CH0)
        │
    ┌───┴───┐
    │  1kΩ  │  R_LO
    └───┬───┘
        │
       GND
```

**公式：**

```
V_PIN = VIN × R_LO / (R_HI + R_LO)     // GPIO1 处电压
VIN   = V_PIN × (R_HI + R_LO) / R_LO   // 反推被测电压（代码里就这句）
```

本电路分压比 = **11**，所以 `VIN = V_PIN × 11`，量程 = 3.3 × 11 = **36.3V**。

**为什么用 10kΩ+1kΩ，而不是指南推荐的 1MΩ+100kΩ：**

| 方案 | 等效源阻抗 | 后果 |
|------|-----------|------|
| 1MΩ + 100kΩ | ≈ 91kΩ | ADC 采样电容充不满 → 读数系统性偏低 5~15%，得并一个 104 电容去救 |
| **10kΩ + 1kΩ** | **≈ 909Ω** | 采样充足，读数准，**不需要电容** |

代价：输入阻抗从 1.1MΩ 降到 11kΩ。测电池、测电源轨完全够用。

### 接线

两个电阻**串成一排**，中间那一列**共用一个孔**，就是分压中点：

| 步骤 | 动作 |
|------|------|
| 1 | 10kΩ 插第 10 列 → 第 15 列；1kΩ 插**第 15 列**（共用中点）→ 第 20 列 |
| 2 | 第 15 列 → **GPIO1** |
| 3 | 第 20 列 → **GND** |
| 4 | 第 10 列引出一根线当**表笔**，先不接 |

⚠️ **先接 GND，最后接 VIN**；拆线反过来。⚠️ **ESP32 要先上电**（插着 USB）再接被测电压。

踩过的坑：

1. 一度把校准前读数误记成 3.16 V，算出 `1.0538`，上传后读数变成 **3.49 V（+4.8%）**，
   比不校准的 −2.7% 还差。
2. 读数本身会漂 ±1.2%（当天三次测 3V3：3.24 → 3.31 → 3.23），
   所以必须**同时测量**：万用表夹在分压器 VIN 端，和串口同一时刻读。
3. 两点标定 `vin = a × vPin + b` 现在做不了：拟合出 `b = +0.263 V`，
   意味着表笔接地时要报 0.26 V，与实测 `adc 0 → 0.00 V` 矛盾。

**结论：保持 `1.0055` 别再调，先去做一次同时测量。**

### 误差来源与处理

| 误差来源 | 量级 | 处理 |
|---------|------|------|
| Vref 不准 | ±5% | ✅ 用 `analogReadMilliVolts()` 读 eFuse 出厂校准值 |
| ADC 噪声 | ±1~2 LSB | ✅ 16 次采样平均 |
| 源阻抗过高 | -5~15% | ✅ 改用 10kΩ+1kΩ，根子上解决 |
| 电阻公差 | ±10% | ⚠️ 靠单点校准 |
| ADC 两端非线性 | 低端/高端 | ⚠️ 避开，代码已标 `LOW` 提示 |

### 出了什么问题 & 如何修复

- **5Vin 引脚接上分压电路后读数变成 0**：5Vin 是电源**输入**引脚，不是稳压输出，没有驱动能力。万用表（10MΩ 输入阻抗）能测到 4.4V，但接 11kΩ 负载后电压直接 collapses 到 0。修复：改用 3V3（板载 LDO 输出，有驱动能力）做校准基准。
- **悬空时读数乱飘，不是 0**：1kΩ 没接到 GND，或两电阻没共用中点。
- **读数乱跳无规律**：被测源与 ESP32 没共地。
- **读数固定偏差 10% 左右**：电阻公差，做单点校准。
- **枚举值叫 `OK`/`LOW` 编译报错**：Arduino 核心已把它们定义成宏。改名 `V_OK`/`V_TOO_LOW`/`V_TOO_HIGH`。

完整笔记：[`day-15/README.md`](./day-15/README.md)

**实拍**：[`焊接导线测导通.png`](./day-15/焊接导线测导通.png)、[`焊接5个焊点.png`](./day-15/焊接5个焊点.png)

### 目标

把"杜邦线一碰就松"变成"焊死了不会掉"。这是第 3 周的开门技能 —— 小车跑起来会震，虚焊 = 半路歇菜。

关键认知：**烙铁加热的是焊盘和引脚，不是锡丝。** 把锡丝怼在烙铁头上化开再"涂"上去，是冷焊的头号来源。

### 五步焊接法

```
① 加热焊盘和引脚（不是加热锡丝）
      ↓
② 送锡到"焊盘与引脚交界处"（不是烙铁头上）
      ↓
③ 锡熔化并自己流满焊盘  →  先撤锡丝
      ↓
④ 再撤烙铁
      ↓
⑤ 别动，等它自然凝固（1~2 秒）
```

**新手 90% 的错都在三点**：① 先加热焊件再送锡；② 锡从烙铁的对面送，靠毛细作用吸满；③ 锡只要米粒大小，多了桥连、少了强度不够。

**"怎么算少"的三条硬指标**（不靠目测）：送锡**不超过 1 秒**就撤 / 锡的边缘**收在焊盘内**（看得见外圈铜色）/ 是**小丘**不是球（引脚从丘顶冒出一小截）。
> 例外：焊**多股软导线**时锡必须包住整股铜丝，会明显多于米粒，这是对的。

### 焊点自检表

| 检查项 | 合格 | 不合格 |
|--------|------|--------|
| 形状 | 圆锥形/小丘状 | 球状堆起 / 尖刺拉丝 |
| 表面 | **光亮**（像镜面） | 暗淡粗糙、像豆腐渣 |
| 浸润 | 锡铺满整个焊盘 | 缩成球、堆在一侧 |
| 用量 | 米粒大小 | 太多（快连到旁边）/ 太少（看得见孔） |
| 牢固 | 拔不动 | 一拔就掉 |

**虚焊最阴险**：肉眼看着跟好焊点一样，只有用力拔或万用表才暴露。

### 客观判定：万用表导通档

用 DT9205A PRO 打到导通档：

- 线的**两端金属** → **响**（导通）
- 这根线和**相邻导体** → **不响**（绝缘，说明没锡桥）

两项都过才算合格。

> ⚠️ **测之前先问一句**：这两个点**本来是不是就通的**？如果板上本来就有覆铜走线相连，"响"证明不了任何关于焊点的事。
> 正确顺序：**焊前先量一次（应该不响）→ 焊后再量（响）**，前后对比才构成证据。

### 本次验收实测（2026-09-16）

| 项目 | 结果 |
|------|------|
| 废板焊点 | ✅ 板上有 5~7 个独立焊点，形状/浸润/用量/无锡桥 全部合格 |
| 导通测试有效性 | ✅ **裸板这两个孔本不连通 → 焊后连通**，排除了"板上本就有走线"的干扰，证明是焊点建立的导通 |
| 拔线测试 | ✅ 顺着导线方向轻拉，**不脱开** |

> 📌 通用方法论：**任何"通断测试"都要先问"会不会本来就通？"** 没有对照组，"响"不构成证据。Day 16 拆焊、Day 21 整车接线排查都继续沿用。

"光亮"和"暗淡粗糙"光看文字想象不出来。做法：烙铁压上去**只贴 1 秒就撤**（焊件还没到温），或送锡后**边凝固边晃导线** → 锡浮在表面、呈灰白颗粒状像豆腐渣。把好/坏两个并排拍一张，对比最直观。

**实拍**：[`五个电阻串联焊接.png`](./day-16/五个电阻串联焊接.png)（正面）、[`五个电阻串联背面焊接点.png`](./day-16/五个电阻串联背面焊接点.png)（背面焊点）

### 目标

把 Day 15 在废板上练的送锡量与撤锡时机用到**真实电路**上：在洞洞板上焊出一条电阻串联链，并用万用表分段验证。

三条检查标准：① 无虚焊 ✅ 已过（全链 4.5kΩ + 分段自洽）② 无短路 ✅ 已过（相邻空孔 = OL）③ 焊点平整 ⚠️ 有瑕疵（锡量偏少 + 形状拉长）。

### 洞洞板 ≠ 面包板

| | 面包板 | 洞洞板 |
|---|--------|--------|
| 孔内部 | 有**铜条**，一行 5 孔内部相连 | **每个孔是独立焊盘**，彼此不连通 |
| 连不连 | 插进去就连通 | 不焊就不通，全靠**焊锡**连通 |

**所以洞洞板上串联不需要跳线** —— 两个元件的引脚塞进**同一个孔**，焊锡一包就是同一个电气节点。

### 共用孔串联法

```
  孔1    孔3    孔5    孔7    孔9    孔11
   ●──────●──────●──────●──────●──────●
   │ R1   │ R2   │ R3   │ R4   │ R5   │
  330Ω   1kΩ    2kΩ    1kΩ    220Ω
```

孔 3/5/7/9 各塞两根引脚，焊锡包住 = 节点，零跳线。

**为什么用不同阻值**：累计值唯一 → 测出哪个数就知道链子通到哪一节。全是 1kΩ 的话，测出 3kΩ 只知道"通了 3 个"，不知道断在哪。

### 安装：架空式弯脚（离本体 3mm 处折）+ 八字固定

- 从**正面插入、背面焊接**；在**离本体 3mm 处**（不是贴着本体）把两脚各弯 90°
- 跨度 = 本体长度 + 6mm ≈ **12.5mm ≈ 5 个孔间距** → **两头穿过的孔间隔非常大**，本体**架空**在板面上方，不贴板
- 背面刚好露出 **3mm**，正好够焊，**不浪费引脚线，也几乎不用剪断**
- 背面两脚**向外掰 30~45°** 成"八字" → 翻面不掉（架空式下两脚本来就外张，轻掰即可）
- ⚠️ **"少插一点只露 3mm" ≠ "插到底之后露 3mm"**。前者本体悬空十几毫米立不住。**插入深度由弯脚位置决定，不是用力大小。**
- ❌ 对照：说明书常见的"贴板卧式 ∏ 形"是离本体 1~2mm 弯、跨 2 孔距（5.08mm）、本体平躺贴板、背面伸 3~5mm 还得剪。**本次没用它。**

### ⭐ 分段求和自检法

| 测哪 | 理论值 | 实测 | 判定 |
|------|--------|------|------|
| 全链（头↔尾） | 4.55kΩ | **4.5kΩ** | ✅ |
| R1+R2 | 1.33kΩ | **1.3kΩ** | ✅ |
| R3+R4+R5 | 3.22kΩ | **3.2kΩ** | ✅ |

```
1.33k + 3.22k = 4.55k = 全链
1.3k  + 3.2k  = 4.5k  = 实测全链 4.5k  ✅
```

**两段正好把整条链无重叠、无缺口地分完 → 分段点（孔 3 共用孔）真的导通了。** 若那里虚焊，前段会是无穷大、后段也不会是 3.2k。

## 第 17 天 — HC-SR04 超声波测距

> 日期：2026-09-18
> 状态：✅ **已完成**（2026-09-19）：五档灯色全命中、空旷对照组通过、4 点误差 −0.1~−1.0cm
>
> 硬件：ESP32-S3（N16R8）+ HC-SR04 超声波模块（宽电压 3-5.5V 版）
> 核心：时序通信 → Trig 触发 / Echo 回响 → 声速换算 → 超时与量程判断
> 代码：[`实验1-超声波测距.ino`](./day-17/实验1-超声波测距/实验1-超声波测距.ino)

完整笔记：[`day-17/README.md`](./day-17/README.md)

### 原理

Trig 收到 **≥10μs 高脉冲** → 模块发射 8 个 40kHz 方波 → **Echo 拉高、收到回波拉低**。距离藏在 Echo 高电平的**宽度**里：

```
距离 cm = duration(μs) ÷ 58 = duration(μs) × 0.0343 ÷ 2
```

0.0343 cm/μs 是声速（343 m/s），除以 2 因为脉冲走了个来回。反着记更快：**58μs ≈ 1cm**。

量程 2~400cm，探测锥角约 **15°**（不是一条直线 —— 这正是 Day 20 要给超声波配 SG90 舵机左右扫的原因）。

### 接线

| HC-SR04 | ESP32-S3 |
|---------|----------|
| VCC | **3V3**（板上两个 3V3 任选其一） |
| GND | GND（**必须共地**） |
| Trig | **GPIO4** |
| Echo | **GPIO5**（直连，无需分压） |

没沿用指南的 GPIO5/18：4/5 在排针上相邻好走线，也避开 Day 18 打算用的 GPIO8/9（I2C）。

### ⚠️ 为什么供电选 3V3，而不是 5Vin / 5V

看 `docs/ESP32-S3-Metric.pdf` 会以为板上只有 `5Vin` 没有 5V。**注意那张 PDF 是机械尺寸图** —— 内容只有元器件位号（`PAU4024` / `PAJ102` / `PARGB01`）和尺寸（25.40 / 27.94 / 43.18mm），对 `5V` / `3V3` / `VIN` / `GND` 的检索**零命中**，不能拿它判引脚功能。真正的网络名在原理图 `docs/ESP32-S3-SCH.pdf`：`VBUS` / `5V` / `3V3` / `VDD33` / `GND`。

而 **`5Vin` 的 "in" 就是输入** —— 它是给板子供电的入口，不是稳压输出。**本项目 Day 14 已经踩过**（see 踩坑记录）：5Vin 用万用表能测到 4.4V，但接 11kΩ 负载后电压直接塌到 0。HC-SR04 发射瞬间几十 mA 峰值，接上去整块板会被拉垮。

| 引脚 | 性质 | 能给 HC-SR04 供电吗 |
|------|------|--------------------|
| **3V3** | 板载 LDO **输出**（约 1A） | ✅ **就用它** |
| **5Vin** | 电源**输入** | ❌ 无驱动能力，会塌压 |
| 5V 排针 | 通常直连 VBUS | ⚠️ 可行但见下 |

选 3V3 还有一个额外收益：**宽电压版 HC-SR04 的 Echo 高电平跟随 VCC**，因此 3V3 供电时 Echo 就是 3.3V，直连 GPIO5 绝对安全，**连 1kΩ+2kΩ 分压都省了**，彻底绕开指南警告的"5V 灌进 GPIO 烧 IO"。若坚持 5V 供电，则 Echo 输出 5V，必须加分压。

代价是发射功率略低、远距离量程理论上稍短 —— §六 实测会验证 3.3V 下能测到多远。真不够用再换 5V 排针 + 分压。

### 代码要点

```cpp
digitalWrite(TRIG_PIN, LOW);  delayMicroseconds(2);   // 保证干净上升沿
digitalWrite(TRIG_PIN, HIGH); delayMicroseconds(10);  // 手册要求 ≥10μs

```

### 时序通信 → 总线通信

| | Day 17 超声波 | Day 18 IMU |
|---|---|---|
| 通信方式 | **时序**：脉冲宽度编码距离 | **总线**：两根线按地址 + 寄存器交谈 |
| 能否挂多个设备 | ❌ 一根线一个设备 | ✅ SDA/SCL 并联多个，靠地址区分 |

**两个细节**：① 地址是 **7 位**，第 8 位是读写方向，代码填 `0x68`，移位由库做；② 每传一个字节接收方要拉低 SDA 一拍作为 **ACK**，扫描器就是靠它判断地址上有没有人。

⚠️ I2C 是**开漏输出**，引脚只能拉低不能推高，靠上拉电阻维持高电平 —— **没有上拉就永远读不到 ACK**。MPU-6050 模块自带 4.7kΩ 上拉，所以本项目零额外元件；自己接裸芯片时要外加。

### 接线

| MPU-6050 | ESP32-S3 |
|---|---|
| VCC | **3V3**（模块自带 LDO；**别接 5V**，上拉若拉到 5V 会超出 3.3V IO） |
| GND | GND（**必须共地**） |
| SDA | **GPIO8** |
| SCL | **GPIO9** |

接线顺序：先 GND → 再 SDA/SCL → 最后 VCC；拆线反过来。

ESP32-S3 **没有固定 I2C 引脚**，任意 GPIO 都行，靠 `Wire.begin(SDA, SCL)` 指定 —— 这和 AVR（Uno 的 A4/A5 焊死）完全不同。但要避开 **strapping 引脚 0 / 3 / 45 / 46**：它们上电瞬间要采样电平决定启动模式，外接模块会把电平拉偏。Day 17 选 4/5 时已经给今天的 8/9 让开了位置。

### 加速度计为什么静止时读 9.8

静止在桌面上的加速度计测到的**不是重力，而是桌面的支持力**，大小等于重力、方向朝上 —— 它测的其实是"没掉下去"这件事。放平就该 `az ≈ 9.8`；**这是判断读数对不对最快的自检**。自由落体时读数是 0。

更狠的自检是看**模长**：`|a| = √(ax²+ay²+az²)` 静止时应恒等于 9.81，与摆放姿态无关。单看 `az` 偏小分不清是"没放平"还是"刻度错了"，看模长一刀切。

### 由重力反推倾角

```cpp
float roll  = atan2(a.acceleration.y, a.acceleration.z) * 180.0 / M_PI;
float pitch = atan2(-a.acceleration.x,
                    sqrt(a.acceleration.y * a.acceleration.y +
                         a.acceleration.z * a.acceleration.z)) * 180.0 / M_PI;
```

两个易错点：① **用 `atan2` 而非 `atan`** —— `atan` 只有 ±90° 且丢符号，`atan2` 覆盖 ±180° 全象限；② **pitch 的分母要取 YZ 合矢量模长**，偷懒写 `atan2(-ax, az)` 在 roll 大时会算错。

> 📌 这套公式**只在静止/匀速时成立**：加速运动时会有额外线性加速度叠加到重力上，算出的"倾角"是假的。这正是要用陀螺仪融合的原因。

### 两个传感器各自的短板

| | 长期准 | 抗震动 | 会漂移 |
|---|---|---|---|
| 加速度计求角 | ✅ 长期指向"下" | ❌ 一抖就乱跳 | 不会 |
| 陀螺仪积分 | ❌ 误差累积漂走 | ✅ 不受线性加速度影响 | **会**（静止时 gz 也不是严格 0） |

单独用哪个都不行。**互补滤波 / 卡尔曼**就是把两者融合的工程解法，超出本课。本课按指南要求只用加速度计求倾角，陀螺仪数据照读照打印。

> ⚠️ 陀螺仪单位是 **rad/s 不是 °/s**，乘 `180/π` 才是度每秒。

✅ 均通过（`--fqbn esp32:esp32:esp32s3`）：I2C 扫描 339664 bytes / 25%，IMU 读数 350632 bytes / 26%。

依赖链：`Adafruit MPU6050` (2.2.9) → `Adafruit BusIO` (1.17.4) + `Adafruit Unified Sensor` (1.1.15)，缺一个都编译不过。

### 实测

**实验 1**：12:25:42~12:26:00 连续 7 轮，每轮稳定 `found 0x68 = MPU-6050 (AD0=GND)`，`1 device(s) found.`，灯绿。

**实验 2**：`MPU6050 ready. SDA=GPIO8 SCL=GPIO9`，三个档位都触发过，灯色跟随正确。

静止 10 帧平均：`ax=0.41, ay=-0.07, az=7.82`，`roll=-0.6°, pitch=-3.0°`。
手动翻转的实测帧验证了 `atan2` 的价值：

| ax | ay | az | roll | pitch |
|---|---|---|---|---|
| 2.26 | **9.21** | **0.08** | **89.5°** | −13.8° |
| 1.87 | **9.45** | **−1.26** | **97.6°** | −11.1° |

立起来 90° 测得 89.5°，越过 90° 还能正确读出 97.6° —— `atan` 在这里会失效。

### ⚠️ 自检没过：az = 7.82 而不是 9.8

```
|a| = √(0.41² + 0.07² + 7.82²) = 7.83 m/s²    标准值 9.81，偏差 −20.2%
```

方向几乎正对 Z 轴（roll/pitch 才 3°），所以**不是没放平** —— 倾斜只会让 `az` 变小，模长仍是 9.81。模长本身就少 2 m/s²，是**灵敏度标定偏差**，13.8 元山寨模块的典型毛病。标定系数 `9.81 / 7.83 = 1.253`。

> 📌 这恰好说明**自检要看模长而不是单轴**：单看 `az=7.8` 会误判成"没放平"，看模长才能区分「方向错」和「刻度错」。

### 疑问：移动时 `az` 会变，怎么能说是"不准"？

增益误差是**乘性**的，它把变化的部分一起乘，不会把读数钉死。静止 `az=7.83` 对应真实 9.81；运动帧 `az=10.56` 对应真实 `10.56 / 0.798 = 13.2`，在手持晃动的线性加速度量级内。

运动帧模长范围 `5.63 ~ 10.85`，**最大值超过 9.81** —— 传感器坏了不可能冒出比重力还大的值。所以是两件独立的事：响应正常 ✅ / 绝对刻度偏小 ✗。

两次运行摆放角不同（`pitch` −3.0° 和 −5.5°，隔两小时），用同一个 k = 0.798 都能解释到小数点后两位：

| 运行 | 真实 ax / az | × 0.798 | 实测 |
|---|---|---|---|
| 13:01（pitch −3.0°） | 0.514 / 9.796 | 0.410 / 7.817 | 0.41 / 7.82 |
| 15:01（pitch −5.5°） | 0.940 / 9.766 | 0.750 / 7.793 | 0.75 / 7.83 |

纯增益误差，不是"读数卡住"。

> 📌 类比：刻度印短了 20% 的尺子。量桌子和量椅子，两个数都会变，但两个都小 20%。判据是**量一个已知长度的东西**，不是看它会不会变。

### 追问：上下晃动时 `az` 会冲到 9.8 附近

观察是对的 —— 第三份截图里 `az` 确实出现了 `9.79 / 9.88 / 10.04 / 10.26`。但**上下晃动是对称运动，线性加速度的平均值是 0**，所以 25 帧的平均 `az` 必须等于该倾角下的静止值。

| | 值 |
|---|---|
| 平均 pitch | −14.0° |
| 平均 az | **7.73** |
| 增益模型预测（`0.798 × 9.81 × cos14°`） | **7.60** |
| 若无增益误差应为 | 9.52 |

模型与实测只差 1.7%。那些冲到 10 的帧，是下落到最低点后**向上减速**的瞬间：

```
az = 10.26 → 真实 Z 轴比力 = 10.26 / 0.798 = 12.86
12.86 − 9.52（该倾角下的重力分量）= +3.34 m/s² 向上
```

**峰值来自加速度，不是来自准确的静态读数。** 该看的是平均值，而平均值仍然偏低 20%。

### 陀螺仪漂移有了具体数字

静止时零点偏移 `gx=-0.028, gy=0.030, gz=-0.009 rad/s`（≈ −1.6 / 1.7 / −0.5 °/s）。拿 `gy` 算账：

```
0.030 rad/s × 30 s = 0.9 rad ≈ 52°
```

**静止不动放 30 秒，单纯积分陀螺仪能跑偏 52°** —— "积分会漂"这句话从此有数了，也是为什么必须用互补滤波把加速度计拉回来。

### 踩的坑：实验 2 报 `not found`，但实验 1 同一条线扫得到 0x68

原因是**杜邦线母头没插到底，接触不良**。值得记的是为什么实验 1 能过：

| | 事务次数 | 失败后果 |
|---|---|---|
| 实验 1 扫描器 | 每个地址 1 次独立写 | 某一帧失败只丢一个地址，下一轮重扫又命中 |
| 实验 2 `mpu.begin()` | 地址探测 + 读 WHO_AM_I 一连串事务 | 中间断一帧，整个 `begin()` 返回 false |

**"扫描能过"不等于"接触可靠"** —— 扫描是偶发成功，库初始化要求连续成功。所以别一失败就去改代码，先重插线。

让一个 TT 直流马达正转、反转、刹车、滑行，并用 PWM 无级调速。第一次让代码输出机械转动，也第一次遇到 GPIO 驱不动的负载。

### 硬件
ESP32-S3 开发板（N16R8）+ TB6612FNG 电机驱动模块（焊好排针款）+ TT 马达 1:48 + 电池盒（2 节 5 号 = 3V，TT 马达额定电压）。6 根公对母杜邦线 + 电机直接拧在 AO1/AO2 端子，零额外元件。

### 为什么不能拿 GPIO 直驱电机

三个理由，一个比一个硬：

1. **电流不够。** ESP32-S3 单 GPIO 持续电流约 40mA，TT 马达空载就 100~200mA、堵转 1A 以上，差一个数量级。
2. **会烧 GPIO。** 电机是感性负载，断电瞬间的反电动势 `V = −L·di/dt` 尖峰可达电源电压数倍，直接击穿 GPIO。
3. **不会换向。** GPIO 只能输出 0 / 3.3V，反转需要把电机两端电压对调 —— 靠两组开关交叉连接实现，也就是 H 桥。

> 📌 分工就此定型：**GPIO 只发逻辑电平，大电流开关交给驱动芯片。**

### H 桥与 TB6612FNG 真值表

四个开关接成"日"字形，电机竖在中间：闭合 S1+S4 正转、S2+S3 反转、全断开滑行、S1+S2 同闭则两端短接成刹车。**绝不能同闭 S1+S3 / S2+S4** —— 那是直通，电源正负极直接短接。

TB6612FNG 一个芯片两套 H 桥，本项目只用 A 通道：

| IN1 | IN2 | PWM | 输出 | 模式 |
|:---:|:---:|:---:|---|---|
| 1 | 0 | 1 | OUT1=H, OUT2=L | **正转** |
| 0 | 1 | 1 | OUT1=L, OUT2=H | **反转** |
| 1 | 1 | 1 | OUT1=L, OUT2=L | **刹车** |
| 0 | 0 | x | 双高阻 | **滑行** |
| x | x | 0 | 双高阻 | **滑行** |

> ⚠️ **刹车和滑行是两回事**：`IN1=IN2=1` 才是刹车，`IN1=IN2=0` 是滑行。而且 `PWM=0` 时输出端是高阻、与 IN 无关 —— 所以"IN1=IN2=1 但 PWM=0"依然是滑行。**刹车 = 短接 + 有驱动能力，两个条件都要满足。**

### PWM 调速与开环局限

H 桥输出端只有通/断，PWM 靠快速开关给出**平均电压**：`duty 180/255 ≈ 70.6%` → 电机两端平均约 `3V × 0.706 ≈ 2.12V`。频率沿用 Day 10 呼吸灯的 `ledcAttach(PWMA, 5000, 8)`：5kHz 安静、开关损耗可接受；几百 Hz 会啸叫，太高则发热。

**本项目只能开环**：代码只管发 duty，不知道实际转速。同样的 duty，电池越用越没劲、负载变重、两个电机个体差异，转速都会掉。底盘套件的 TT 马达没有编码器引线，闭环测速要等 Day 28 前后。

> ⚠️ **duty 要乘 VM 才是真实电压。** 3V 电池下 `duty 180/255` 只有 2.12V 平均电压，低于 TT 马达的启动阈值 —— 表现为电机嗡嗡响但不转，而 AO1/AO2 用万用表量出来那 1~2V 恰恰是正常的（表读的是平均值，不是瞬时电平）。实测这块电机的起转点落在 duty 180~220 之间，改 220 后四种模式全部验证通过。代价是 3V 下 PWM 可调区间只剩 duty 220~255 这最后 14%，死区把最宽的一段从下面吃掉了。

PWM 渐变实验还从串口暴露了两件代码里看不到的事：`P_HOLD` 段因为 duty 不变、`if (duty != printedDuty)` 过滤掉重复行，串口会静默整 1 秒；而 `STEP_MS = 40` 的爬坡实测一步只 33ms 左右 —— `Serial.printf` 自己要花几毫秒。想做精确时序，别指望 `millis()` 节流加串口打印的组合。


### 接线三条关键

- **GND 必须共地**：电池负极、ESP32 GND、模块 GND 三者连一起。不共地时 GPIO 的"高电平"在模块眼里没有参考点，表现就是"代码在跑、电机没反应"。
- **VM 和 VCC 是两路独立电源**：VM 接电池 + 走电机电流（几百 mA ~ 1A+），VCC 接 ESP32 3V3 只有几 mA 逻辑电流。电池盒只装 2 节（3V）—— 这是套件 TT 马达的额定电压，装 4 节给到 6V 就是超压一倍，电流翻倍、温升大、寿命骤减。
- **STBY 直接接 3.3V 常高**：省一个 GPIO，芯片始终使能。

电机 AO1/AO2 不分极性，反接只会让转向反过来，拔下来对调即可。

### 代码要点

- 真值表直接翻译成 `switch`，刹车段 `ledcWrite(PWMA, 255)`，滑行段 `ledcWrite(PWMA, 0)`。
- `millis()` 非阻塞节流，不用 `delay(2000)`。
- PWM 从 duty 220 起步而不是 0：**死区** —— duty 太小电机根本不动，力矩得先克服静摩擦。死区高度由平均电压决定，3V 下起转点落在 220。
- ESP32 Core 3.x 的 PWM API 是 `ledcAttach(pin, freq, res)` + `ledcWrite(pin, duty)`，没有通道号；旧教程的 `ledcSetup` / `ledcAttachPin` 已删除。

**① 电机嗡嗡响但不转 —— duty 要乘 VM 才是真实电压**

改成 220（2.59V）四种模式全部通过。**这块电机在 3V 下的起转点落在 duty 180 与 220 之间。**

**② AO1/AO2 用万用表只量到 1~2V，不是故障**

万用表跟不上 5kHz 的开关，读到的是 PWM **平均值**，不是瞬时电平：`3V × 180/255 ≈ 2.12V` 正好落在 1~2V 区间。判据是 —— 读 0V 才是没输出，读 3.3V 才是常通，读中间值恰恰说明 H 桥在正常开关。

**③ 实验 2 烧录后"一直"响不转，代码上不可能**

duty 每 40ms +5，1.1s 内必然穿过起转点。实际原因是 `START_DUTY = 120` 时爬坡全程落在死区（平均电压 1.41V~2.12V）。判据看串口：`duty` 一路上涨到 255 还不转才是物理问题（端子松 / 掉压 / 带负载），`duty` 卡在起点不动则是烧进去的不是最新代码。

### 目标
让 SG90 舵机转到指定角度并停在那儿，再用串口输入目标角度实时控制。

### 舵机和昨天的 TT 马达差在哪

| | Day 19 TT 马达 | Day 20 SG90 舵机 |
|---|---|---|
| 控制量 | 转速（连续旋转） | **角度**（0°~180° 定位） |
| 反馈 | 无，开环 | 内部电位器测位置，**闭环在舵机里** |
| 需要驱动 | H 桥（要换向） | 不需要，单线 PWM |
| 给错指令的后果 | 转太快 / 转不动 | 堵转发热，可能烧 |
| 额定电压 | 3V | **4.8V** |

一句话：**马达是"给电压就转"，舵机是"给角度就停在那儿"。** SG90 拆开是电机 + 减速齿轮 + 位置电位器 + 控制板四件套，位置闭环由舵机自己做完，外部只发目标角度。

### 同一个 PWM 波形，完全不同的含义

今天最该记住的一句：

> **Day 19 的 PWM 里，脉冲宽度编码的是"平均电压 = 转速"；Day 20 的 PWM 里，脉冲宽度编码的是"绝对位置 = 角度"。波形看着一样，物理含义毫无关系。**

| | Day 19 电机 | Day 20 舵机 |
|---|---|---|
| 频率 | 5000Hz | **50Hz** |
| 周期 | 0.2ms | **20ms** |
| 编码量 | 高电平占比 | 高电平**绝对宽度** |
| 低电平是什么 | 另一半占空比，参与平均 | 纯间隔，"没有指令" |

```
一个周期 20ms ────────────────┬─────────────┬──────────
                              │             │
                              └─ 0.5ms ─┘   = 0°
                              └─ 1.5ms ─┘   = 90°
                              └─ 2.5ms ─┘   = 180°
                    剩下的 ~17.5ms 低电平无所谓
```

- 只有高电平的宽度有意义，剩下的是间隔。舵机在每个脉冲的上升沿重新读一次宽度。
- 0.5ms~2.5ms 是 SG90 的量程，不是协议规定。通用舵机测试仪上的"中点 1.5ms"是共识。
- 频率必须是 50Hz：控制回路需要约 20ms 采样一次。发快了来不及响应，发慢了保持不住会"抖"。
- 不需要换向，所以**不需要 H 桥** —— 昨天那套真值表今天整张作废，这是驱动电路的第一次"变薄"。

### 供电：Day 20 最大的坑

**信号线可以直接接 3.3V，功率线不行。**

SG90 高电平阈值约 2.0~2.5V，ESP32 的 3.3V 对它就是可靠高电平，信号线（黄色）直接接 GPIO，不需要电平转换。但红线必须外接 5V：

```
SG90 空载      ~100mA
SG90 带负载    200~300mA
SG90 堵转      700mA 以上
ESP32 3V3 脚   建议不超过 500mA（且与板载逻辑共用）
```

舵机不是逻辑器件，是机电执行器。**"逻辑电平兼容"不等于"功率兼容"** —— 今天供电上唯一需要记住的判据。

| 方案 | 做法 | 评价 |
|---|---|---|
| ① ESP32 板 5V / VIN 脚 | 舵机红线接板子 5V，USB 供电 | 省线，但 USB 只有 500mA。**堵转瞬间会把 USB 端口拉欠压，可能让整块 ESP32 重启**，且重启后舵机又堵转，进入循环 |
| ② 外接 3~4 节 5 号（4.5~6V）+ 共地 | 电池盒独立供舵机 | ✅ 推荐，舵机电流不碰开发板 |
| ③ 映棠 6V 电池盒 | 带盖带开关的 4 节盒 | 6V 在 SG90 工作范围（约 3.5~6V）内，能跑，且舵机会更快更热 |

SG90 标称 4.8V，接 6V 是超压 25%。短时调试可以，长期建议 3 节 5 号 = 4.5V。

**共地和 Day 19 一样是头号嫌疑**：外接电源负极、舵机棕线、ESP32 GND 三者连一起。少共地时 GPIO 的高电平在舵机里没有参考点，表现是"代码在跑、串口正常、舵机纹丝不动"。

### duty 换算与 14 位上限

```
周期        = 1 / 50Hz            = 20ms = 20000us
14 位步数   = 2^14                = 16384
每步时长    = 20000 / 16384       ≈ 1.221us
duty = 脉冲宽度(us) × 16384 / 20000
```

| 角度 | 脉冲宽度 | duty |
|:---:|:---:|:---:|
| 0° | 500us | **410** |
| 90° | 1500us | **1229** |
| 180° | 2500us | **2048** |

**ESP32-S3 的 LEDC 硬件上限就是 14 位**（`SOC_LEDC_TIMER_BIT_WIDTH = 14`，用 `template <int N> struct Reveal;` 编译探针实测）。所有舵机教程写的 16 位是**初代 ESP32**的参数，照抄到 S3 上 `ledcAttach` 在 `resolution > SOC_LEDC_TIMER_BIT_WIDTH` 一行直接返回 false，**且不打任何日志** —— 串口照常打印，舵机纹丝不动，看起来完全像接线问题。

14 位够用：反过来算 8 位（Day 10、Day 19 呼吸灯用的就是 8 位）：256 步，每步 `20000/256 = 78us`，而 0°→180° 全程只差 2000us —— **8 位的一个台阶就等于 7°**，舵机只能在 0、7、14、21… 这种糙度上跳。14 位每步 1.221us，全程 1638 个台阶 ≈ **0.11°/步**，比舵机机械回差还细。

### API 版本陷阱与 `parseInt` 三坑

旧教程的 `ledcSetup(0,50,16)` + `ledcAttachPin` 已删除，Core 3.x 改成 `ledcAttach(SERVO_PIN, 50, 14)` + `ledcWrite(SERVO_PIN, duty)`。

**自检只能信 bool 返回值。** 曾用 `ledcRead()` / `ledcReadFreq()` 复核，两个都会骗人：`ledcReadFreq()` 从时钟分频寄存器反推频率，50Hz 极低频下常算出 0Hz；`ledcRead()` 读影子寄存器，要等一个完整 PWM 周期（20ms）才同步，attach 后立刻读拿到残留值 —— 实测读到 6，真实 duty 是 410，舵机其实转得好好的。

串口输入角度被 `Serial.parseInt()` 的三个坑反复咬：

1. **默认 1 秒超时返回 0，而 0 是合法角度** —— 什么都没发它也会打到限位。用 `setTimeout(10)` 把等待压到 10ms。
2. **上一次的数字会粘住** —— `\r\n` 不是数字会被跳过，上一轮的"180"残留在缓冲区拼进下一轮。解析后 `while (Serial.available()) Serial.read();` 读干净行尾。
3. **只解析到第一个数字就停** —— `abc` 返回 0（碰巧合法），`12abc` 返回 12。所以范围判断不能只靠解析结果。

### 上机检查点

| 现象 | 判断 |
|---|---|
| 上电瞬间"咯噔"跳到某个位置 | 正常。上电到第一次 `ledcWrite` 之间没有脉冲，舵机处于自由态 |
| 不走指令时用手拧不动，是绷住的 | 正常。模拟舵机没有指令时**保持最后位置**，只有掉电才松掉 |
| 长时间停在固定角度不发热 | 正常。保持只需很小的保持电流 |
| **用手强行扭住不放 → 很快发热烫手** | ❌ **烧舵机最常见的方式**。堵转电流 700mA+ 全变成热 |
| 串口正常但舵机完全不动 | 头号嫌疑没共地，其次红线没接 5V |
| 抖动、嗡嗡响、角度不到位 | 供电不足（USB 500mA 被拉垮）或红线接到 3V3 |

**SG90 读不到实际角度**：它是模拟舵机，内部电位器的信号不引出到外部，所以和 Day 19 一样是开环 —— 代码知道"我发了 90°"，不知道"它是不是真在 90°"。

### 实测

**实验1**：串口打印 `attach=OK`、`duty 410 / 1229 / 2048` 与手算一致，`us` 回算正好 500 / 1500 / 2500us；视频里舵机在 0°→180° 之间摆。

**实验2**：串口监视器 115200 / Newline，依次输入 `0` `180` `90` `160` `30` `0`，回显 `duty 410 / 2048 / 1229 / 1866 / 683`，`us` 500 / 2500 / 1500 / 2278 / 834 —— 任意角度都落在 14 位公式上，视频里舵机跟着每条指令转到位。

分辨率写错时 `ledcAttach` 返回 false 却不打日志，串口照常打印而舵机不动。此时的 duty 是按错误分辨率算的：90° 在 14 位下是 `1229`、16 位下是 `4915`，180° 是 `2048` 对 `8192`。串口出现 4915 / 8192 这种值，就说明烧进去的不是当前固件。

### 目标

把 Day 19 的单电机扩成双电机差速底盘，再加 HC-SR04 做避障 —— 第一次出现「感知 → 决策 → 执行」的完整闭环。

### 差速转向：两轮车没有转向机构

```
直行      左 ●▶▶▶▶  右 ●▶▶▶▶    同速同向 → 直线
原地左转  左 ◀◀◀●    右 ●▶▶▶▶    等速反向 → 绕车体中心转，半径 ≈ 0
弧线左转  左 ●▶▶     右 ●▶▶▶▶    同向不同速 → 绕远处圆心走弧
```

原地转向最常用（转弯半径为零，死胡同能掉头），代价是两轮互相较劲、电流比直行大。

### 引脚：三个器件第一次同板共存

| 功能 | GPIO | 来自 |
|---|---|---|
| HC-SR04 Trig / Echo | 4 / 5 | Day 17 |
| MPU-6050 SDA / SCL | 8 / 9 | Day 18 |
| TB6612 AIN1 / AIN2 / PWMA（左轮） | 10 / 11 / 12 | Day 19 |
| TB6612 BIN1 / BIN2 / PWMB（右轮） | **15 / 16 / 17** | Day 21 新增 |
| SG90 舵机信号 | 18 | Day 20 |

舵机和 MPU-6050 **今天不接**：两轮 + 万向轮底盘不需要姿态就能跑，舵机是 Day 27 云台才上车。先只接要用的，少一组线少一处故障点。

### 接线

```
TB6612FNG                    ESP32-S3 / 电源
─────────                    ───────────────
VCC    ──────  3V3（逻辑）
GND    ──────  ESP32 GND 且 电池负极（共地！）
STBY   ──────  3V3（常高）
VM     ──────  电池盒 +（6V，电机电流不经过开发板）
AIN1/AIN2/PWMA ─── GPIO10 / 11 / 12   左轮
AO1/AO2 ──────  左电机 ±（接反不烧，只是转向反过来）
BIN1/BIN2/PWMB ─── GPIO15 / 16 / 17   右轮
BO1/BO2 ──────  右电机 ±

HC-SR04                      ESP32-S3
───────                      ────────
VCC    ──────  3V3
GND    ──────  GND（共地）
Trig   ──────  GPIO4
Echo   ──────  GPIO5
```

三条要点：**共地**（电池负极 / ESP32 GND / TB6612 GND / HC-SR04 GND 四点相连，漏接表现为电机不动且测距恒为 0）；**VM 与 VCC 两路独立**（电机电流走电池，不经过开发板）；**电池盒装 4 节 = 6V**，理由见下节。

### duty 从哪来：6V 电源 + 半占空比

电机线圈是电感，电流被平滑，吃的是**平均电压**而不是 PWM 峰值：

```
平均电压 = 电源电压 × 占空比
3V × 230/255 = 2.7V
6V × 115/255 = 2.7V
```

平均电压相同，马达的转速、扭矩、发热完全一样 —— 6V 峰值不会烧马达。换 6V 的真正理由是**内阻**：TT 马达启动瞬间堵转电流最大，2 节 5 号的内阻相对 3V 太大，两个电机同时启动就把电压拉垮，于是嗡嗡响不转，或者一个先转、另一个等电流降下来才转。6V 盒供得起的峰值电流大得多，才顶得开静摩擦。

所以巡航取 `115`、转向取 `120`、弧线内轮 `75`，起步再加 200ms 的 `150` 冲击。

两个 TT 马达有个体差异，直行会跑偏，代码留了 `TRIM_RIGHT` 手工补偿位。这是开环的固有缺陷 —— 真正的解法是编码器闭环。

### 两路 LEDC 不会打架

指南的 `Motor` 类把 `_channel` 硬编码成 0，两个实例抢同一路 LEDC。Core 3.x 的 `ledcAttach(pin, freq, res)` 按**引脚**分配、底层自动挑空闲通道，两行搞定：

```cpp
ledcAttach(PWMA, 20000, 8);
ledcAttach(PWMB, 20000, 8);
```

选 20kHz 而不是指南的 5kHz：超出人耳范围，消除 PWM 啸叫；周期变短，电流纹波更小，平均电压更接近理论值。

📌 **别用 `ledcRead()` 回读。** Core 3.x 下它恒返回 0，刹车时明明写了 255 却打印 `PWMB=0%`，很容易被误导成「B 通道坏了」。要打印就打印你自己写进去的那个值。

### 实验 1：双电机差速

自动轮播 8 个动作，每个 6 秒，灯色对应当前运动：

| 动作 | 左轮 / 右轮 duty | 灯 |
|---|---|---|
| 前进 / 后退 | +115 / +115 ｜ −115 / −115 | 绿 / 橙 |
| 原地左转 / 右转 | −120 / +120 ｜ +120 / −120 | 青 / 紫 |
| 左弧线 / 右弧线 | +75 / +115 ｜ +115 / +75 | 黄 |
| 刹车 / 滑行 | 两轮短接 ｜ 两轮断电 | 红 / 蓝 |

实测串口打印：

```
09:31:19.549 -> 绿灯 | 前进  两轮都向前 | 左轮=前进115 右轮=前进115
09:31:43.563 -> 黄灯 | 左弧线  左轮75慢+右轮115快（弯向左） | 左轮=前进75 右轮=前进115
09:31:55.534 -> 红灯 | 刹车  两轮短接，立刻停住 | 两轮短接制动
```

八个动作全部正常：原地转向确实是两轮等速反向（±120），弧线是外侧全速、内侧降到 75，车明显走弧。

刹车与滑行的区别沿用 Day 19 的真值表，两个电机各执行一次：刹车 = `IN1=IN2=1` 且 **PWM 必须非 0**；滑行 = `IN1=IN2=0`、PWM=0。`PWM=0` 时输出是高阻，与 IN 无关。

### 实验 2：超声波避障

在实验 1 之上加 HC-SR04，形成「测距 → 判断 → 动作」闭环。

### 避障状态机

```
CRUISE ──cm < 15──▶ BACK ──500ms──▶ TURN ──400ms──▶ COMMIT ──300ms──▶ CRUISE
```

`COMMIT` 是指南没有的一段：转完立刻测距，可能刚转 40° 又看到同一堵墙，车会贴着墙原地抽搐。强制前进 300ms 让它先离开障碍区。

**阈值必须带迟滞。** 指南的单一阈值 `dist < 15` 会在临界点振荡（退到 16 进到 14 反复抽搐），改成进入 15cm / 退出 25cm，中间 10cm 死区让状态稳住。

**`pulseIn()` 超时压到 6ms。** 只关心 15cm 以内，不需要 Day 17 的 30ms（400cm 量程）。超时的结果与远距一致 —— 反正都是前进，但最坏卡顿从 30ms 降到 6ms。

**转向左右交替。** `turnLeftNext` 每完成一次转向翻一次边，所以挡两次路就是一次左转、一次右转 —— 看到「一会儿左拐一会儿右拐」是设计如此。固定朝一边转会在夹角里越转越深出不来。

**障碍一直挡着就会一直避障。** 手停在 15cm 处，车就退 0.5s → 转 0.4s → 强进 0.3s → 测距 → 又触发，一轮约 1.2 秒循环下去。这是闭环在正常工作，不是卡死。

串口输出写成中文整句而不是 JSON 裸数字：避障是一串连续动作，光看 `{"cm":12.3}` 看不出「第几步、为什么转、往哪边转」。状态切换的那一刻打印原因，通畅时按 500ms 节流：

实测片段（手在车前方反复挡）：

```
前方 25.9cm，通畅 → 直行前进
第1轮｜前方 6.1cm < 15cm，挡住了 → 后退 500ms
第1轮｜原地左转 400ms（左轮后退 / 右轮前进，左右交替，下一轮换另一边）
第1轮｜转向已转开，强制前进 300ms 再重新测距（避免刚转开又看到障碍）
第2轮｜前方 14.8cm < 15cm，挡住了 → 后退 500ms
第2轮｜原地右转 400ms（左轮前进 / 右轮后退，左右交替，下一轮换另一边）
```

📌 **日志要解释「为什么」，不只是「是什么」。** 调试卡人的从来不是值是多少，而是它凭什么做了这个决定。JSON 留给 Python 解析，人看的现场日志另写一套。

「超出量程（>100cm）」和「读数无效（<2cm）」两种异常都当前方通畅 —— 结论都是没挡住，区别只在日志文字，这样传感器偶尔抽出异常值车也不会莫名后退。

### 实验 3：串口单步调试

`1`~`8` 一次跑 6 秒、刹车 1 秒，单步观察每一种运动。另加：

| 命令 | 作用 |
|---|---|
| `9` | 右轮连测：前进 3 秒 → 后退 3 秒，左轮全程断电 |
| `s` | 占空比扫描：两轮同时 80→255，每档 1.5 秒，找起转点 |
| `lf lb lz lc` | 左轮 前进 / 后退 / 刹车 / 滑行 |
| `rf rb rz rc` | 右轮 前进 / 后退 / 刹车 / 滑行 |
| `v` | 切换 6V / 3V 标定 |
| `0` | 立刻断电 |

单轮命令的另一路全程断电，用来把「电机/接线」和「供电」分开：单轮全都正常、双轮却不动，问题就不在电机和接线。

### 排查记录：两个轮子「时好时坏」

| 现象 | 真实原因 |
|---|---|
| 电机响但不转 | 峰值电流不够，顶不开静摩擦 |
| 一先一后 | 先转的那个电流降下来才轮到另一个 |
| 时好时坏 | 电池电压处在临界点 |
| 刹车时右轮还在转 | 同上，不是代码问题 |
| 8 条单轮命令全好 | 电机、接线、代码都正常 |

📌 **症状相似时，找「只差一个变量」的对照组。** 本次是「单轮 vs 双轮」—— 只差一条回路的电流，一下子就把范围缩到供电上。

### 成品化供电：脱离 USB（MP1584EN 降压模块）

ESP32 现在靠 USB 供电，车被一根线拴着。降压模块到货后按此接法断开 USB：

```
6V 电池盒
   ├────────────────────► TB6612 的 VM（电机动力，直连 6V，不经降压）
   │
   └──► MP1584EN IN ──► OUT 5V ──► ESP32「5V」引脚
                                    │
   电池负极 ──┬── TB6612 GND ───────┴── ESP32 GND   （三点共地）
```

⏳ 待降压模块到货后落地（2026-09-22 下单，运输中）：

1. 万用表量 MP1584EN 输出端，确认真是 5V 再上板
2. 6V 电池盒正负极各引出两路：一路进 TB6612 VM，一路进降压模块 IN
3. 降压 OUT 5V → ESP32「5V」引脚，负极 → GND，**三点共地**
4. 先不拔 USB，量完电压再拔；拔掉后串口监视器会断，属正常
5. 车放地上跑，复测 `TRIM_RIGHT` 与电压跌落

> ⚠️ **电机不能走降压模块。** 两个 TT 马达同时启动的堵转电流会超过 MP1584EN 的 3A，模块过流保护会打嗝，正是 §三 踩过的"电流供不出"那个坑。所以 6V 是**并联两路**：电机直连，只有 ESP32 走降压。
>
> ⚠️ **必须共地**，否则 TB6612 的 PWM 信号没有回流路径，电机完全不听使唤。
