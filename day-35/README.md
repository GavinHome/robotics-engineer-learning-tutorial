# Day 35 — 开环巡线

> 硬件：Day 34 的五路 AO + 五路 DO 一根不动，加上 Day 21 已经调好的 TB6612 双电机
> 核心：不用控制律，只用"线在哪一边"打方向，先把"哪偏哪纠"的方向验证对
> 固件：[`实验1-开环巡线.ino`](./实验1-开环巡线/实验1-开环巡线.ino)

## 一、今天为什么"不控制"

Day 33 有了 `pos`（线在哪），Day 34 有了 DO（线在不在），看起来只剩"把 `pos` 变成轮子
 duty"这一步。但这一步有个陷阱：**`turn = Kp × pos` 这个式子太自然了，自然到会跳过
 一件更要紧的事——方向。**

方向错了，`Kp` 调得再准都是反向放大：线在左边，车往右修，越修越偏。而且 `Kp` 小的时候
修正无力、看起来像"车有点抖但还在走"，很容易被误判成"P 值不够"而不是"符号反了"。

所以今天**故意不用比例项**，只用三档固定 duty：

| 情况 | 左轮 | 右轮 | 灯 |
|---|---|---|---|
| `|pos| ≤ 死区` | 巡航 115 | 巡航 115 | 绿：直行 |
| `pos < 0`（线在左） | 慢速 75 | 巡航 115 | 红：左弧线 |
| `pos > 0`（线在右） | 巡航 115 | 慢速 75 | 蓝：右弧线 |
| 丢线未超时 | 巡航 115 | 巡航 115 | 白：保持方向 |
| 丢线超 500ms | 刹停 | 刹停 | 红闪 |

`pos < 0 → 左轮减速` 这一条就是今天唯一要验证的东西。方向做成 `steerSign` 一个常数，
串口按 `s` 就能取反——**不用重新烧录**，两个方向都能试。

### 为什么不用 `map()` 把 pos 线性映射到 duty

指南特意点了这条。轮子的响应是非线性的：同样的 duty 增量，低速段和高速段转速变化
完全不是一个比例；起转点以下轮子压根不动（Day 21 实测 `DUTY_SLOW = 75` 就是故意压在
起转点以下，让外轮拖着内轮走）。`map()` 隐含"duty 和转速成正比"这个假设，今天它不成立。

今天用三档，等于**把这个假设整个躲开**。等 Day 36 上 P 控制时，同一个假设会以
`turn = Kp × pos` 的形式回来——那时候再破它，才知道边界在哪。

## 二、接线

Day 34 的十根线一根不动，只加 TB6612 的六根：

```
TCRT5000        ESP32-S3          TB6612          ESP32-S3
─────────       ────────          ──────          ────────
0~4 号 AO ───── GPIO6/7/8/2/3     STBY  ───────── 3V3（常高）
0~4 号 DO ───── GPIO1/13/14/21/47 AIN1/AIN2/PWMA  GPIO10/11/12  ← 左轮
                                   BIN1/BIN2/PWMB  GPIO15/16/17  ← 右轮
```

- TB6612 这六根**必须和 Day 21 完全一致**。今天的 duty 值（115/75/150）是 Day 21 在
  6V 下标出来的，换一根线这个标定就作废。
- `STBY` 直接接 3V3 常高，不占 GPIO。
- 五路模块的左右顺序不能反：`W[]` 按 0 号最左排，反一路 `pos` 的符号就反了，
  今天验证的方向就是错的。

## 三、串口命令

| 键 | 作用 |
|---|---|
| `c` / `b` / `w` / `t` | 标定白底 / 黑底 / 总表 / 量电位器阈值（Day 34 原样） |
| `p` | 曲线模式 |
| `q` | 静音：关掉每帧 raw 日志 |
| **`s`** | **转向方向取反** |
| `+` / `-` | 巡航 duty ±5 |
| `[` / `]` | 死区 ±25 |

`+`/`-` 和 `[`/`]` 是给"上车才发现标定值不对"留的：换电池电压、换地面摩擦，
duty 要重调，不用烧录。死区决定车在线上抖不抖——太小了来回摆，太大了该拐不拐。

## 四、上机步骤

1. **先不上线，架起来**。按 `c`（空白 A4 的白）→ `b`（黑底标定纸的黑区）→
   `w`（看标定表）→ `t`（横扫两个来回），五路判定必须全 `OK`。
   Day 34 留下的两颗雷（路0 只有 685 码余量、电位器方向没测）在这一步就会暴露。
2. **单独验方向**。把车放在线上，用手推着走一小段，看串口：
   - 线往左偏（`pos` 变负）→ 灯应该变红、`L75 R115`
   - 线往右偏（`pos` 变正）→ 灯应该变蓝、`L115 R75`
   - 反了就按 `s`。
3. **直道**。录一段，看它能不能一直跟住、丢线丢在哪。
4. **90° 弯**。这是今天最关键的一段：开环没有积分项，弯道里 `pos` 会持续同一个符号，
   车会一直打方向直到看不见线。看它是在弯心丢、入弯前丢、还是出弯后丢。
5. **记摆动**。把车放到线上不动（或很慢地推），数它一秒摆几个来回。这个数是
   Day 36 选 `Kp` 的起点——同样的摆动幅度，P 控制要小得多的增益才能达到。

赛道用黑胶带贴，或打印 [`巡线轨迹-A4.svg`](./巡线轨迹-A4.svg)：A4 横放、缩放 100%、
边距“无”、开“打印背景图形”，线宽 10mm，一张纸只有直道 + 90° 弯 + 尺子。

标定不印在轨迹纸上，另有一张 [`黑底标定-A4.svg`](./黑底标定-A4.svg)：黑区 190×150mm，
`b` 和 `t` 用它，白底 `c` 用一张空白 A4。拆成两张是因为五路阵列展开约 75mm，
黑区在阵列方向上必须比它大——黑块小了，车稍微一歪最外的传感器就压到黑外面，
`b` 采到的是黑白混合，`t` 表立刻散架（靶心五路差一千多码就是这么来的）。

打印黑吸红外弱（实测 2000~3000），照样能标——`b` 逐路标定就是为弱黑设计的；
有条件用黑笔或染料在黑区和线路上再描一遍，读数更高、余量更大。

## 五、要记录的东西

- 方向对不对，反了是按 `s` 修的还是改代码修的
- 直道上丢线的位置和当时的 `pos` / 五路 DO 组合
- 90° 弯上丢线的位置：**入弯前丢 = duty 太大冲过去了；弯心丢 = 慢速档太慢；
  出弯后丢 = 恢复太慢**，三种原因对应 Day 36 三种改法
- 到线附近来回摆的频率和幅度
- 两个 TT 马达不一样快的话，直道上车会往一边偏，记下偏的方向和 `TRIM_RIGHT` 补多少
