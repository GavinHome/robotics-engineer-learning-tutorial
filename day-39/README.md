# Day 39 — MPU-6050 裸读 + 校准

> 硬件：MPU-6050 模块（插针款，库里）+ 面包板，**不装车**
> 核心：不装库、照数据手册把原始量读出来，再把零偏校掉——自平衡车角度环的地基
> 固件：[`实验1-MPU6050裸读.ino`](./实验1-MPU6050裸读/实验1-MPU6050裸读.ino) ｜ [`实验2-标度验证.ino`](./实验2-标度验证/实验2-标度验证.ino)

## 一、MPU-6050 在平衡车里只干一件事

给角度环一个**不漂移的俯仰角**。就这一件。

今天的活分两半，对应这个目标的两层地基：**读得对**（裸读 + 换算）和**校得平**（零偏 + 标度）。明天在同样的原始量上做互补滤波，把"不漂移"补上；再往后才是平衡车的角度环。一层一层往上加，出了错好定位。

## 二、为什么"裸读"也算一件事

第 1 个月（Day 18）用 `Adafruit_MPU6050` 库读过这颗芯片，扫过地址、拿过数据。今天再读一遍，**故意不装库**——因为库把"读寄存器"这件事包掉了，而自平衡车的角度环出问题时，你得能自己下手查：

- 读数恒 0 → 九成是 `PWR_MGMT_1` 没写 0，芯片还在睡眠
- `WHO_AM_I` 回 0xFF 或 0 → 地址错、没共地、或母头没插紧（Day 18 真踩过：扫描器能扫到 0x68，库初始化却报 `not found`，最后查出来是接触不良）
- 数字在飘但幅度不对 → 量程选错，灵敏度差 2/4/8 倍

这三件事库都不会告诉你，它只会回一个 `false`。**里程碑"不看教程、根据数据手册连接并读取 I2C 传感器"要的就是这个手感**：手册翻到寄存器表，自己找地址，自己拼高低字节。

## 三、数据手册里只查三个寄存器

不用通读。今天只查三个，其余照默认值：

| 寄存器 | 地址 | 干什么 | 期望值 |
|---|---|---|---|
| `WHO_AM_I` | 0x75 | 芯片自报家门，验 I2C 地址 | 0x68（AD0 接 GND） |
| `PWR_MGMT_1` | 0x6B | 电源管理，写 0 退出睡眠 | 写 0x00，**不写所有读数恒 0** |
| `ACCEL_CONFIG` | 0x1C | 加速度计量程 | 0x00 = ±2g |

数据起始地址 `ACCEL_XOUT_H = 0x3B`、`GYRO_XOUT_H = 0x43`、`TEMP_OUT_H = 0x41`，从 0x3B 起头可以**一次 burst 读 14 字节**（加速度 6 + 温度 2 + 陀螺仪 6）。

### 灵敏度：每一位等于多少

| 量程 | 灵敏度 | 本日固件 |
|---|---|---|
| ±2g | 16384 LSB/g | ✅ 选它（Day 40 的俯仰角只需要 ±1g，量程小分辨率才高） |
| ±4g | 8192 LSB/g | |
| ±8g | 4096 LSB/g | |
| ±16g | 2048 LSB/g | |
| ±250°/s | 131 LSB/(°/s) | ✅ 选它（平衡车的角速度很小，用大量程等于浪费分辨率） |

⚠️ 灵敏度的正确算法是**满量程 ÷ 65536**（16384 = 32768×2/4）。拿 32768 除会得 32768/2 = 16384 看着对，但那是因为 ±2g 碰巧；换成 ±8g 就算错。写进固件前先在纸上推一遍。

⚠️ `ACCEL_CONFIG` / `GYRO_CONFIG` **写完要回读确认**。I2C 写操作不返回成功与否，读出来不是 0 就说明没写进去——这个坑的表现是"量程莫名差 2 倍"，查半天寄存器。

## 四、接线

```
MPU-6050         ESP32-S3
────────         ────────
VCC      ──────  3V3（模块自带稳压 + LDO，别把 5V 接到 SDA/SCL）
GND      ──────  GND（必须共地，否则没有回流路径，总线永远读不到 ACK）
SDA      ──────  GPIO41
SCL      ──────  GPIO42
INT      ──────  悬空（今天轮询就够，不接中断）
AD0      ──────  GND（决定 I2C 地址 = 0x68；接 VCC 是 0x69）
```

- **接线顺序：先 GND，最后 VCC；拆线反过来。**
- **别用 GPIO 0 / 3 / 45 / 46 做 I2C**——那是 strapping 引脚，上电瞬间要采样电平决定启动模式（SPI boot / JTAG 之类），外接模块会干扰启动。
- **今天用 GPIO41/42，是小车上唯一还空着的一对。** 整车已占用 4、5、6、7、8、9、10-18、21、47；ESP32-S3 还有一批不能碰的：19/20 是 USB、26-32 接 SPI flash、33-37 是 N16R8 的 PSRAM、43/44 是串口、48 是板载 RGB。剩下能自由用的就是 38-42，今天取 41/42（相邻两根，走线短）。
- ESP32-S3 **没有固定的 I2C 引脚**，任意 GPIO 都行，靠 `Wire.begin(SDA, SCL)` 显式指定。AVR（Uno）那套"硬件 I2C 就是 A4/A5"在这里不成立。
- **别让电机线贴 I2C 线**。今天不装车，但自平衡车上 PWM 噪声会顺着底盘传进 MPU，提前把走线习惯养好。

## 六、实验 2：零偏与标度

**零偏**（按 `k`）：板子平放别动，固件采 2000 次（约 3.3 秒）求均值，存 flash。采的时候手别碰、桌上别有风扇/手机震动——均值里混进扰动，比不校还糟。

固件会自检这次校准干不干净：**平放且不动时 `ax/ay` 零偏 < 500 LSB（0.03g）、`az` 零偏 < 500、陀螺三项 < 300 LSB（2.3°/s）**。超了就打 `⚠️ 这次校准可疑`——那时候存进去的是一份脏零偏，之后每个读数都会错，不如重按一次 `k`。

⚠️ **az 的零偏要扣掉 1g，这是今天最容易栽的一步。** 平放时重力全压在 az 上，实测均值 = 零偏 + 1.000g（实测原始 az ≈ 13152 LSB = 0.803g，而它本该读 1.000g）。若把整个 13152 都当零偏减掉，去偏后 az ≈ 0，平放就不再是 +1.000。所以固件存的是 `实测均值 − 16384`——**减掉的只是零偏那一小截，1g 是真实信号，不能减**。陀螺仪没有这个问题，静止就是静止，六轴里只有 az 特殊。

⚠️ **第一次裸读平放只读到 az = +0.794**（期望 +1.000）。这个差得有点多：换算成姿态是倾斜约 37°，要么模块没放平（面包板上歪着、底下压着线），要么这颗 az 轴零偏异常。重放平一次再看 `w`——**如果还是 0.79 附近，就按 `k` 把它当零偏收进来**，此时标度验证会告诉你是哪一种：合成重力仍是 1.000 说明只是零偏，合成重力变成 0.79 说明标度也坏了。

**标度**：三种姿态各摆一次。摆好一个按一个数字键——**`1` 平放 / `2` 竖放 / `3` 倒放**，固件每键采 100 帧求均值（单帧有 ±0.01g 噪声，抄单帧没意义；采集时黄灯亮，手离开板子）。三个都记完按 **`v`**（或 `p`），零偏 + 两张 markdown 表一次全打出来，**整段复制粘贴进本节就行**，不用盯着滚动的窗口抄。

1. 单轴分量对不对（平放 `az ≈ +1.000`、竖放 `ay ≈ ±1.000`、倒放 `az ≈ −1.000`）
2. **合成重力大小**——`√(ax²+ay²+az²)`，任意姿态都该是 **1.000**

第二条才是标度的判据。第一条对、第二条不对，说明三个轴的灵敏度不成比例（很少见，但存在）；第一条就错，说明零偏没校干净或姿态没摆对。

三个姿态的摆法——不是"抬头/低头"，是**把板子整个转过去，让重力换一根轴压**：

| 键 | 姿态 | 怎么摆 | 期望 |
|---|---|---|---|
| `1` | 平放 | 板子平躺桌面，芯片朝上 | `az = +1.000` |
| `2` | 重力换到横轴 | 侧放或竖放都行——**哪个摆得稳用哪个** | `ax = ±1.000` 或 `ay = ±1.000` |
| `3` | 倒放 | 板子翻过来，芯片朝下扣桌面（转 180°） | `az = −1.000` |

`2` 记哪根轴都无所谓，`3` 甚至可以做也可以不做——**标度判据只看合成重力，不关心重力落在哪根轴上**。而平衡车的俯仰角用的是 `atan2(ax, az)`，所以**最值得验的是 `1`（az）+ 一次让 ax 朝上的侧放**，这两根覆盖了角度环真正要用的分量。ay 是横滚，平衡车上用得少。

⚠️ **线会拽着模块，这是杜邦线直连的固有麻烦。** 三个办法：① **把 ESP32 也平放到桌面上**，USB 线留长，让四根杜邦线自然弯曲带松弛——线不绷就不拽；② 竖放/侧放靠一个直立的盒子或书堆，线从盒子顶面平铺过去；③ 倒放时用一本书轻轻压住 PCB 边缘（别压黑色芯片），或者用蓝丁胶/双面胶把模块粘在桌面上、线用胶带粘平。**能省的折腾是：挑摆得稳的姿态做，不必三个都做。**

| 姿态 | ax | ay | az | 合成重力 | 判定 |
|---|---|---|---|---|---|
| 平放 | −0.000 | −0.000 | **+1.001** | **1.001** | ✓ |
| 竖放 | +0.101 | +0.979 | −0.065 | 0.986 | ✓（偏 −1.4%） |
| 倒放 | +0.063 | −0.019 | **−1.031** | 1.033 | ✗ 偏 +3.3% |

**平放 1.001，标度本身是好的**——三个轴灵敏度不成比例的话，平放也不会正好落在 1.000。

竖放 −1.4%、倒放 +3.3%，两次重摆结论不变。关键线索是**倒放的合成重力超过了 1.000**：倾斜只会把 1g 摊到几根轴上，合成永远是 1g；**超过 1g 只能是额外多了力**。所以不是"摆歪了"，是板子被压着。

再往下查一层：平放读 `+1.0005`、倒放读 `−1.0314`，**两者不关于 0 对称**。纯标度误差会让它们对称（同乘一个系数），不对称说明**零偏本身随姿态变了**。原因是模块插在面包板上，插针和面包板成了传力路径，倒放时模块自重压着插针 → PCB 微形变 → 应力传到 MEMS 芯片，零偏就动了。这是廉价模块的常见现象，不是芯片坏了。

**本次实验根本不用面包板**——只用到 VCC/GND/SDA/SCL 四根线。拔下来用四根杜邦线直连，倒放时模块自己躺在桌面上，不受力。再按一次 `3`：

- 回到 1.000 → 证实是装配应力，标度没问题，这个坑记下来就行
- 还是 1.03 → 模块本身在这个方向零偏异常，也不影响平衡车（见下）

**这个偏差值得为它较劲吗？不值得。** 3.3% 的标度误差在 `atan2` 里造成的角度误差约 `3.3% × tanθ`：平衡车只在竖直附近 ±10° 工作，`tan10° ≈ 0.18`，误差 ≈ **0.6°**；而且互补滤波里加速度计只负责慢速校正，快响应全靠陀螺仪。为了 0.6° 换芯片或拆模块重焊，代价远大于收益。记下来，往前走。

### 一轮作废的记录：零偏脏了，整张表都是假的

后来按 `k` 时板子歪着而且在动，得到的零偏是 `ax=+257.5 ay=−2028.1 az=−3349.7`、陀螺 `gz=−173.0`——对比之前干净的 `ax=+59.0 ay=−72.6 az=−3222.4`、`gz=−75.4`：

- **`ay` 从 −72 跳到 −2028**，差 1955 LSB = 0.12g，相当于校准时板子歪了 **7°**
- **陀螺 `gz` 从 −75 变到 −173**，静止时它应该很稳，变了 100 LSB 说明那 3.3 秒里板子在转

拿这份脏零偏算出来的表全是假的：平放 1.014、竖放 1.098。而最后一条"竖放"记录其实是 `ax=−0.942 ay=+0.144`——**板子侧躺着，根本不是竖放**，三个 ✓ 纯属撞上的。从记录里能看出板子一直在滑：`ay` 从 1.09 一路掉到 0.14。

**教训：标度验证之前先确认零偏是干净的。** 零偏错了，三个姿态的读数会一起错，而且错得看不出规律——你会以为标度坏了，其实只是校准时手抖了。现在固件会自己喊出来。

### 六面自动标定：把三轴都标全

上面 3 步法（平放/竖放/倒放）有个**结构缺陷**：只有 Z 轴朝上+朝下各一次，两个水平轴从没单独朝上过，它们的零偏和标度根本算不出来。表现就是竖放合成重力 1.097、倒放 1.028、平放 `ax=0.103`（X 零偏没标）——**不是手抖，是这三个姿态装不下三根轴**。

[`实验2-标度验证.ino`](./实验2-标度验证/实验2-标度验证.ino) 改成**六面法**：X/Y/Z 每根轴都朝上一次、朝下一次，共 6 个姿态，用每轴的 `(max+min)/2` 求零偏、`(max−min)/2` 求标度。每根轴都同时拿到 +1g 和 −1g 两个基准，标度才立得住。

固件是**自动标定**，不用边盯实时数边按键（那样单手保持必然晃）：上电只做准备和提示，发 `s` 才开始；随后依次提示 6 个方向，每个"文字提示 → 摆好松手 → 3 秒摆位倒计时 → 8 秒自动采均值 → 自动下一步"。粗检只提示不拦截，摆歪了也一路走完，标完发 `v` 出两张表，整段复制即可。

6 个姿态（纯物理描述，不用记 X/Y）：

| 步 | 姿态 | 怎么摆 |
|---|---|---|
| 1 | 平放 | 芯片丝印朝上，放桌面 |
| 2 | 倒放 | 翻面，芯片朝下贴桌 |
| 3 | 竖-A | 沿短边立起，引脚(VCC)那头朝上 |
| 4 | 竖-B | 竖-A 翻过来，引脚那头朝下 |
| 5 | 竖-C | 沿长边立起：**有排针（8 个引脚）那条长边着桌**，排针那头朝下 |
| 6 | 竖-D | 竖-C 翻过来：换成**没排针那条长边着桌**，排针那头朝上 |

标定结果（合成重力全部回到 1.00）：

| 姿态 | ax | ay | az | 合成重力 |
|---|---|---|---|---|
| 平放 | +0.054 | −0.005 | +1.000 | 1.001 |
| 倒放 | −0.086 | −0.040 | −1.000 | 1.004 |
| 竖-A 短边·引脚朝上 | +0.050 | +1.000 | +0.050 | 1.002 |
| 竖-B 短边·引脚朝下 | +0.070 | −1.000 | −0.036 | 1.003 |
| 竖-C 长边·排针朝下 | +1.000 | −0.124 | −0.023 | 1.008 |
| 竖-D 长边·排针朝上 | −1.000 | +0.008 | −0.041 | 1.001 |

推算标定参数：零偏 `ax≈+750 ay≈+254 az≈−3488`，标度 `ax≈16412 ay≈15626 az≈16553`（都接近 16384）。对比 3 步法的 1.097 / 1.028，六面法把三轴全收到 1% 以内。

> 竖-C 的 `ay=−0.124` 偏大，是沿长边立那两步板子歪了约 7°；只轻微影响竖-C 自己（|g|=1.008），不污染标定。**装配应力仍要靠直连消除**（见 §八）：六面法能标好零偏和标度，但插针传力带来的姿态相关误差标不掉。

### 不校准会怎样

固件上电时如果 flash 里没有零偏记录，`calibrated = false`，**故意不减零偏直接打原始值**——这就是要看的"不校准长什么样"。这一栏不用单独记：`v` 出的汇总里，表2 的"校准前"用的就是同一姿态的原始 LSB 均值，一次就有。

| | 校准前 ax/ay/az | 校准后 ax/ay/az |
|---|---|---|
| 平放 | +0.004 / −0.005 / **+0.804**（raw +58 / −76 / +13170） | −0.000 / −0.000 / **+1.001** |

校准前 `az` 只有 0.804——这就是**不校准长什么样**：车的"竖直"会被认定在倾斜 36° 的地方，角度环会一直朝一个方向使劲，看着像车坏了，其实是静差。

⚠️ **姿态记录也存 flash**（和零偏同一个 NVS 命名空间）。早先只存内存，清一次控制台或复位板子，姿态全丢而零偏还在，汇总表就打出三个"未记"——不是固件坏了，是数据没落盘。现在重启后按 `v` 照样出表。

记住这个偏置。后面平衡车的角度环会用到：**自平衡车角度环的角度零点来自这颗 MPU，零偏不校 = 车的"竖直"是斜的**，它会一直朝一个方向使劲，看起来像"车坏了"，其实是静差。

## 七、串口命令

| 键 | 作用 |
|---|---|
| `a` | 加速度计：g + 原始 LSB（默认） |
| `g` | 陀螺仪：°/s + 原始 LSB |
| `t` | 温度（`raw/340 + 36.53`，用来看芯片有没有被烤热） |
| `r` | 六轴紧凑格式，给绘图脚本 |
| `k` | **校零偏**：采 2000 次，存 flash |
| `w` | 看当前零偏 / 量程常量 |
| `1` / `2` / `3` | **记姿态**：平放 / 竖放 / 倒放，各采 100 帧求均值 |
| `v` 或 `p` | **出汇总**：零偏 + 两张 markdown 表，整段可复制 |
| `0` | 静音 |

彩灯：蓝=初始化、绿=正常打印、黄=正在采零偏（别碰）、红=`WHO_AM_I` 对不上。

**NVS 命名空间 `day39`**，存 6 个零偏 + 一个 `cal` 标志，外加三个姿态的原始均值（`p0`/`p1`/`p2` + `pmask` 位图）。Day 40 的固件读零偏那一份——校准只做一次，不是每天重做。

## 八、几个今天就会遇到的坑

**`endTransmission(false)` 的 `false` 是什么。** 它是"不释放总线"（发 restart 而不是 stop）。读寄存器必须 `beginTransmission → write(reg) → endTransmission(false) → requestFrom`，少了 `false` 的表现是 `WHO_AM_I` 恒回 0xFF，而且错得非常稳定——最难查的那种。

**别读 6 次。** 一次 `requestFrom(MPU, 14)` 从 0x3B 拉完，比分六次读快一个数量级，更重要的是**六轴是同一时刻的采样值**。分次读的话加速度和陀螺仪之间差几毫秒，做融合时就是一个时间错位——Day 40 的 `gyr × dt` 会因此对不齐。

**读不满 14 字节就当帧作废。** `Wire.available() < 14` 时返回全 0，别用半包数据。校零偏时这种帧也要跳过（`if (s.ax==0 && s.ay==0 && s.az==0) continue;`），否则均值被拉偏。

**"有效帧只有 0/100，放弃"是 I2C 断了，不是测不出来。** 100 帧全是 0 = `requestFrom` 一字节都没拿到。这种时候固件**故意拒绝记录**——把 100 个 0 平均成一份"数据"写进表格，比报错危险得多。报错时先按 `a` 看流：raw 全是 0 就是线的问题（杜邦线没插紧 / 没共地 / VCC 松了），跟姿态、跟面包板都没关系。

**温度不用校。** 它不准（ datasheet 只给 ±0.x °C 量级而且没标定点），打出来只是为了判断"芯片是不是被电机烤了"。角度计算不用它。

**改了零偏算法必须重按一次 `k`。** 零偏是**存进 flash 的数字**，上电时原样读回来用，固件不会重新算。所以换了算法、改了公式之后，flash 里那份旧值还在——表现就是"代码明明改了，读数还是老样子"。改完算法第一件事是按 `k` 覆盖掉旧记录，按完看 `w` 确认新值写进去了。

**装配方式会影响力读数。** 模块插在面包板上时，倒放测出合成重力 1.033（超过 1g）。超过 1g 只能是额外多了力——插针和面包板成了传力路径，模块自重压着插针让 PCB 微形变，应力传到 MEMS 芯片，零偏就随姿态变了。**今天这种只用到 VCC/GND/SDA/SCL 四根线的实验，别插面包板**，四根杜邦线直连最干净。这条对以后上车同样成立：MPU 固定在底盘上的方式、螺丝松紧、垫片材质，都会影响力读数——装车时也要留意。
