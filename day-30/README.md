## 一、第 1 个月到底做了什么

30 天不是 30 个孤立实验，是一条线：**从"点亮一个 LED"到"一辆能自己躲障碍、能被手机遥控的机器人"**。

| 周次 | 天数 | 主题 | 终点 |
| --- | --- | --- | --- |
| 第 1 周 | Day 1–7 | 电路基础 + 面包板 | 手算 5 道电路题、Tinkercad 搭自动路灯、面包板实测 |
| 第 2 周 | Day 8–14 | ESP32-S3 外设 | 数字电压表：ADC + 分压 + 多次采样平均 + 单点校准 |
| 第 3 周 | Day 15–21 | 手工 + 传感器 + 电机 | 焊接过关、超声波 / IMU / 电机 / 舵机全上过手 |
| 第 4 周 | Day 22–29 | 软件 + 联网 + 整理 | Wi-Fi 遥控小车、Python 遥测绘图、GitHub 主页 |

一条贯穿的主线是**感知—决策—执行**：第 1 周只有"执行"（LED 亮灭），第 2 周有了"感知"（电位器 / 电压），第 3 周执行升级成电机、感知升级成超声波和 IMU，第 4 周把三者用 Wi-Fi 串成一个闭环，并且这一整段只用了一块开发板、一个传感器都没浪费。

### 学会了什么（按主题归并）

**电路与测量**：欧姆定律、串联分压、LED 限流电阻怎么选，以及万用表的三种用途——量电压电流、通断档验虚焊、上电前查电源短路。第 1 周在手算题上栽过的跟头，第 4 周在真车上救了命：换 6V 电池盒不是因为要更快，是因为 2 节 5 号的内阻供不出两路电机同时启动的峰值电流。

**GPIO 输出**：`digitalWrite()` 的高低电平，以及 PWM 用占空比假装"模拟量"。占空比不是电压——`DRIVE_DUTY = 180` 在 3V 电源上平均只有 2.12V，电机嗡嗡响不转；这就是平均值和瞬时值的差别。

**GPIO 输入**：`INPUT_PULLUP` 用芯片内部 ~40kΩ 上拉，按键按下 = LOW，这就是"低电平有效"；机械触点弹跳要 20ms 消抖。

**模拟输入**：12 位 ADC 出 0–4095，除以 4095 乘 3.3 就是电压；单点不够，要多次采样平均；即使这样仍有系统误差，用已知的 3V3 和 USB 5V 各测一次解出 `CAL_SCALE = 1.0055` 才算完。

**总线与协议**：HC-SR04 的 Trig 发 10µs 高电平、量 Echo 高电平宽度、用 340m/s 换算距离；MPU-6050 走 I2C，靠设备地址寻到它、按寄存器地址读写；SG90 靠 50Hz 下的脉宽表达角度，20ms 一帧、0.5–2.5ms 为 0–180°。这三件事背后是同一件事：**没有时钟线也要两台设备商量好时间**。

**电机驱动**：不能拿 GPIO 直驱电机，H 桥靠"两侧晶体管不同时导通"的排列实现正反转，同一组输出既能驱动也能刹车，占空比从 0 到满就是滑行到全速；两个电机差动就是转向。

**手工**：烙铁头镀锡是后面一切的前提，五步焊接法、冷焊的识别（光泽差、焊点呈球状）、用导通档验证每一焊、用吸锡器返修。手上这道关过了，后面所有"焊好排针款即插即用"的模块才真的可信。

**软件侧**：Python 把串口数据落成 CSV、画成曲线；ESP32 起 Web Server，同一个 `/data` 接口既能给人看、也能给程序看；`millis()` 取代 `delay()`，让心跳、轮询、彩灯、避障在同一个 `loop()` 里并行；用状态机把"直行—转向—强制前进"写清楚，让障碍不挪开时车也不会卡死。

**工程习惯**：改动要能被验证——编译过、上机跑过、logs 对得上；出问题先量再猜，引脚接错、LED 长短脚反、电阻选大，三类问题用万用表一分钟分清。

### 哪些概念仍未掌握

- **闭环控制**：PWM 调速是开环的，给多少 duty 就期望多快，但实际转速受电压、负载、地面影响；编码器读数 → 位置环 / 速度环闭合，一次都没碰过。这是第 2 个月的第一课。
- **姿态融合**：MPU-6050 的原始加速度和角速度读过，但把两者融成一个稳定角度（互补滤波 / 卡尔曼）没有做过。自平衡车的前提就是这个。
- **按数据手册独立接线**：现在是照着教程配库，I2C 传感器的寄存器表还不敢直接读全英文手册自己写驱动。
- **焊接平整度**：Day 16 遗留，锡量偏少、沿腿拉长，焊点功能对但不好看。
- **代码组织**：单文件 `.ino` 已经到两三页长，模块化、配置外置还没系统练过。

> **最大的成就感是什么？**
> 是**把一个又一个孤立的基础元件，攒成了一辆真能跑的聚合物件**。电阻、电容、电位器、姿态传感器，从认识它们开始；ESP32 开发、驱动电路、电源降压模块，一个个单独上手；最后装成小车、跑起来——这是以前根本不敢想的事，而且全程没有抄现成方案，是在基础电路上自己一点一点搭的。
> 这个过程的收获不在于"精通"了哪一个元件，而在于**弄清了输入输出，就知道怎么用了**。HC-SR04 只是一个模块，搞清 Trig/Echo 两脚的高低电平和时序，就能用 GPIO4/GPIO5 让它测出前方距离；写代码控制一个脚输出、用占空比做左右轮差速，本质都是同一回事。模块不用全懂，脚位和时序懂到能驱动它，就够往前走一步。
> 还有焊接。一开始焊得不好，换一把 80W 数显调温烙铁、掌握手势和时机之后，明显顺了——**手上这道关是靠换对工具加练跨过去的，不是靠熬时间。**

> **如果重来一次，会做什么不同的选择？**
> **没有不同的选择。** 基础这些东西，跳不过去，也勉强不来，重来一次还是一天一天这么过。唯一的奢望是选一个更高难度的目标——比如机器狗、双足机器人。但那也是要等现在这些基础结了果才够得着的东西：差速转向、占空比、姿态读数、I2C，一个都绕不开。
>
> 换句话说：第 1 个月不是保守，是**必经**。想直接上机器狗，缺的恰恰是这 30 天补的东西。

## 四、第 2 个月预习

逐日指南已就位：[`进度/第2月-30天逐日指南.md`](../进度/第2月-30天逐日指南.md)。**它只写增量**——GPIO / PWM / I2C / 串口 / Web Server / Python 第 1 个月全练过，一个天数都不重复编排，30 天全部投给第 1 个月没碰过的四件事。

本月目标：**造一辆能移动、能感知环境、并能自我纠正的机器人。**

按周排：

| 周 | 天数 | 内容 |
| --- | --- | --- |
| 第 1 周 | Day 31–37 | 中断 → 编码器 → 转速换算 → P 速度环 → 精确转一圈 |

| 第 4 周 | Day 52–58 | ⭐ 自平衡机器人（角度环 → PD → 速度环 → 遥控联调） |
| 收尾 | Day 59–60 | 月度复盘 + GitHub 上两个可运行机器人 + 第 3 个月准备 |

Day 31 第一站是**中断**，不是循线：编码器必须用中断计数，而反应计时游戏能用现有按键和 LED 把中断吃透，等新件到货再上硬件——**不空转**。

**内部顺序不能反**：先编码器闭环（速度可测才谈得上可控），再姿态融合（自平衡的前提），然后循线（建在差速和 PWM 之上），最后自平衡（要用到前两样的全部成果）。

**内部顺序不能反**：先编码器闭环（速度可测才谈得上可控），再姿态融合（自平衡的前提），然后循线（建在差速和 PWM 之上），最后自平衡（要用到前两样的全部成果）。

月末要能达到：

- 以可控速度驱动电机，说清 PWM 占空比与实际转速的区别
- 读取编码器并闭合位置环路
- 不看教程、根据数据手册连接并读取 I2C 传感器
- 把加速度计和陀螺仪数据融合成稳定角度估计
- 解释 P、I、D 各自的作用，描述调它们时机器人怎么变
- GitHub 上摆出两个能跑的机器人（接线图、代码、故障说明）
