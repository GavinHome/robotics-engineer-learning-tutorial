## 一、目标

读取距离数据，理解**时序通信**（Day 18 的 I2C 是它的升级版）。

前面 Day 8~14 用的都是**电平**通信：GPIO 输出高就是高、ADC 读到一个电压值。超声波不一样 —— 它把"距离"编码成**一个脉冲的宽度**。这是第一次遇到"信息藏在时间里"的通信方式。

---

## 二、HC-SR04 原理

### 四个引脚

| 引脚 | 方向 | 作用 |
|------|------|------|
| VCC | 电源 | 宽电压版 3~5.5V；普通版只能 5V |
| GND | 电源 | 必须与 ESP32 共地 |
| **Trig** | 输入（ESP32 → 模块） | 收到一个 **≥10μs 的高电平**，模块就发射超声波 |
| **Echo** | 输出（模块 → ESP32） | 发射后拉高，**收到回波时拉低**；高电平宽度 = 声波往返时间 |

### 时序图（关键）

```
ESP32          HC-SR04
  │               │
  │  Trig ── 10μs 高脉冲 ──▶│
  │               │
  │               │ 内部发出 8 个 40kHz 方波（人耳听不见）
  │               │
  │◀── Echo 高电平 ──┤
  │   （宽度 = 声波从发出到返回的时间）
  │               │
```

```
Trig  ──────┐          ┌────────────────────────
            │  10μs    │
            └──────────┘
                       模块发射 8×40kHz 脉冲
Echo  ──────────────┐                    ┌──────
                    │  宽度 = 往返时间    │
                    └────────────────────┘
                    ←────── duration ────→
```

**绘制版**：[`时序图.png`](./时序图.png)（2026-09-19，实测平台 ESP32-S3 · Trig=GPIO4 · Echo=GPIO5 · VCC=3V3）

### 换算公式

```
距离 cm = duration(μs) ÷ 58
        = duration(μs) × 0.0343 ÷ 2
```

**0.0343 是哪来的**：声速 343 m/s = 34300 cm/s = **0.0343 cm/μs**。
**为什么除以 2**：脉冲走了个来回（去 + 回），单程才是距离。

反过来记更快：**58μs ≈ 1cm**（1 ÷ 0.01715 ≈ 58.3）。

### 量程与限制

| 参数 | 值 |
|------|-----|
| 标称量程 | 2 ~ 400cm |
| 探测锥角 | 约 15°（**不是一条直线**） |
| 测量周期 | 建议 ≥60ms |
| 400cm 对应的 Echo 宽度 | 400 × 58 = **23.3ms** |

⚠️ **锥角 15° 这个数字 Day 20/21 会用到**：超声波装死在车头只能看到正前方一条窄带，所以才要配 SG90 舵机左右扫。

## 三、接线

### 原理图

```
        HC-SR04                    ESP32-S3
   ┌──────────────┐          ┌──────────────────┐
   │              │          │                  │
   │  VCC    ●────┼──────────┼── 3V3（任一脚）  │
   │  Trig   ●────┼──────────┼── GPIO4          │
   │  Echo   ●────┼──────────┼── GPIO5（直连）  │
   │  GND    ●────┼──────────┼── GND            │
   │              │          │                  │
   │  ▮▮ 发射器   │          │  板载 RGB: GPIO48│
   │  ▯▯ 接收器   │          └──────────────────┘
   └──────────────┘
```

### 接线表

| HC-SR04 | ESP32-S3 | 说明 |
|---------|----------|------|
| VCC | **3V3**（板上两个 3V3 任选其一） | 3V3 是板载 LDO 输出，**有驱动能力**；HC-SR04 宽电压版 3V 即可正常工作 |
| GND | GND | **必须共地**，否则信号没有参考电平 |
| Trig | **GPIO4** | 输出 |
| Echo | **GPIO5** | 输入，**直连**，不需要分压电阻 |

> **没沿用指南的 GPIO5/18**：指南原文写 Trig→GPIO5、Echo→GPIO18。这里改成 4/5 —— 两个脚在排针上相邻，走线整齐，也避开后续 I2C（Day 18 打算用 GPIO8/9）。要换脚只需改代码里两行常量。

### ⚠️ 为什么是 3V3，而不是 5Vin / 5V（本模块最大的坑）

用户看 `docs/ESP32-S3-Metric.pdf` 时提出质疑：图上标的是 **5Vin，没有 5V**。这个质疑是对的，直接改了接线方案。三条理由：

**① Metric.pdf 是尺寸图，不能用来判引脚功能**

那张 PDF 只有元器件位号（`PAU4024` / `PAJ102` / `COIN0OUT` / `PARGB01`）和机械尺寸（25.40mm / 27.94mm / 43.18mm）。对它 grep `5V` / `3V3` / `VIN` / `VCC` / `GND` / `VBUS` **零命中**。真正的网络名在原理图 `docs/ESP32-S3-SCH.pdf`：`VBUS` / `5V` / `3V3` / `VDD33` / `GND`。

**② `5Vin` 的 "in" 就是"输入"——它没有驱动能力**

这是电源**输入**脚（给板子供电的入口），不是稳压输出。**本项目自己在 Day 14 已经踩过这个坑**（`README.md` 踩坑记录原文）：

> **5Vin 引脚接上分压电路后读数变成 0**：5Vin 是电源**输入**引脚，不是稳压输出，没有驱动能力。万用表（10MΩ 输入阻抗）能测到 4.4V，但接 11kΩ 负载后电压直接塌到 0。修复：改用 3V3（板载 LDO 输出，有驱动能力）。

HC-SR04 发射瞬间峰值电流几十 mA，接在 5Vin 上会把整块板拉垮。

对照 `day-08/README.md` 的定义也只有这两个能用：

| 引脚 | 性质 | 能不能给 HC-SR04 供电 |
|------|------|----------------------|
| **3V3** | 板载 LDO **输出**（约 1A） | ✅ **就用它** |
| **5Vin** | 电源**输入** | ❌ 没有驱动能力，会塌压 |
| 5V（排针） | 通常直连 VBUS/USB | ⚠️ 理论可行，但见 ③ |

**③ 用 3V3 反而绕开了"5V 烧 IO"这个坑**

这是唯一额外收获。宽电压版 HC-SR04 的 **Echo 高电平跟随 VCC**：

| 供电方案 | Echo 电平 | 后果 |
|---------|----------|------|
| VCC → **3V3** | 3.3V | ✅ 直连 GPIO5 绝对安全，**连 1k+2k 分压都省了** |
| VCC → **5V** | 5V | ⚠️ 会烧 ESP32-S3 的 3.3V IO，必须加分压 |

也就是说：**选 3V3 一次性解决了"驱动能力"和"电平安全"两个问题**，代价只是发射功率略低（量程理论上稍短，实测 §六 会验证 3.3V 下能测到多远）。这正是采购时特意选宽电压 3-5.5V 版的意义 —— 省掉一整块电平转换电路。

> 📌 如果 §六 实测发现 3.3V 下远距离（>2m）读数不稳，再考虑换 5V 排针 + Echo 串 1kΩ/2kΩ 分压。**先别做**。

### 接线顺序（防烧）

```
接：先 GND → 再 Trig/Echo → 最后 VCC
拆：先 VCC → 再 Trig/Echo → 最后 GND
```

理由和 Day 14 数字电压表一样：ESP32 没上电时，GPIO 内部保护二极管可能把外部电压灌进芯片。**先把参考地接好，再接信号，最后接电源。**

## 四、代码要点

文件：[`实验1-超声波测距/实验1-超声波测距.ino`](./实验1-超声波测距/实验1-超声波测距.ino)

### 核心函数

```cpp
unsigned long measureOnce() {
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);          // 确保是干净的上升沿
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);         // 手册要求 ≥10μs
  digitalWrite(TRIG_PIN, LOW);

  return pulseIn(ECHO_PIN, HIGH, TIMEOUT_US);   // 阻塞等高电平，返回微秒数
}
```

**`pulseIn()` 是今天新学的函数**：阻塞等待指定引脚变成 HIGH，测量它保持 HIGH 多久，返回微秒数。**超时返回 0**（不是 -1），所以判断失败要写 `duration == 0`。

> ⚠️ `pulseIn()` 是**阻塞**的：超时 30ms 意味着最坏情况下你的 `loop()` 会卡住 30ms。对今天这种"只测距"的任务无所谓；Day 21 整车要同时跑电机 + 舵机 + 测距时，就得改成中断或非阻塞写法。记一笔。

### 三个细节

| 细节 | 为什么 |
|------|--------|
| 发脉冲前先 `LOW` 停 2μs | 保证 Trig 上是一个干净的上升沿，模块才认 |
| 两次测量间隔 ≥60ms（代码用 100ms） | 手册要求；间隔太短，上一次的余波会被下一次当成回波，读数乱跳 |
| 超时设 30ms | 400cm × 58μs = 23.2ms，留余量。设短了远距会误判成"超量程" |

### 灯色 = 距离档位（沿用 Day 14 的状态指示约定）

| 距离 | 灯色 | 串口 zone |
|------|------|-----------|
| < 2cm | 🔴 红 | `TOO_CLOSE`（低于标称下限，不可信） |
| 2 ~ 30cm | 🔴 红 | `NEAR` |
| 30 ~ 150cm | 🟠 橙 | `MID` |
| 150 ~ 400cm | 🟢 绿 | `FAR` |
| 超时 / 超量程 | 🔵 蓝 | `TIMEOUT` / `OUT_OF_RANGE` |

同样遵守 Day 14 踩过的坑：**枚举值不能叫 `LOW`/`HIGH`**，Arduino 核心已把它们定义成宏，所以叫 `D_NEAR`/`D_MID`/`D_FAR`/`D_INVALID`。

## 六、实测

### 第一轮（2026-09-19）：五档灯色 ✅ 全对 + 距离对照

| # | 场景 | 真实距离（尺子量） | 串口 cm | 误差 | 相对误差 | zone / 灯色 |
|---|------|------------------|---------|------|---------|------------|
| 1 | 手 | 6.7 | 6.5 | −0.2 | −3.0% | 🔴 NEAR ✅ |
| 2 | 书本 | 20.2 | 20.0 | −0.2 | −1.0% | 🔴 NEAR ✅ |
| 3 | 书本 | 50.1 | 50.0 | −0.1 | −0.2% | 🟠 MID ✅ |
| 4 | 远距离目标 | 174.0 | 173.0 | −1.0 | −0.6% | 🟢 FAR ✅ |
| 5 | **空旷（无遮挡）** | — | 0 | — | — | 🔵 TIMEOUT ✅ |

> ⚠️ 串口值由用户按 `%.1f` 输出口头报数，精度约 ±0.05cm；尺子读数约 ±0.2cm。
> 近距离档的相对误差（−3.0%）看着大，其实绝对量只有 0.2cm，在尺子分辨率以内。

**判读一：灯色档位全部命中** —— 对照代码阈值（`实验1-超声波测距.ino:104-113`）：

| 距离区间 | 代码判定 | 灯色 | 实测命中 |
|---------|---------|------|---------|
| `duration == 0` | TIMEOUT | 🔵 | 无遮挡 ✅ |
| `cm <= 30` | NEAR | 🔴 | 6.5、20.0 ✅ |
| `30 < cm <= 150` | MID | 🟠 | 50.0 ✅ |
| `150 < cm <= 400` | FAR | 🟢 | 173.0 ✅ |

**判读二：必须的对照组通过** —— 这是本轮最有价值的结论。Day 14 的方法论在这里生效：*"一直有读数"不等于"读数是对的"*。空旷时是 `TIMEOUT` 而不是某个假读数，**证明前 4 项测的是真回波，不是噪声或余波**。如果空旷处也报 20cm，前 4 项全部作废。

**判读三：读数系统性偏小 —— 本轮唯一的异常**

**四个点全部为负，没有一个是正的**，所以这不是随机跳动，是系统偏移。平均偏差 −0.375cm，最大 −1.0cm。

两个候选原因，方向一致，这份数据**分不开**：

| 候选 | 性质 | 预测量级 | 依据 |
|------|------|---------|------|
| ① 温度（比例项） | 读数 ∝ 真值 | 约 **−0.87%** | 代码按 343 m/s 算；室温 ~25℃ 实际约 346 m/s → 回波更早到 → `us` 更小 → 算出的 cm 更小 |
| ② 起算点（固定项） | 恒定差值 | 约 1~2mm | 声波从**换能器金属网面**出发，而尺子零点多半在它后面 |

证据倾向：近距离两档绝对量都是 −0.2cm（相对量却差 3 倍）→ 像固定项主导；174cm 档 −1.0cm ≈ 纯比例项预测（−1.5cm 同量级）。

> 📌 **⚠️ 修正一处自己讲错的方向**：上一版笔记曾写「室温声速比 343 快 → 读数偏**大**约 0.9%」。**方向讲反了**。正确推导：声速快 → 回波更早到 → `us` 更小 → `cm = us × 0.01715` 算出来**更小**。实测 174cm 处 −0.6%，与 −0.87% 的理论值方向和量级都对得上。

**要把两项分开，需要补一个远距离点（3~4m）**：那里比例项占绝对主导，固定项可忽略。

**判读四：3V3 供电方案成立** —— 173cm 仍能稳定读出且判定为绿，说明 3.3V 供电下量程足够，**不需要退回「5V + 1kΩ/2kΩ 分压」方案**。之前担心的"3.3V 发射功率不足"在这个距离范围内没造成问题。

> ✅ **2026-09-19 用户已确认：VCC 实际接的就是 3V3 排针**，本节结论成立。

### 为什么不动代码做补偿

Day 21 只用它判断「前方有没有障碍」，1cm 以内的偏差对阈值判定毫无影响。用一个**四舍五入过的 4 个点**拟合校准系数，精度撑不住它带来的复杂度。所以把它作为**已知系统偏差记录在案**，不修。

## 七、出了什么问题 & 怎么修（预判）

| 症状 | 原因 | 修复 |
|------|------|------|
| 一直 `TIMEOUT`（us=0） | ① Trig/Echo 接反 ② 没共地 ③ VCC 没接 | 逐根线核对；量 VCC-GND 间电压 |
| 读数一直是 0.0 但 us 有值 | 公式没写对 / 单位错 | `cm = us × 0.0343 / 2` |
| 读数固定偏大/偏小一个比例 | 声速随温度变（0℃ 331m/s、25℃ 346m/s） | 练手不用管；要准就加温度补偿 |
| 读数剧烈跳动 | 两次测量间隔太短 | 把 `CYCLE_MS` 从 100 调到 150 |
| 近距离（<5cm）乱跳 | 低于标称下限 2cm / 发射余波干扰 | 这是模块物理限制，不是 bug |
| 串口无任何输出 | 波特率不对 / 没选对 COM 口 | 115200 |
| 灯不亮 | 板载 RGB 是 GPIO48，与测距无关；`RgbCycle::begin()` 没调 | 检查 `setup()` |
