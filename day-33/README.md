# Day 33 — 五路 AO 合成一个"线在哪"的数

第 1 周第 3 天。昨天把一颗模块的三个数定死了：黑 4095（顶天花板）、白 ~1700、悬空 ~2550，高度定 3cm。今天把这颗变成五颗，回答一个新问题：**五个连续读数，怎么变成一个"线偏左还是偏右、偏了多少"的数。**

这件事今天不装车，在工作台上拿手横扫完成。控制律（Day 35–37）、丢线判定（Day 34）都还没上场，今天只要一件事立住：`pos` 必须从 −1000 平滑走到 +1000，中间不许回头、不许跳。

## 一、五路怎么摆

**模块不要插到面包板上。** 模块的两颗管子长在板子底面，眼睛就朝下；插上面包板，眼睛盯的是面包板底面，纸在更下面对不上。面包板在今天一件正事都没有——VCC/GND 靠级联解决，五根 AO 直接接 ESP32。

### 摆法：模块在上不动，纸在下动

眼睛必须朝着纸。管子长在板子底面，所以**模块得在纸的上面、眼睛朝下**：

1. 五块模块**有元件的那一面贴牢在同一块平板的下表面**（眼睛朝下），排成一排，**相邻两颗管子的中心距 1.5cm**——拿尺量管子中心，不是量板子边。
2. 五块朝向一致，四针脚朝同一侧。管子偏在长边的一头，有一块转了个方向，它的眼睛就比别的偏出 2cm 以上。
3. 胶带把五块固定在平板下表面，别让它们在推纸的时候滑动。
4. 平板架起来，让**灯珠最低点离桌面 3cm**：拿三本一样厚的书垫在数组**左右两端的外侧**，别压住纸要走的路。量的是灯珠的下边缘，不是板子到桌面——光从灯珠出来、回到灯珠，板子多厚不参与反射。灯珠要是陷在板子的开孔里，板子贴 3cm 时它其实更高。
5. 测试纸**平铺在桌面上**，从平板和桌面之间推过去，横扫整排。

为什么纸动而不是模块动：五块的高度被同一块平板锁死，一毫米都不会变；纸上有刻度，推到哪一格就是哪一格，直接对应 `pos` 该是多少。手悬空抬着模块扫，高度和速度都在抖。

上机时同一套模块、同一张白纸，只因为手持的高度在变，五路 raw 的差就跟着变：

| 摆法 | 五路 raw | 最大/最小 |
|---|---|---|
| 手持悬空 | 1043 297 227 857 933 | 4.6× |
| 手持悬空（换了个角度） | 1355 688 292 1445 1768 | 6.1× |
| 垫到接近 3cm | 1189 1043 904 867 1419 | 1.6× |

三次里"谁高谁低"的顺序都不同——**不是某颗模块固定偏，是高度在变**。1.6× 那一行的 552 个码折合高度约 0.7cm，剩下的这点差不影响今天：逐路标定把每颗的白底各自记下，归一化又除掉各自的量程，两端（白=0、黑=1）都锚死了，质心不受基线差影响。真正要盯的是曲线本身——中间出平台、某一格 `pos` 跳，再回头查那一颗。

- **0 号在最左。** 站在桌子前方、朝模块看过去，最靠左那颗是 0 号，往右依次 1、2、3、4。**顺序是这套东西的符号基准**：反了的话 `pos` 整周反着来，Day 35 的"哪偏哪纠"会全拧。

### 脚位是怎么挑出来的

**ESP32-S3 上能读模拟量的只有 GPIO1~10（ADC1）和 GPIO11~20（ADC2）两段**，GPIO21 以上一颗 ADC 通道都没有。35~42 是 JTAG（39~42）、彩灯（38）、PSRAM（35~37）的地盘，GPIO46 也一样不是 ADC 脚——`analogRead()` 读出来全是废数。所以候选只有这 20 个。

按小车现有接线（[`day-24/智能小车接线图.png`](../day-24/智能小车接线图.png)）已占的是：GPIO4/5 = 超声波，GPIO10/11/12/15/16/17 = TB6612，GPIO48 = 板载彩灯。剩下的 ADC 脚里取 **6/7/8/2/3**：6/7/8 是从没用过的空脚，2/3 是拆掉 Day 31 的按键 + LED 腾出来的。**五路全在 ADC1 上。**

为什么要全挑 ADC1：ADC2 和 Wi-Fi 的 RF 共用模拟前端，Wi-Fi 一忙就读不出来。今天 USB 供电、不开 Wi-Fi，本来用 ADC2 也没事；但五路全落 ADC1，以后把遥控（Day 27/28）和循线写进同一个固件，一根脚都不用挪。

一条要记住：

- **GPIO8/9 是留给 MPU-6050 的 I2C 脚**（第 2 周姿态融合用）。今天 IMU 没插，所以 GPIO8 是空的；等第 2 周上 IMU 时这一路要拔下来让位。注意必须是"把 MPU 模块从排针上拔掉"——那两块 4.7kΩ 上拉在模块板上，光是"不用它"没用，上拉会一直把 AO 读数钉在高位。

### 拆什么、留什么

| 处理 | 东西 |
|---|---|
| 拆 | Day 31 的按键 + 1kΩ + 外接 LED（GPIO1 / GPIO2）——那个实验已经做完了，拆下来的 GPIO2/3 今天给 #3/#4 用 |
| 留 | HC-SR04、SG90 舵机、电位器、板载彩灯（GPIO48，今天当状态灯）、MPU-6050（本周不插） |

### 线太多：VCC / GND 级联

二十根线听着多，要接到 ESP32 上的其实只有七根。**VCC 和 GND 在模块之间级联**——每块模块的 VCC 接下一块的 VCC、GND 接下一块的 GND，一路串到末块，最后只出一根 VCC 和一根 GND。五块 TCRT5000 一共不到 30mA，级联的压降可以不管。

```
ESP32 3V3   ─┬─ 模块0 ─ 模块1 ─ 模块2 ─ 模块3 ─ 模块4
ESP32 GND   ─┴─ 模块0 ─ 模块1 ─ 模块2 ─ 模块3 ─ 模块4
ESP32 GPIO6 ───── 模块0 AO
ESP32 GPIO7 ───── 模块1 AO
ESP32 GPIO8 ───── 模块2 AO
ESP32 GPIO2 ───── 模块3 AO
ESP32 GPIO3 ───── 模块4 AO
```

躲不掉的只有那五根 AO——五路就是五个独立的数，没有合并的余地。级联之后面包板也可以不用了。

### 归一化这一步不能省

指南给的是 `pos = Σ(weight_i × value_i) / Σ(value_i)`。中间的 `value_i` 该填什么，昨天已经给出答案的一半：黑恒 4095、五路的差别全在白底。于是

```
n_i = (raw_i − white_i) / (4095 − white_i)        # 取值 0 ~ 1
pos = Σ(w_i × n_i) / Σ(n_i) × 500                 # w = −2/−1/0/+1/+2，归一到 ±1000
```

**为什么不直接拿 `raw_i − white_i` 当 value：** 昨天的表里，各路的白底不一样（模块体制有差、高度有差），于是各路"黑白差"也不一样。直接相减，量程大的那路在质心里说话更响，线明明在正中间，读数会被它拽偏。除掉各自的量程，五路才等价。

黑侧因此不用单独标定——昨天三次实测全顶在 4095，量程 `4095 − white_i` 直接由它自己的白底推出来。**逐个标定在白底这一侧才有意义。**

### 看不见线怎么办

`Σ(n_i) < 0.5` 就当没看见线，`pos` 保持上一帧的值。0.5 的单位是"等效压线传感器个数"：五路全白时接近 0，一路压线大约 0.6~1.0。这个数只是让 `pos` 今天不抽风，完整的丢线判定、丢线多久停车，是 Day 34 的事。

### 彩灯

绿=等标定或线居中、白=没看见线、红=偏左、蓝=偏右。±100 个码的死区（约 3mm）以内算居中，免得灯一直闪。

## 四、上机步骤

没有纯黑纸也能测：打印 A4 测试纸，黑区是印上去的黑，白区就是标定基准。文件在 [`五路测试纸-A4.pdf`](./五路测试纸-A4.pdf)（源文件 [`五路测试纸-A4.svg`](./五路测试纸-A4.svg)），打印时选 **A4 / 缩放 100% / 边距"无" / 关掉"适应页面"**——一缩放，1.5cm 的格子就不是 1.5cm 了，整张表的答案全作废。

纸上四块，从上往下：

- **① 白底标定区**：一片故意不带格子的纯白，`c` 就在这里按。
- **② 全宽黑块**：198mm 宽，保证同时盖住整排五路，用来看黑是不是真的顶到 4095。
- **③ 阵列位置图**：标出五路各自在纸的横向上落在哪里（宽 60mm，2 号在中点）。
- **④ 九格扫场带**：每格带里只有一根 8mm 黑条，从左到右依次错开 −45 / −30 / −15 / −7.5 / 0 / +7.5 / +15 / +30 / +45 mm。纸上下推，阵列这条横线每次只扫过一根黑条，所以九格带给出九个已知答案。

步骤：

1. 接线上电前万用表通断档确认五路 VCC/GND 没短路，**且确认 0 号在最左**。
2. 烧录，打开串口监视器（115200）。桌面铺一张**纯白纸**或测试纸的 ① 区（别用裸桌面——桌面有纹路、有色差，不是可信的基准），五路 raw 应该都停在同一个数附近。**哪一路不动**，就是脚位或接线的问题；**五路差出好几倍**（>2×）是高度没弄平；**差几百**是模块体质差，逐路标定会处理掉，不用管。
3. 拿尺子竖直插在桌面，逐颗量灯珠下边缘到纸面的距离，五颗都得是 3cm。差 1cm 就能让 raw 差出 4 倍（Day 32 的高度曲线：白底 2cm=527、3cm=1499、4cm=2145），所以这一步不能靠眼睛。
4. 把测试纸平铺在桌面、从模块板下推进来，纸停在**① 白底标定区**，按 `c` 标定白底（约 1 秒，别动别挡光）。把打印出来的五路白底抄进下表。
5. 推纸到**② 全宽黑块**，五路 raw 应该全是 4095；顺手按 `w` 核对白底表。哪一路不是 4095，先查那一路的焊点和高度。
6. 推纸到**④ 的"0（正中）"那一格**，左右微调纸的位置，直到 `pos` 读出 0 附近、彩灯转绿——这时 2 号对上了纸的中线。**从此别再动左右**，只上下推。
7. 按 `p` 开曲线模式，从下到上一格格推纸，每格停 1 秒，把 `pos` 抄进下表。格与格之间彩灯会闪白（丢线），正常。
8. 两端那两格（±45mm）黑条已经出了数组，看它是丢线还是勉强读数——这个边界就是 Day 34 丢线判定的尺度。
9. 用串口绘图器再看一遍整条横扫过程。

### 要落地的四个结论

1. **`pos` 单调吗**：从左到右一路不减（或一路不增），中间不许回头。回头 = 权重的符号或 0 号的位置搞错了。
2. **一格等于多少个码**：相邻两路之间 pos 差多少？接近 500 说明五路权重正确；偏差大说明某路量程或高度不对。
3. **丢线区多宽**：线中心离开数组多远 `Σn` 才掉到 0.5 以下？这个宽度就是 Day 34 丢线判定的尺度。
4. **斜率线性吗**：中间段应该近似一条直线，两端压平。中间有平台 = 某两颗模块之间的间距和别处不一样。

## 六、与《逐日指南》的出入

| 指南 | 实际 | 为什么 |
|---|---|---|
| "各自标定黑白阈值" | 只标白底 | Day 32 实测黑恒 4095，五路没有可标的差别；二值阈值留给 Day 34 |
| `pos = Σ(w·v)/Σ(v)` | 先归一化 `n_i` 再质心 | 直接减白底会让"黑白差大"的那路说话更响，质心被它拽偏 |
| "间距 ≤ 线宽" | 定 1.5cm，量眼睛到眼睛 | 模块板子是长条的，板心不在两只眼睛中间，按板边量会歪 |
| 引脚没指定 | 挑出 GPIO6/7/8/2/3 | 能读模拟量的只有 GPIO1~10 / 11~20；35~42、46 没有 ADC，读出来是废数。按小车现有接线（day-24 图）取没占的脚，且全落在 ADC1 上（ADC2 和 Wi-Fi 抢模拟前端） |
