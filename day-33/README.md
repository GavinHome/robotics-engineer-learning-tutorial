# Day 33 — 五路 AO 合成一个"线在哪"的数

第 1 周第 3 天。昨天把一颗模块的三个数定死了：黑 4095（顶天花板）、白 ~1700、悬空 ~2550，高度定 3cm。今天把这颗变成五颗，回答一个新问题：**五个连续读数，怎么变成一个"线偏左还是偏右、偏了多少"的数。**

这件事今天不装车，在工作台上拿手横扫完成。控制律（Day 35–37）、丢线判定（Day 34）都还没上场，今天只要一件事立住：`pos` 必须从 −1000 平滑走到 +1000，中间不许回头、不许跳。

## 一、五路怎么摆

**模块不要插到面包板上。** 模块的两颗管子长在板子底面，眼睛就朝下；插上面包板，眼睛盯的是面包板底面，纸在更下面对不上。面包板在今天一件正事都没有——VCC/GND 靠级联解决，五根 AO 直接接 ESP32。

### 摆法：模块在上不动，纸在下动

眼睛必须朝着纸。管子长在板子底面，所以**模块得在纸的上面、眼睛朝下**：

1. 五块模块**有元件的那一面贴牢在同一块平板的下表面**（眼睛朝下），排成一排，**相邻两颗管子的中心距 1.5cm**——拿尺量管子中心，不是量板子边。五块并起来，**最左一块的左沿到最右一块的右沿约 7.5cm**（5 × 1.4cm 板身 + 4 道约 1mm 的板缝），测试纸的定位版就是按这个外沿对齐的。
2. 五块朝向一致，四针脚朝同一侧。管子偏在长边的一头，有一块转了个方向，它的眼睛就比别的偏出 2cm 以上。
3. 胶带把五块固定在平板下表面，别让它们在推纸的时候滑动。
4. 平板架起来，让**灯珠最低点离桌面 3cm**：拿三本一样厚的书垫在数组**左右两端的外侧**，别压住纸要走的路。量的是灯珠的下边缘，不是板子到桌面——光从灯珠出来、回到灯珠，板子多厚不参与反射。灯珠要是陷在板子的开孔里，板子贴 3cm 时它其实更高。
5. 测试纸**平铺在桌面上**，从平板和桌面之间推过去，横扫整排。

为什么纸动而不是模块动：五块的高度被同一块平板锁死，一毫米都不会变；纸上有刻度，推到哪一格就是哪一格，直接对应 `pos` 该是多少。手悬空抬着模块扫，高度和速度都在抖。

上机时同一套模块、同一张白纸，只因为手持的高度在变，五路 raw 的差就跟着变：

| 摆法 | 五路 raw | 最大/最小 |
|---|---|---|
| 手持悬空 | 1043 297 227 857 933 | 4.6× |
| 手持悬空（换了个角度） | 1355 688 292 1445 1768 | 6.1× |
| 垫到接近 3cm | 1189 1043 904 867 1419 | 1.6× |

三次里"谁高谁低"的顺序都不同——**不是某颗模块固定偏，是高度在变**。1.6× 那一行的 552 个码折合高度约 0.7cm，剩下的这点差不影响今天：逐路标定把每颗的白底各自记下，归一化又除掉各自的量程，两端（白=0、黑=1）都锚死了，质心不受基线差影响。真正要盯的是曲线本身——中间出平台、某一格 `pos` 跳，再回头查那一颗。

- **0 号在最左。** 站在桌子前方、朝模块看过去，最靠左那颗是 0 号，往右依次 1、2、3、4。**顺序是这套东西的符号基准**：反了的话 `pos` 整周反着来，Day 35 的"哪偏哪纠"会全拧。

### 间距必须是 1.5cm，不是"看着差不多"

相邻两颗管子中心距定 **1.5cm**，这是三张测试纸的刻度基准。量的是**两只红外灯的中心到中心**，不是板子边到板子边、也不是挡板到挡板——模块是长条的，管子偏在板子的一头，按板边量必然歪出 2cm 以上。

**摆成 3cm 会怎样：** `pos` 的刻度"一格 = 500"照样成立（那是五路的**序号**，不是毫米），但纸上印的 mm 数字全废了。更要命的是 ±7.5mm 那两个半格站：1.5cm 间距下 8mm 黑条能同时压住两颗管子，才读出 ±250；3cm 间距下黑条只碰得到一颗，`pos` 就只剩 0 / ±500 / ±1000 三档，半格点直接测不出来。

**3cm 大概率是摆向错了。** 模块板是长条的（带电位器那头更宽），长边顺着阵列排，每颗要吃掉近 3cm。**把每块模块转 90°：让长边（电位器那一头）垂直于阵列**，排进阵列的就只剩灯珠那头的约 1.4cm，15mm 轻松做到。转完再看一次朝向是否一致——有一块转反，它的眼睛会比别的偏出去。

**转对了也还可能摆成 3cm——按板边留缝。** 灯珠那一头的板身只有约 1.4cm，所以管心 1.5cm 意味着**板边贴着板边**（最多留 1mm）；板子之间留出 1.5cm 的缝，管心距就变成 3cm。贴完拿尺量**管子中心**：第 1 颗到第 5 颗应该是 60mm，量出 12cm 就是缝留大了。整组模块因此只有 7cm 多宽——① 白底区和 ② 黑块就是按这个宽度印的（定位版 75mm、竖版 198mm）；阵列宽一倍的话，按 `c` 时最外两颗压在桌面或纸边上，白底表从第一步就错，后面九个 `pos` 之间不可比。

### 脚位是怎么挑出来的

**ESP32-S3 上能读模拟量的只有 GPIO1~10（ADC1）和 GPIO11~20（ADC2）两段**，GPIO21 以上一颗 ADC 通道都没有。35~42 是 JTAG（39~42）、彩灯（38）、PSRAM（35~37）的地盘，GPIO46 也一样不是 ADC 脚——`analogRead()` 读出来全是废数。所以候选只有这 20 个。

按小车现有接线（[`day-24/智能小车接线图.png`](../day-24/智能小车接线图.png)）已占的是：GPIO4/5 = 超声波，GPIO10/11/12/15/16/17 = TB6612，GPIO48 = 板载彩灯。剩下的 ADC 脚里取 **6/7/8/2/3**：6/7/8 是从没用过的空脚，2/3 是拆掉 Day 31 的按键 + LED 腾出来的。**五路全在 ADC1 上。**

为什么要全挑 ADC1：ADC2 和 Wi-Fi 的 RF 共用模拟前端，Wi-Fi 一忙就读不出来。今天 USB 供电、不开 Wi-Fi，本来用 ADC2 也没事；但五路全落 ADC1，以后把遥控（Day 27/28）和循线写进同一个固件，一根脚都不用挪。

一条要记住：

- **GPIO8/9 是留给 MPU-6050 的 I2C 脚**（第 2 周姿态融合用）。今天 IMU 没插，所以 GPIO8 是空的；等第 2 周上 IMU 时这一路要拔下来让位。注意必须是"把 MPU 模块从排针上拔掉"——那两块 4.7kΩ 上拉在模块板上，光是"不用它"没用，上拉会一直把 AO 读数钉在高位。

### 拆什么、留什么

| 处理 | 东西 |
|---|---|
| 拆 | Day 31 的按键 + 1kΩ + 外接 LED（GPIO1 / GPIO2）——那个实验已经做完了，拆下来的 GPIO2/3 今天给 #3/#4 用 |
| 留 | HC-SR04、SG90 舵机、电位器、板载彩灯（GPIO48，今天当状态灯）、MPU-6050（本周不插） |

### 线太多：VCC / GND 级联

二十根线听着多，要接到 ESP32 上的其实只有七根。**VCC 和 GND 在模块之间级联**——每块模块的 VCC 接下一块的 VCC、GND 接下一块的 GND，一路串到末块，最后只出一根 VCC 和一根 GND。五块 TCRT5000 一共不到 30mA，级联的压降可以不管。

```
ESP32 3V3   ─┬─ 模块0 ─ 模块1 ─ 模块2 ─ 模块3 ─ 模块4
ESP32 GND   ─┴─ 模块0 ─ 模块1 ─ 模块2 ─ 模块3 ─ 模块4
ESP32 GPIO6 ───── 模块0 AO
ESP32 GPIO7 ───── 模块1 AO
ESP32 GPIO8 ───── 模块2 AO
ESP32 GPIO2 ───── 模块3 AO
ESP32 GPIO3 ───── 模块4 AO
```

躲不掉的只有那五根 AO——五路就是五个独立的数，没有合并的余地。级联之后面包板也可以不用了。

### 归一化这一步不能省

指南给的是 `pos = Σ(weight_i × value_i) / Σ(value_i)`。中间的 `value_i` 该填什么，昨天已经给出答案的一半：五路的差别主要在白底。于是

```
n_i = (raw_i − white_i) / (black_i − white_i)     # 取值 0 ~ 1
pos = Σ(w_i × n_i) / Σ(n_i) × 500                 # w = −2/−1/0/+1/+2，归一到 ±1000
```

**为什么不直接拿 `raw_i − white_i` 当 value：** 昨天的表里，各路的白底不一样（模块体制有差、高度有差），于是各路"黑白差"也不一样。直接相减，量程大的那路在质心里说话更响，线明明在正中间，读数会被它拽偏。除掉各自的量程，五路才等价。

昨天因此只标白底——黑胶带三次实测全顶在 4095，黑侧五路一模一样、没有可标的东西，量程直接由白底推出来。**但这条只对黑胶带成立**：喷墨打印的黑吸红外远不如胶带，实测只到 3000 出头，而且五路还差出几百码，黑侧也有可标的差别了。所以今天黑也逐路标（按 `b`），量程用 `black_i − white_i`。判据很简单：**贴上去能不能顶到 4095**，能就还按昨天的办法只标白，不能就黑白都标。

### 看不见线怎么办

`Σ(n_i) < 0.5` 就当没看见线，`pos` 保持上一帧的值。0.5 的单位是"等效压线传感器个数"：五路全白时接近 0，一路压线大约 0.6~1.0。这个数只是让 `pos` 今天不抽风，完整的丢线判定、丢线多久停车，是 Day 34 的事。

### 彩灯

绿=等标定或线居中、白=没看见线、红=偏左、蓝=偏右。±100 个码的死区（约 3mm）以内算居中，免得灯一直闪。

### 纸往哪边推：阵列的长边必须和移动方向垂直

九格带能成立，全靠阵列这条 60mm 的横线**每次只扫过一根黑条**。所以纸必须**上下**推。改成左右推，60mm 的阵列会同时盖住三根黑条（格带间距只有 20mm），五路读到的是 `[0,1,1,1,0]` 这种混合值，九格带全部作废——只有正中对上那一格碰巧也读出 0，其余八格全是错的。

只能左右推的话（比如模块架起来、纸上下推会撞书），把模块转 90° 排成**竖直一列**：[`五路测试纸-A4-横移.pdf`](./五路测试纸-A4-横移.pdf)（源文件 [`五路测试纸-A4-横移.svg`](./五路测试纸-A4-横移.svg)）就是给这种摆法用的。九格带沿横向排，每格黑条的**上下**偏移编码线的位置，打印设置和答案表都不变。阵列仍保持横排又想左右推，九格带没有意义，只能印一根黑条加纸边刻度、拿尺子读偏移。

### 纸推不动：定位版

模块架在桌上、纸上下左右都只剩一两厘米行程时，前两张都用不上。但还有个方向没用到——**转**。模块连垫子一起钉在桌上不动，只把纸在桌面转：[`五路测试纸-A4-定位版.pdf`](./五路测试纸-A4-定位版.pdf)（A4 横放 297×210）印了 7 个站位，沿纸边走一圈，每换一边纸朝同一个方向转 90°、让印好的框正对阵列，读一次 `pos`。七站的答案和另两张完全一样（一格 = 500），只是"线在纸上动"换成了"纸在线下转"。

**为什么非要转：** 七个站位摊开 −45 ~ +45 mm，阵列扫完全程要挪将近 90mm，手上那点行程连一站都过不去。但把这 90mm 摊到纸的四条边上，每边只剩一两站的量，转 90° 就够——所以纸不用钉死，模块也不用搬。

### 对齐按板子，不按灯

灯朝下，转纸的时候根本看不见它，所以**每条虚线框就是五块板子的外沿（75mm）**：板子并成一排是 5 × 1.4cm = 7cm，加上板缝约 0.5cm，合起来 7.5cm。把**最左一块的左沿**贴到框的左端、**最右一块的右沿**贴到框的右端，五颗管子就自己落在框里那 5 条刻度上（刻度距框沿 7.5mm，相邻两条 15mm）。框的两端印了"板沿"两个字，对的就是那两条边。

这么对齐有三个好处：不用找灯；顺手验了间距——**框要是塞不进你的板子，就是板缝留大了**（管心距会从 15mm 变成 30mm）；纸稍微转歪一点也不怕，只要两条板沿各自贴住。

管心距量成 15.25mm 没关系：末端只差半毫米，答案照样对。

**七个站位沿纸边怎么排**（不是一排七站，是两条长边各三个 + 两条短边各一件）：

| 位置 | 站位 |
|---|---|
| 上排长边（左到右） | −45 / −30 / −15 |
| 下排长边（左到右） | +15 / +30 / +45 |
| 右短边 | 第 9 站：0 正中（竖站，转 90° 后正对阵列） |
| 左短边 | ① 白底标定区、② 全宽黑块（两条并排竖条） |

一条长边只放得下三个 75mm 的框：挨太近，黑条会伸进隔壁的阵列框。±45mm 两站偏移比阵列半宽（37.5mm）还大，黑条整根跑到框外，所以 −45 占上排最左、+45 占下排最右，各留足空地——它就是丢线判定的尺度。

±250 两个半格点纸上没印（长边放不下第九个框）。要测就把纸沿阵列方向平移 7.5mm——半个间距，板沿离开框沿半个刻度。

① ② 和第 9 站都**顺着短边**印成竖条，沿阵列方向都是 75mm，和长边的框同一个对齐基准。短边只有 210mm，两条 75mm 的竖条上下叠会放不下，所以 ① ② 改成左右并排：① 紧贴纸边，② 往里挪 30mm。把纸转 90°，竖条就变成横条正对整排五颗，模块一步都不用动。② 往里那点没关系——白底表只按一次。第 9 站同理贴在右短边（离边 7mm），转过来就是一行横站，刻度从上到下 = #0 → #4。

① ② 只有 24mm 深，板子在**深度**方向会探出一截，这没关系——要的是五颗管子都压在那片白/黑里，不是整块板都在。七个站位的框也一样：框只管沿阵列方向那 75mm，深度方向随便。

每个站位的偏移量、对应 `pos`、该亮的灯，都印在它自己框的旁边——**不用对表，站在哪一站，答案就在那站脚底下。**

这么做只有一个硬前提：**阵列离纸面一直 3cm**。转纸时别碰模块；白底 3 分钟能漂 250 个码，漂了七个 `pos` 之间不可比。

步骤（前三步三张纸通用，后面按纸的用法分两种）：

1. 接线上电前万用表通断档确认五路 VCC/GND 没短路，**且确认 0 号在最左**。
2. 烧录，打开串口监视器（115200）。桌面铺一张**纯白纸**或测试纸的 ① 区（别用裸桌面——桌面有纹路、有色差，不是可信的基准），五路 raw 应该都停在同一个数附近。**哪一路不动**，就是脚位或接线的问题；**五路差出好几倍**（>2×）是高度没弄平；**差几百**是模块体质差，逐路标定会处理掉，不用管。
3. 拿尺子竖直插在桌面，逐颗量灯珠下边缘到纸面的距离，五颗都得是 3cm。差 1cm 就能让 raw 差出 4 倍（Day 32 的高度曲线：白底 2cm=527、3cm=1499、4cm=2145），所以这一步不能靠眼睛。

**A. 推纸的两种（竖版 / 横移版）**

4. 把测试纸平铺在桌面、从模块板下推进来，纸停在**① 白底标定区**，按 `c` 标定白底（约 1 秒，别动别挡光）。把打印出来的五路白底抄进下表。
5. 推纸到**② 全宽黑块**，五路 raw 应该全是 4095；顺手按 `w` 核对白底表。哪一路不是 4095，先查那一路的焊点和高度。
6. 推到**④ 的"0（正中）"那一格**，微调纸的位置，直到 `pos` 读出 0 附近、彩灯转绿——这时 2 号对上了纸的中线。
7. 按 `p` 开曲线模式，沿移动方向一格一格推，每格停 1 秒，把 `pos` 抄进下表。格与格之间彩灯会闪白（丢线），正常。
8. 两端那两格（±45mm）黑条已经出了数组，看它是丢线还是勉强读数——这个边界就是 Day 34 丢线判定的尺度。
9. 用串口绘图器再看一遍整条横扫过程。

**B. 定位版（模块不动，转纸）**

4. 先在纸上认准 ① ② 和七个站位。把纸摆到**上排长边**正对阵列，从最左一站开始，**把五块板子的外沿贴到虚线框两端的"板沿"上**（最左块的左沿贴框左端、最右块的右沿贴框右端），**别动、别抬**，读一次 `pos`。板子塞不进框 = 板缝留大了，回去重贴。
5. 上排三站从左到右读完，把纸朝**同一个方向**转 90°——转过来是左短边的 ① ②。板沿贴住 ① 的框（五颗全压白），按 `c` 标定白底；再沿垂直阵列的方向把纸往里滑 30mm，板沿贴住 ② 的框，按 `b` 标定黑底。标完按 `w`，白底、黑底、量程三列一起打出来。七站里就这一步要推纸，而且只推一次（黑白表各按一次）。
6. 再朝同一个方向转 90°，读下排三站（左到右）；再转 90°，读右短边的第 9 站。第 9 站的刻度从上到下是 #0 → #4。七站全读完抄进下表，**答案印在每个站位的框旁**，不用另找表。
7. 每换两三个站位，回 ① 区按 `w` 核对——白底 3 分钟能漂 250 个码，漂了就该重按 `c`，黑底跟着重按 `b`。重新上电、换纸、改高度，两张表都要重按。
8. 下排如果推不进去（纸要穿到模块另一头），把纸旋转 180° 再读——**此时读到的 `pos` 符号是反的，填表时取反**，丢线不变。

## 五、测试结果

### 黑白标定（① 区按 `c`，② 区按 `b`）

| 路 | 引脚 | 白底 raw | 黑底 raw | 量程 黑−白 |
|---|---|---|---|---|
| 0 | GPIO6 | 1672 | 3802 | 2130 |
| 1 | GPIO7 | 1526 | 3775 | 2249 |
| 2 | GPIO8 | 1497 | 3782 | 2285 |
| 3 | GPIO2 | 1448 | 3786 | 2338 |
| 4 | GPIO3 | 1425 | 3719 | 2294 |

黑底五路只差 83 码、白底五路差 247 码，量程 2130~2338——都在"差几百"的体质档里，归一化之后五路等价。

### pos 标定曲线

黑条中心相对 2 号（阵列中点）的偏移，正 = 偏右。七行对应测试纸 ④ 的站位（定位版印了这七个；推纸的两种是九格带，多出 ±7.5mm 两个半格点）：

| 偏移 | 黑条压在哪 | 预期 pos | 实测 pos |
|---|---|---|---|
| −45 mm（−3 格） | 0 号再往外 15mm | 可能丢线 | 丢线 |
| −30 mm（−2 格） | 0 号 | ≈ −1000 | **−910** |
| −15 mm（−1 格） | 1 号 | ≈ −500 | **−512** |
| 0 | 2 号（正中） | ≈ 0 | **0** |
| +15 mm（+1 格） | 3 号 | ≈ +500 | **+541** |
| +30 mm（+2 格） | 4 号 | ≈ +1000 | **+952** |
| +45 mm（+3 格） | 4 号再往外 15mm | 可能丢线 | 丢线 |
| ±7.5 mm（±½ 格） | 1 号与 2 号之间 / 2 号与 3 号之间 | ≈ ±250 | 定位版没印，要测就把纸沿阵列方向平移半个间距 |
| ±3.75 mm（±¼ 格） | 更细的点 | ≈ ±125 | 推纸的两种停在两条 15mm 格线正中间 |

### 要落地的结论

1. **`pos` 单调吗**：单调，一路不减——丢线 → −910 → −512 → 0 → +541 → +952 → 丢线，中间没有回头。权重符号和"0 号在最左"都是对的。
2. **一格等于多少个码**：中间三格 512 / 541，贴近 500；最外两格只有 398 / 411，小了五分之一。原因是最外两格黑条贴在阵列边缘，8mm 的条会漏到内邻那颗管子上（−30 站的条边缘离 1 号中心 11mm），质心被往中间拽；±15 和 0 站漏光左右对称，不产生偏差，所以读数准。
3. **丢线区多宽**：±30mm（黑条正在最外一颗管子上）还能读数，±45mm（黑条在最外那颗再往外 7.5mm）丢线。边界落在"阵列最外一颗"到"再往外 7.5mm"之间，Day 34 设阈值就查这一段。
4. **斜率线性吗**：中间三段近似一条直线（每格 ~520 码），最外两格压平到 ~400 码。中间没有平台，说明五颗管子的间距一致。
5. **左右对称吗**：−910 / +952 差 42 码，−512 / +541 差 29 码。差出几百才是五路高度或接线有问题。

## 六、与《逐日指南》的出入

| 指南 | 实际 | 为什么 |
|---|---|---|
| "各自标定黑白阈值" | 白底黑底都逐路标 | Day 32 实测黑恒 4095 是对**黑胶带**成立的；喷墨打印的黑吸红外远不如胶带，实测只到 3000 出头，且五路差几百码，黑侧也有可标的差别 |
| `pos = Σ(w·v)/Σ(v)` | 先归一化 `n_i` 再质心 | 直接减白底会让"黑白差大"的那路说话更响，质心被它拽偏 |
| "间距 ≤ 线宽" | 定 1.5cm，量眼睛到眼睛，模块长边垂直阵列 | 模块板子是长条的，板心不在两只眼睛中间，按板边量会歪；长边顺着阵列排会占到近 3cm，半格点测不出来 |
| 引脚没指定 | 挑出 GPIO6/7/8/2/3 | 能读模拟量的只有 GPIO1~10 / 11~20；35~42、46 没有 ADC，读出来是废数。按小车现有接线（day-24 图）取没占的脚，且全落在 ADC1 上（ADC2 和 Wi-Fi 抢模拟前端） |
