# 编辑约定（给助手：不属于学习内容，禁止写进 README）

本文件是 Clark 的写作规则。它记录"文档该怎么改"，**永远不要**把这些内容写进 `README.md` / `README.en.md` / 各 `day-NN/README.md`。用户明确要求：README 只记录学习内容本身（历程、问题、解决办法、结果），不记录文档的变动过程。

## 判断标准

一句话该不该留在 README：**它与学习内容有关，还是与"文档怎么改"有关？** 后者一律删除。

## 禁止出现在 README 的表述

- "已移到 xx/README.md"、"下沉至 xx"、"见 §九（原文在…）" —— 移动痕迹不留，删掉即可
- "原写的 xx 改为 yy"、"2026-09-19 修订"、"更新为" —— 直接写最终结论，不写演变史
- "上一版曾写"、"之前认为" —— 除非是讲自己搞错的技术因果（见下方例外），否则删

**例外**：如果修正本身是有教学价值的坑（如"把声速方向讲反了"这类），保留**技术因果**，仍不保留"某一版文档当时写了什么"的叙述。

## 推进下一章节（Day N+1）的固定流程

1. 把 Day N 的**选做 / 进阶**项从外层 README 移出，下沉到 `day-N/README.md` 内部的「选做 / 进阶」小节；外层不留任何"已移到哪里"的说明
2. 同步更新两个外层 README —— 删掉上一章已完成的「下一步」，只留最新章节的一处
3. 逐日章节的改动必须同时落到 `README.md` 与 `README.en.md`（目录表 + 目录树 + 完整章节）
4. 最后再写 Day N+1 的内容

## 标记约定

- ⏳ 指南明确要求、尚未完成（必补）
- ⏭️ 指南未要求的选做 / 进阶
- 📌 时机未到，等真实场景触发

外层 README 的「下一步」只保留**指向 Day N+1 的指针**；⏳/⏭️ 一律留在 `day-N/README.md` 内部。

## 其他硬性约定

- 图片一律用链接形式 ``[`x.png`](./x.png)``，**不用** `![]()`
- ESP32-S3 编译：`"/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli" compile --fqbn esp32:esp32:esp32s3 "day-NN/实验x"`
- 板载 RGB 用 `RgbCycle` 库（GPIO48）
- 枚举避开 Arduino 核心宏 `OK`/`LOW`/`HIGH`，距离档位叫 `D_NEAR`/`D_MID`/`D_FAR`/`D_INVALID`
- 能省的元件就省，别过度设计
- 回复用中文，极度精简
