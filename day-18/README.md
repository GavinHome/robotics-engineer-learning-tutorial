## 一、目标

读加速度计和陀螺仪，理解 **I2C 通信**。

和 Day 17 的对比先把话说清楚：

| | Day 17 超声波 | Day 18 IMU |
|---|---|---|

## 二、I2C 是什么

### 两条线讲一屋子的话

```
        ┌──────────────┐
        │   ESP32-S3   │
        │    主机 Master│
        └──┬────────┬──┘
   SDA ────┘        └──── SCL
        │                │
   ┌────┴────┬───────────┴────┐
   │         │                │
┌──┴──┐  ┌───┴───┐      ┌────┴───┐
│0x68 │  │ 0x3C  │      │ 0x76   │
│IMU  │  │ OLED  │      │ 气压计 │
└─────┘  └───────┘      └────────┘
   全部并联在同一对 SDA/SCL 上
```

- **SDA**（Serial Data）：传数据
- **SCL**（Serial Clock）：主机打拍子，双方按同一个节拍收发

关键：**一根总线挂多个设备，靠地址区分。** 不像 SPI 每个从机都要一根 CS 片选线，也不像 UART 只能点对点。

### 一次完整的读取

```
主机：START ──▶ 设备地址+写(0xD0) ──▶ 寄存器号(0x3B)
      ──▶ 重START ──▶ 设备地址+读(0xD1)
从机：                                    ──▶ 数据字节 ──▶ 数据字节 ──▶ ...
主机：                                                          ──▶ STOP
```

两个细节：

1. **地址是 7 位**，第 8 位是读写方向。`0x68 << 1 | 1 = 0xD1`（读），`0x68 << 1 | 0 = 0xD0`（写）。代码里直接填 `0x68`，底层位移由库做。
2. **每传一个字节，接收方要拉低 SDA 一拍作为 ACK**（应答）。没拉低就是 NACK —— 扫描器就是靠这个判断"这个地址上有没有人"。

### ⚠️ I2C 是开漏输出，必须上拉

SDA/SCL 引脚只能**拉低**，不能主动推高。总线靠上拉电阻维持高电平。**没有上拉母线永远读不到 ACK**。

MPU-6050 模块自带 4.7kΩ 上拉 + LDO，所以本项目**一个额外元件都不用加** —— 4 根杜邦线直连即可。

> 📌 自己画板或接裸芯片（不是模块）时要**外加 4.7kΩ 上拉到 3V3**。这条今天用不上，但串口一直报 "not found" 时会回来查。

### MPU-6050 的地址

| AD0 引脚 | 地址 |
|---|---|
| 悬空 / 接 GND | **0x68**（默认，本项目用这个） |
| 接 VCC | 0x69 |

同型号想挂两个？一个 AD0 接地、一个接 VCC 就能在同一总线上共存。

## 三、MPU-6050 是什么

一个芯片里塞了两个传感器：

| 传感器 | 测什么 | 单位 | 静止时（放平） | 类比 |
|---|---|---|---|---|
| **加速度计** 三轴 | 比力（含重力） | m/s² | az ≈ **9.8**，ax/ay ≈ 0 | 耳石：知道哪边是"下" |
| **陀螺仪** 三轴 | 角速度 | rad/s | 全 ≈ 0 | 半规管：感知转动 |

### 加速度计为什么静止时是 9.8？

爱因斯坦的等效原理是最短的那一句：**静止在桌面上的加速度计测到的不是"重力"，而是桌面给它的支持力**，大小刚好等于重力，方向朝上。所以放平时读到 +9.8 而不是 0 —— **它测的其实是"没掉下去"这件事**。

自由落体时读数是 0（失重）。这是判断"加速度计读数到底对不对"最快的自检：**放平就该是 9.8，拿起来甩 ax/ay 才大幅偏离。**

但自检要做得更狠一点 —— 看**模长**而不是单轴：

```
|a| = √(ax² + ay² + az²)     静止时应恒等于 9.81，与摆放姿态无关
```

单看 `az` 只有 7.8 时，你会以为"没放平"；算一下模长，如果 `|a|` 也是 7.8，那就是**刻度错了**（灵敏度偏差）；如果 `|a| = 9.81` 而 `az = 7.8`，那才是**方向错了**（真倾斜）。这一条把两类故障彻底分开，实测见 §八。

### 为什么两个都要？各自的短板

| | 长期准吗 | 抗震动吗 | 会漂移吗 |
|---|---|---|---|
| 加速度计求角 | ✅ 长期指向"下"，不漂 | ❌ 一抖就乱跳 | 不会 |
| 陀螺仪积分 | ❌ 角度会累积误差漂走 | ✅ 完全不受线性加速度影响 | **会** |

所以单独用哪个都不行。**互补滤波 / 卡尔曼滤波**就是把两者融合的工程解法 —— 超出本课范围，Day 21 之后再说。

本课只用加速度计求倾角（指南的"简化版"要求），陀螺仪数据照读照打印，先感受一下数量级。

## 四、接线

```
        MPU-6050                   ESP32-S3
   ┌──────────────┐          ┌──────────────────┐
   │              │          │                  │
   │  VCC    ●────┼──────────┼── 3V3            │
   │  GND    ●────┼──────────┼── GND            │
   │  SCL    ●────┼──────────┼── GPIO9          │
   │  SDA    ●────┼──────────┼── GPIO8          │
   │              │          │                  │
   │   ┌───────┐  │          │  板载 RGB: GPIO48│
   │   │ QFN   │  │          └──────────────────┘
   │   │ 芯片  │  │
   │   └───────┘  │
   │  AD0 未接→0x68│
   └──────────────┘
      模块自带 LDO + 上拉电阻，零额外元件
```

| MPU-6050 | ESP32-S3 | 说明 |
|---|---|---|
| VCC | **3V3** | 模块自带 LDO；**别接 5V** —— 上拉若拉到 5V，SDA/SCL 会超出 3.3V IO |
| GND | GND | **必须共地**，否则总线没有回流路径 |
| SDA | **GPIO8** | 数据线 |
| SCL | **GPIO9** | 时钟线 |

**接线顺序**：先 GND → 再 SDA/SCL → 最后 VCC。拆线反过来。

### ⚠️ 为什么是 GPIO8/9

ESP32-S3 **没有固定的 I2C 引脚** —— 片上有 GPIO 矩阵，任意 GPIO 都能路由成 SDA/SCL，靠 `Wire.begin(SDA, SCL)` 指定。这和 AVR（Uno/Nano 的 A4/A5 焊死）完全不同。

但要避开 **strapping 引脚** —— GPIO0 / GPIO3 / GPIO45 / GPIO46 在上电瞬间要采样电平来决定启动模式。外接模块会把电平拉偏，板子可能起不来。GPIO8/9 不在名单里，且在排针上相邻，走线整齐。

> 📌 Day 17 的超声波选 GPIO4/5 时已经给今天的 8/9 让开了位置 —— 整周排针分配：4/5 超声波、8/9 I2C、Day 19 电机用 10/11/12/16。

## 五、实验 1：I2C 扫描

文件：[`实验1-I2C扫描/实验1-I2C扫描.ino`](./实验1-I2C扫描/实验1-I2C扫描.ino)

**接任何 I2C 模块之前先跑它。** 确认线通不通、地址对不对，能省掉后面 90% 的排查时间。

```cpp
Wire.begin(SDA_PIN, SCL_PIN);        // ESP32-S3 必须显式传引脚

for (uint8_t addr = 1; addr < 0x80; addr++) {
  Wire.beginTransmission(addr);      // 只把地址放到总线上，不传数据
  uint8_t err = Wire.endTransmission();
  if (err == 0) Serial.printf("  -> found 0x%02X\n", addr);
}
```

`endTransmission()` 的返回值就是判决依据：

| 返回值 | 含义 |
|---|---|
| **0** | 成功 —— 有设备拉低 SDA 应答了 ✅ |
| 2 | 地址发出去了，但没人应答（NACK） |
| 3 | 数据字节没被应答 |
| 4 | 其他错误（总线被占 / 仲裁丢失） |

每 3 秒重扫一次，方便插拔线观察。灯色也是状态指示：**红=没扫到**（查线），**绿=扫到了**。

## 六、实验 2：IMU 读数与倾角

文件：[`实验2-IMU读数/实验2-IMU读数.ino`](./实验2-IMU读数/实验2-IMU读数.ino)

### 初始化

```cpp
Wire.begin(SDA_PIN, SCL_PIN);

// 第二个参数要把指定好引脚的那条 Wire 传进去，否则库用的默认引脚可能不是 8/9
if (!mpu.begin(0x68, &Wire)) { /* 停住 */ }

mpu.setAccelerometerRange(MPU6050_RANGE_8_G);
mpu.setGyroRange(MPU6050_RANGE_500_DEG);
mpu.setFilterBandwidth(MPU6050_BAND_21_HZ);
```

`mpu.begin()` 内部读 **WHO_AM_I 寄存器**（值应为 0x68）确认芯片在线 —— 这一步失败，说明要么线不通、要么地址不对，回到实验 1。**但注意"实验 1 能过"不代表这里一定能过**，接触不良时实验 1 照样命中而这里失败，详见 §九 案例 1。

三个量程/滤波参数：

| 设置 | 取值 | 权衡 |
|---|---|---|
| 加速度量程 | ±8G | 越小分辨率越高，但砸桌/剧烈运动会打满溢出。2G 日常够，8G 留余量 |
| 陀螺量程 | ±500°/s | 手拿着转很难超过这个值 |
| 低通带宽 | 21Hz | 滤机械抖动。带宽越低越干净、**延迟越大**（21Hz 约 5ms） |

### 读数

```cpp
sensors_event_t a, g, temp;
mpu.getEvent(&a, &g, &temp);
// a.acceleration.{x,y,z}  → m/s²
// g.gyro.{x,y,z}          → rad/s
// temp.temperature        → ℃
```

`sensors_event_t` 是 **Adafruit Unified Sensor** 定义的统一结构体。它的意义是：换任何一个 Adafruit 传感器，读数这行代码长得都一样 —— 以后接 BMP280 气压计不用重新学一遍。

> ⚠️ **单位注意**：陀螺仪出来的是 **rad/s，不是 °/s**。乘 `180/π` 才是度每秒。

### 怎么由加速度求倾角

静止时加速度计测到的就是重力矢量。放平时 `az = 9.8, ax = ay = 0`；倾斜 θ 后，重力在水平轴上分出 `g·sinθ`：

```
   倾斜 θ          重力 g 竖直向下
     ___           │
    ▓▓▓▓▓          分解：
     ╲             沿板面 = g·sinθ  → ax 出现分量
      ╲ θ          垂直板面 = g·cosθ → az 减小
       ╲
```

所以 **`θ = atan2(分量, 另一分量)`**：

```cpp
// roll  绕 X 轴翻滚：Y 与 Z 之比
float roll  = atan2(a.acceleration.y, a.acceleration.z) * 180.0 / M_PI;

// pitch 绕 Y 轴俯仰：X 与 YZ 合矢量之比（分母必须取模长）
float pitch = atan2(-a.acceleration.x,
                    sqrt(a.acceleration.y * a.acceleration.y +
                         a.acceleration.z * a.acceleration.z)) * 180.0 / M_PI;
```

两个易错点：

| 坑 | 说明 |
|---|---|
| **用 `atan2` 而不是 `atan`** | `atan` 只能覆盖 ±90° 且**丢符号**（无法区分正负倾角）；`atan2` 两个参数各自带符号，覆盖 ±180° 全象限 |
| **pitch 的分母要取 YZ 模长** | 偷懒写成 `atan2(-ax, az)` 在 roll 很大时会算错 —— 那是另一个轴污染进来的结果 |

> 📌 **这套公式只在静止/匀速时成立。** 加速运动时有额外线性加速度叠加到重力上，算出的"倾角"是假的。这正是要用陀螺仪融合的原因。

### 输出

一行 JSON（延续 Day 13/14/17 的格式，方便 Python 直接解析）：

实测真实一行（静止时，注意 `az` 没到 9.8，原因见 §八）：

```json
{"ax":0.41,"ay":-0.07,"az":7.82,"gx":-0.027,"gy":0.030,"gz":-0.009,"roll":-0.6,"pitch":-3.0,"zone":"LEVEL"}
```

灯色 = 倾角档位，沿用 Day 14 的状态指示约定：

| \|roll\| + \|pitch\| | 灯色 | zone |
|---|---|---|
| < 10° | 🟢 绿 | `LEVEL` |
| 10 ~ 45° | 🟠 橙 | `TILT` |
| ≥ 45° | 🔴 红 | `STEEP` |
| 传感器异常 | 🔵 蓝 | `T_FAIL` |

枚举同样避开 Arduino 核心宏 `LOW`/`HIGH`，叫 `T_LEVEL`/`T_TILT`/`T_STEEP`/`T_FAIL`。

**非阻塞节流**：用 `millis()` 而不是 `delay(500)` —— 因为 `RgbCycle::update()` 需要被持续调用才能循环变色。Day 21 整车同时跑多个任务时，这个写法是必须的。

### ⚠️ 自检没全过：az = 7.82，不是 9.8

按 §三 的自检标准，平放时 `az` 该在 **9.8 ± 0.3** 内。实测 7.82，偏差 **−20.2%**。

先排除"没放平"：如果只是倾斜 θ，`az = g·cosθ` 会变小，但**合矢量模长仍然是 9.81**。而实测

```
|a| = √(0.41² + 0.07² + 7.82²) = 7.83 m/s²
```

模长本身就少了 2 m/s²，且方向几乎正对 Z 轴（roll/pitch 才 3°）。**所以不是摆放问题，是灵敏度标定偏差** —— 芯片的 LSB/g 增益与数据手册标称值不一致，读出来整体偏小。

这类 13.8 元的模块相当常见。修法见 §十一 第 1 项（加速度计标定）。

> 📌 换个角度看，这恰好证明了"模长自检"比"单轴自检"更强：**单看 az 会误判成没放平，看模长才能区分"方向错"和"刻度错"。**

### 第 3 步（陀螺仪漂移）

静止 10 帧的陀螺仪读数（上方表格）不是 0，而是稳定的非零值。这就是零点偏移。

拿 `gy = 0.030 rad/s` 算笔账：

```
0.030 rad/s × 30 s = 0.9 rad ≈ 52°
```

**静止不动放 30 秒，单纯积分出来的"角度"能跑偏 52°。** §三 那句"陀螺仪会漂"从此有了具体数字 —— 这就是为什么姿态解算必须把加速度计拉回来，单独积分陀螺仪不可用。

> ⚠️ 上电第一帧的陀螺仪读数异常大（`gz = 1.154`、`-0.552`），是上电瞬态，读程序时应当丢弃前 1~2 帧。

## 九、出了什么问题 & 怎么修

### 案例 1：实验 2 报 `MPU6050 not found`，但实验 1 同一条线扫得到 0x68

**症状**：实验 1 稳定输出 `found 0x68`，换到实验 2 就停在

```
MPU6050 not found at 0x68. Check wiring / run the scanner sketch.
```

**原因**：杜邦线母头与模块排针**接触不良**，没插到底。

**为什么实验 1 能过而实验 2 过不了** —— 这是本案例真正值得记的点：

| | 事务次数 | 失败后果 |
|---|---|---|
| 实验 1 扫描器 | 每个地址 1 次独立写，互不影响 | 某一帧失败只丢一个地址，下一轮重扫又能命中 |
| 实验 2 `mpu.begin()` | 地址探测 + 读 WHO_AM_I 一连串事务 | 中间任何一帧断了，整个 `begin()` 返回 false |

**"扫描能过"不等于"接触可靠"。** 扫描是统计意义上的偶发成功，库初始化是要求连续成功。所以排错的顺序不能反：先重插线，再怀疑库和芯片。

**修复**：4 根线逐根拔下重插，听到/感觉到卡扣到位；确认母头完全套住排针，不是只搭在针尖上。

### 案例 2：静止时 `az` = 7.82 而不是 9.8

见 §八 的分析。**模长偏小 20%** 是灵敏度标定偏差，不是接线问题，重插线无效。

### 通用症状表

| 症状 | 原因 | 修复 |
|---|---|---|
| **扫描 0 found，灯红** | ① 没共地 ② SDA/SCL 接反 ③ VCC 没接 | 逐根核对；量 VCC-GND 应为 ~3.3V |
| 库初始化失败，但扫描能命中 | **接触不良**（见案例 1） | 重插线，别先改代码 |
| `az` 偏小但方向对 | 灵敏度标定偏差（见案例 2） | 乘标定系数，见 §十一 |
| **`az` 是 0 或 −9.8** | 模块装反了（芯片面朝下） | 翻过来装；`az` 变 −9.8 就是典型的倒装 |
| 读数全是 0 | 总线锁死 | 断电重接；检查 SDA/SCL 上有没有别的设备占用 |
| `Wire.begin()` 编译报错 | 用了 AVR 老教程的写法 | ESP32-S3 必须 `Wire.begin(SDA, SCL)` 传引脚 |
| 串口无输出 | 波特率 / COM 口 | 115200 |
| 陀螺仪读数看着不对 | 单位混淆 | `g.gyro.*` 是 **rad/s**，乘 `180/π` 才是 °/s |
| 倾角在抖动时乱跳 | 正常 —— 只用加速度计的代价 | 见 §十一 互补滤波 |
| 上电第一帧陀螺仪读数爆表 | 上电瞬态 | 丢弃前 1~2 帧 |

## 十、与《逐日指南》的出入

| 指南原文 | 本 README | 理由 |
|---|---|---|
| SCL→GPIO9, SDA→GPIO8 | ✅ 沿用 | 已避开 0/3/45/46 strapping 引脚 |
| VCC→3.3V（或 5V） | **只用 3V3，不用 5V** | 模块上拉若拉到 5V，SDA/SCL 超过 ESP32-S3 的 3.3V IO 上限 |
| Adafruit MPU6050 库 | ✅ 沿用 | 依赖 BusIO + Unified Sensor 需一并安装 |
| 采样间隔 `delay(500)` | 改成 `millis()` 非阻塞 | 保证 `RgbCycle::update()` 能并行跑 |
| 输出：串口输出 | ✅ 沿用 + 加倾角档位灯色 | 延续 Day 14 状态指示约定 |
| 输出：姿态可视化（可选） | 📌 不做 | 串口足够验证；见 §十一 |

> 原则：**能省的元件就省。** 模块自带 LDO + 上拉电阻，4 根杜邦线直连，零额外元件。

## 十一、选做 / 进阶

以下都是**非必须**的补强项，按兴趣挑。

### 本日实测暴露的两个待办

- ⏭️ **加速度计标定**：实测模长 7.83 而标准值 9.81，比例系数 `9.81 / 7.83 = 1.253`。最简单做法是读数统一乘这个系数；要更准用 **6 面法**：把模块六个面依次朝下各采一组数据，每轴取 ± 两组的平均值作为零点与满量程，逐轴解出偏移和增益。不标定的话，所有倾角读数会按同一个比例缩小（`asin` 出来的角度偏小约 20%）。
- ⏭️ **拔掉 SDA 复测扫描器**：验证绿灯靠的是真 ACK 而不是误判 —— 拔掉 SDA 再扫，应该 `0 found` 且灯变红。这个负向对照实验 5 分钟就能做完，但它证明的是"扫描器的绿灯确实来自设备应答"，而不是总线悬空时的假阳性。

### 进阶方向

- ⏭️ **陀螺仪零点标定**：静止时读数不是 0（实测 `gx=-0.028, gy=0.030, gz=-0.009` rad/s），减掉这个偏置能显著减缓漂移。做法：上电后取前 200 帧求平均，之后每帧减掉。
- ⏭️ **互补滤波**融合加速度计与陀螺仪：`angle = 0.98 × (angle + gyro·dt) + 0.02 × accAngle`。Day 21 小车要知道自己倾没倾时会需要。
- ⏭️ **Python + Matplotlib 实时画姿态曲线**：本日已输出 JSON，直接复用 Day 13 的串口解析脚本。
- ⏭️ **Serial Plotter 直接看**：把 ax/ay/az 三个值用空格隔开打印，`工具 → 串口绘图器` 就能看波形，不用写字上位机。
- ⏭️ **OLED 显示姿态**（同一条 I2C 总线，0x3C）：装 MPU6050 库时已从文件带进来了 SSD1306 依赖，硬件到货后可试。
