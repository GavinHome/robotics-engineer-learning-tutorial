# Day 31 — 中断：反应计时游戏

第 2 个月第 1 天的主题只有一个：**中断**。

编码器要数脉冲，脉冲是电机转起来之后源源不断来的，不能靠 `loop()` 里 `digitalRead()` 一遍遍问——问的间隙就漏了。Day 32 接编码器之前，先把中断这件事在一个"看得见、摸得着、错了立刻知道"的实验上吃透：**人按键的反应时间**。同一套游戏写完两份代码，唯一差别是"谁发现按键被按下"，用对照把中断的价值钉在数据上。今天要落地的结论只有一条：**`loop()` 慢到一定程度时，轮询不是迟一会儿，是直接漏**——这正是编码器不能靠轮询的原因。

## 一、接线

全部外设只有一颗按键 + 一颗 LED，USB 供电足够。

| ESP32-S3 引脚 | 接到 | 说明 |
|---|---|---|
| GPIO1 | 按键一脚 | 内部上拉：不按 = 高、按下 = 低 |
| GND | 按键另一脚 | |
| GPIO2 | 1kΩ → LED 长脚 | GPIO2 不在 ADC1 上，纯数字输出最干净 |
| GND | LED 短脚 | 1kΩ 是限流值里最合适的（3.3V 下约 3mA，亮且不刺眼） |
| GPIO3 | **悬空** | 只用来给 `randomSeed()` 提供噪声，不接任何东西 |
| GPIO48 | 板载 WS2812B | 用 `RgbCycle` 库做状态灯，不用另接线 |

### 板载彩灯的三色语义

状态指示只用 `RgbCycle::begin()` + `RgbCycle::setColor()`，**不调 `update()`**（一调就开始三色循环，反而看不出状态）：

| 颜色 | 含义 |
|---|---|
| 绿 | 随机等待中（2~5 秒），这时按了算抢跑 |
| 蓝 | 外接 LED 亮起，计时开始，快按 |
| 黄 | 本轮结束，展示 `reaction = xx ms` |
| 红 | 抢跑，本轮作废重开 |

## 二、两个版本跑的是同一个游戏

| | 实验1 `实验1-轮询版` | 实验2 `实验2-中断版` |
|---|---|---|
| 怎么知道按键按下 | `loop()` 里 `digitalRead(PIN_BTN) == LOW` | `attachInterrupt()` 挂 FALLING 边沿，ISR 里打时间戳 |
| 谁算反应时间 | `millis() - tLight`（在 loop 里） | `tPress - tLight`（时间戳来自 ISR） |
| 去抖放在哪 | loop 里比时间戳 | **ISR 里**比时间戳，不阻塞 |
| 有没有额外打印 | 每秒一条 `loop = xx 圈/秒` | 无 |

两版的接线、引脚、随机延时区间、去抖 50ms、结果展示 1.5s 完全一致，唯一的差别就是"谁发现按键被按下"。

状态机三个态，两版通用：

```
ST_WAIT ──(随机延时到)──> ST_TIMING ──(按下)──> ST_RESULT ──(1.5s)──> ST_WAIT
   │                                              ^
   └──(提前按 = 抢跑)──────────────────────────────┘
```

`millis()` 判断一律用相减（`now - tRound >= waitMs`），不用加法比大小——相减在 `millis()` 溢出回绕时依然正确。

## 四、中断的三个坑

三个坑，以及为什么会炸：

### 坑 1：中断里不能 `Serial.print`，也不能 `delay()`

`Serial.printf()` 在数据没发完时会**忙等**串口；`delay()` 直接挂起。中断服务函数（ISR）一慢，主循环被拖住不说，ESP32 的其他中断也可能被延迟。

本实验的做法是：ISR 里只做"读 `millis()`、写三个 `volatile` 变量"这点事，其余全在 `loop()` 里。ISR 因此短到可以随时来。

### 坑 2：跨中断共享的变量必须 `volatile`

编译器不知道 ISR 会偷偷改 `evt` / `tPress`，很可能把 `loop()` 里对它们的读操作优化掉（"这个值上一行刚读过，不可能变"），结果永远等不到事件。

```cpp
volatile Evt evt = EVT_NONE;        // 必须 volatile
volatile unsigned long tPress = 0;
volatile bool timing = false;
```

注意 `volatile` 只管"别优化掉这次访问"，**不管原子性**。所以 ISR 里先写 `tPress` 再置 `evt`，`loop()` 里先读 `evt` 再读 `tPress`——用"标志后置"保证读到的时间戳是新的。清标志这种活也只能由 `loop()` 单方面做，ISR 只负责置位。

### 坑 3：ESP32 的 ISR 必须加 `IRAM_ATTR`

```cpp
void IRAM_ATTR onPress() { ... }
```

默认代码放在 Flash 里，而 Flash 在缓存被禁用的时段（例如写 Flash）是**读不了**的，ISR 跑过去会直接挂死。加 `IRAM_ATTR` 把函数指定放进 IRAM（SRAM），任何时候都能执行。

### 附带踩到的一个：`randomSeed()` 的种子不能取按键脚

指南给的例子是 `randomSeed(analogRead(1))`，而 GPIO1 正是按键脚。按键松开时被内部上拉拉高，`analogRead()` 每次上电读到的是同一个值 —— 随机序列每次重启都一模一样，游戏第一下就把答案泄露了。

因此 GPIO3 单独留一个悬空脚做种子源：ADC 输入端浮空时有热噪声，读数逐次上电都不同。若实测发现序列仍然重复，用手碰一下 GPIO3 即可引入噪声。

## 五、上机步骤

1. 按 §一 接线，上电前用万用表通断档确认按键两脚、LED 两脚没有搭到一起，电源正负极没短路。
2. 烧 `实验1-轮询版`，打开串口监视器（115200）。
3. 玩 10 轮：看到外接 LED 亮立刻按，把每轮 `reaction = xx ms` 记进下表，同时记下每秒打印的 `loop = xx 圈/秒`。
4. 把 `实验1-轮询版.ino` 里 `loop()` 中的 `delay(50);` 打开，重新编译烧录，再玩 10 轮 —— 这行模拟的正是"loop 里有别的活要干"的真实情况（.ino 头部写明了两种配置的唯一差别就是这一行）。
5. 烧 `实验2-中断版`，同样玩 10 轮。
6. 对比三组数据：`loop 圈/秒` 掉多少、最短反应时间有没有跟着变差。

## 六、测试结果

**实验1 轮询版** ✅ 两种配置都测了 · 素材：[`实验1-串口打印.txt`](./实验1-串口打印.txt)（空转）、[`实验1-串口打印-delay50.txt`](./实验1-串口打印-delay50.txt)（delay 版）、[`实验1-轮询版.MOV`](./实验1-轮询版.MOV)
**实验2 中断版** ✅ 已测 · 素材：[`实验2-串口打印.txt`](./实验2-串口打印.txt)

实验1 的两个配置**只差 `loop()` 里那一行 `delay(50)`**，其余一字未动（见 .ino 头部说明）。

| 版本 | 最短 reaction | 中位数 | `loop 圈/秒` | 备注 |
|---|---|---|---|---|
| 轮询（loop 空转） | **358 ms** | 769 ms | 48.7万–65.2万 | 4 轮有效（1802 / 750 / 788 / 358），零抢跑 |
| 轮询（`loop` 里加 `delay(50)`） | **200 ms** | 250 ms | **20** | 21 轮有效 + 2 次抢跑，reaction 全是 50 的整数倍 |
| 中断 | **189 ms** | 217 ms | 不适用（不依赖 loop） | 15 轮有效 + 2 次抢跑 |

**要回答的问题**：中断版比轮询版快出来的那几毫秒，真的是中断的功劳吗？

### 实验1：4 轮就看出"比 reaction"比不出中断

4 轮 reaction：1802 / 750 / 788 / 358 ms，相差 5 倍，只有 358 ms 落在人的正常区间，1802 ms 那轮是走神——**人手噪声是几百毫秒量级**。程序侧空转 `loop()` 一圈 ≈ **2 µs**（50.3万 圈/秒），每秒一条 `Serial.printf()` 的短行进了发送缓冲区、通常不阻塞，所以轮询版的**最坏发现延迟是 2 µs ~ 毫秒级**，对 358 ms 而言不到 1%。两版在人手尺度上测不出差别。

### 实验2：15 轮同样不支持"中断更快"

实验2 的 15 轮 reaction：189 / 193 / 196 / 197 / 204 / 206 / 209 / 217 / 257 / 271 / 286 / 302 / 312 / 428 / 768 ms。
最短 **189 ms**、中位数 **217 ms**、均值 282 ms（去掉开头两轮冷身的 428 / 768，13 轮均值 234 ms、中位数 204 ms）；
另记录到 **2 次抢跑**，`EVT_FALSE_START` 分支验通。

中断版的中位数确实比实验1 好一大截（217 vs 769 ms），**但这笔账不能记在中断头上**：两次测量隔了不到一小时，实验2 是练过之后的第二轮，前两轮 428 / 768 明显是冷身，之后稳定掉进 190–220 区间——这是**训练效应**，不是边沿触发比轮询快。

### delay(50)：轮询的代价终于能看见

| | loop 一圈 | 轮询最坏发现延迟 | reaction 的最细刻度 |
|---|---|---|---|
| 轮询（空转） | ≈2 µs | 2 µs | 1 ms |
| 轮询（`delay(50)`） | **50 ms** | **50 ms** | **50 ms** |
| 中断 | 无关 | **0** | 1 ms |

`loop = 20 圈/秒`（第一秒 21），和 1000/50 对上了。21 轮 reaction：200 / 250 / 300 / 350 / 400 ms，中位数 250、均值 271、最短 200；另 2 次抢跑。**没有一个不是 50 的整数倍。**

这不是巧合：`reaction = now - tLight`，而 `now` 和 `tLight` 都是在 `loop()` 边界上取的，loop 一圈 50 ms，测出来的数就只能按 50 ms 跳——**测量分辨率本身被 loop 周期量化了**。对比中断版的 189 / 193 / 197 / 204 / 206 / 209 / 217 ms：毫秒级的数字在慢 loop 的轮询版里根本表达不出来，因为 ISR 的时间戳不受 loop 快慢影响。

中位数 250 ms 比中断版的 217 ms 高 33 ms，方向和量级都对得上（按键均匀落在半个周期里，期望 +25 ms）。而且这 33 ms 还是**低估**——delay(50) 这一轮测得晚，人已经练熟，训练效应本该让它更快，结果反而更慢。

### 结论

- 空转时两版测不出差别：**轮询已经足够快**（最坏发现延迟 2 µs ~ 毫秒级，占人反应 1% 以下）。
- `loop()` 一慢下来，轮询立刻付两笔账：**发现最多迟一整圈**（50 ms）、**测量刻度粗到 50 ms**。中断版一笔都不付——ISR 在按下的瞬间就打了时间戳。
- 中断版的 `loop()` 在计时状态下什么都不问（一个 `digitalRead()` 都没有，`ST_TIMING` 分支直接 `break`），照样抓到了每一次按下，包括 2 次灯没亮时的抢跑。
- 编码器要的就是这个性质：脉冲比 `loop()` 快的时候，轮询不是"迟一会儿"，是整个脉冲没被看见，`ticks` 少一个就永远少一个。
