## 一、GIF：30 MB 的 MOV 压到 1.5 MB

### 为什么是 GIF 不是视频

GitHub README 里 `<video>` 标签的兼容性一般，而 `.gif` 会被自动内联播放——点开 README 就动，不需要点击。代价是 GIF 只有 256 色、没有音频、体积大。对"小车撞墙前自己拐弯"这种 4 秒片段，这是划算的。

### 切哪一段

源素材 `day-21/实验2-超声波避障.MOV`：HEVC、1920×1080、29.97 fps、26.19 秒、785 帧、30 MB。

```bash
$ ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate,nb_frames -show_entries format=duration,size -of default=nw=1 "day-21/实验2-超声波避障.MOV"
codec_name=hevc
width=1920  height=1080  r_frame_rate=30000/1001  nb_frames=785
duration=26.188333  size=30250724
```

整段 26 秒里，车在跑的只有中间一段，开头是开机、结尾是手伸进去拿车。取 `-ss 1 -t 4`：跳过第 1 秒，截 4 秒。

**省掉的时间不只是转码时间**——26 秒 / 785 帧里真正有信息量的不到三分之一，直接整段转的话，观众前三秒看到的是一辆不动的车。

### 参数怎么定的

一条命令，四个可调旋钮：

```bash
ffmpeg -y -v error -ss 1 -t 4 -i "day-21/实验2-超声波避障.MOV" \
  -vf "fps=8,scale=440:-1" -loop 0 "day-24/超声波避障演示.gif"
```

| 旋钮             | 取值        | 为什么                                               |
| ---------------- | ----------- | ---------------------------------------------------- |
| `-ss 1 -t 4`   | 1 秒起 4 秒 | 跳过开机静止段                                       |
| `fps=8`        | 8           | 车是慢速运动，8 fps 足够连贯；每 +2 fps 体积涨约 20% |
| `scale=440:-1` | 宽 440      | README 正文宽度约 700px，440 显示清晰且不撑破排版    |
| `-loop 0`      | 无限循环    | GIF 不写 loop 块就只播一遍                           |

**`-ss` 放在 `-i` 前面**是快的原因：这样 ffmpeg 先 seek 再解码，只解 4 秒；放在 `-i` 后面会把 26 秒全解一遍再丢掉。

实测扫参（`fps=8,scale=440` 为基准）：

| 变量   | 取值                     | 体积                                  |
| ------ | ------------------------ | ------------------------------------- |
| 分辨率 | 320 /**440** / 640 | 821 KB /**1.50 MB** / 3.01 MB   |
| 帧率   | 6 /**8** / 10 / 12 | 1.17 /**1.50** / 1.83 / 2.10 MB |

分辨率是平方级关系（440→640 是 2.1× 像素，体积 2.0×），帧率是线性关系。**要省体积先降分辨率。**

### 调色板这条岔路

ffmpeg 转 GIF 有两条路，我原本以为第二条一定更好，实测下来不是：

```bash
# A：不指定 palette，ffmpeg 自己套一个通用调色板
-vf "fps=8,scale=440:-1"

# B：先从视频统计出这张图专属的 256 色，再拿它编码
-filter_complex "fps=8,scale=440:-1,split[a][b];[a]palettegen=max_colors=256[p];[b][p]paletteuse"
```

拿源视频第 3 秒那一帧当基准，量两种结果跟它的像素误差（RMSE，0–255 灰度）：

| 方案                          | 体积        | RMSE                 |
| ----------------------------- | ----------- | -------------------- |
| A 无 palette                  | 1,495,717 B | 6196（归一化 0.095） |
| B palettegen + 默认抖动       | 2,751,770 B | 1665（0.025）        |
| B palettegen +`dither=none` | 2,425,935 B | 1263（0.019）        |

保真度差 2.5–5 倍，但**体积贵 1.6 倍**。拆开 GIF 二进制看，四个方案结构完全一样——都是单张 256 色全局色表、零局部色表、32 帧全是 440×248 整帧，所以体积差别纯粹来自 LZW 压缩率：抖动把画面打上噪声点，细节多了就压不动。

4 秒的动作演示，1.5 MB 换 5 倍保真不划算——**看得出车在躲就够了**。最后装的是 A。

> 反过来，要展示的是串口波形、屏幕文字这类**细节即内容**的画面，`palettegen` 那 1.6 倍体积就值得付。

### 补一段地面实拍

后来补了第二段：车真的放在瓷砖地上跑（`智能小车落地跑.MOV`，HEVC、1920×1080、29.298 秒、31.9 MB）。上面那个 GIF 是早期**轮子悬空**的验证片段——能动、能躲，但看不出它真的在地上走。新切的是 19–22 秒，车靠近纸箱后自己后退 → 转向 → 强制前进，正好一个完整的避障周期：

```bash
ffmpeg -y -v error -ss 19 -t 3 -i "day-24/智能小车落地跑.MOV" \
  -vf "fps=6,scale=440:-1:flags=lanczos" -loop 0 "day-24/智能小车落地跑.gif"
```

440×782、6 fps、18 帧、3.00 秒、2,040,194 B。

三个旋钮重新扫了一遍（都是 `-ss 19`），结论跟上面一致——**要省体积先降分辨率**：

| 参数 | 体积 |
|---|---|
| 5 fps × 360 宽 × 4 秒 | 1.56 MB |
| 6 fps × 360 宽 × 3 秒 | 1.41 MB |
| **6 fps × 440 宽 × 3 秒** | **2.04 MB（装的这个）** |
| 8 fps × 400 宽 × 3 秒 | 2.27 MB |
| 8 fps × 440 宽 × 3 秒 | 2.71 MB |
| 8 fps × 440 宽 × 4 秒 + palette 有序抖动 | 5.62 MB |

`palettegen` 在这段上比第一段更不值得：画面是大片瓷砖地板，细节多得多，统计调色板 + `dither=none:bayer_scale=3` 出来 5.62 MB，比同一段不指定 palette 的 3.56 MB 还大 58%。**有序抖动给地板打上一层规则噪声点，LZW 直接压不动。** 这条不是推理出来的，是两个数字摆在一起看出来的。

### 实物图：13.2 MB 的 PNG 压到 346 KB

iPhone 直出的 PNG 是 3024×4032、13,240,200 B——一张图比三个 GIF 加起来还大，不可能进仓库。用 macOS 自带的 `sips`，不引新工具：

```bash
sips -Z 1400 -s format jpeg -s formatOptions 82 \
  "day-24/智能小车实物图.png" --out "day-24/智能小车实物图.jpg"
```

`-Z 1400` 是"最长边缩到 1400"并保持宽高比，3024×4032 → 1050×1400；`formatOptions 82` 是 JPEG 质量。出图 346,230 B。

| 输入 | 输出 |
|---|---|
| PNG 3024×4032，13.2 MB | JPEG 1050×1400，346 KB |

源 PNG 和 MOV 已移出仓库，但**它们是这两个派生文件的唯一来源**——GIF 和 JPG 都是压缩产物，删了原始素材就再也做不出同样的图。

## 二、电路图：没有 Fritzing 器件库怎么办

### 试过的和没试过的

指南推荐 Fritzing / draw.io / KiCad，先查本机有没有：

| 方案                                  | 结论                                                                        |
| ------------------------------------- | --------------------------------------------------------------------------- |
| Fritzing                              | 库里没有 ESP32-S3-WROOM-1，也没有我手上这块 TB6612FNG 模块（不是 DIP 那颗） |
| KiCad                                 | 没装                                                                        |
| draw.io                               | 在线工具，但画接线图要手摆几十根线，改一处全乱                              |
| Tinkercad Circuits                    | 试过：没有 ESP32，也没有 TB6612；只能画静态图                               |
| rsvg-convert                          | 没装                                                                        |
| **SVG 手写 + 无头 Chrome 渲染** | **这个能用**                                                          |

最后选了手写 SVG。理由不是"更极客"，是它解决了上面所有方案没解决的一个具体问题：

**接线图里引脚名是要跟着代码走的。** `AIN1 = 10` 在 `.ino` 里改了，图上就得改；SVG 是纯文本，`AIN1` 这四个字符能直接 grep 出来，跟 `.ino` 交叉核对是命令行一把梭的事。Fritzing 存的是二进制 `.fzz`，没法 diff，也没法跟代码对。

### 中文能不能渲染

第一个坑。SVG 里写 `font-family="Helvetica"` 加中文，渲染出来全是方框——Helvetica 里没有汉字字形。改成 `PingFang SC`（macOS 系统中文字体）就正常了。

```xml
<text x="180" y="109" font-family="PingFang SC" font-size="14">ESP32-S3-WROOM-1</text>
```

### 渲染命令

SVG 转 PNG 走的是**无头 Chrome 截图**，不是 ImageMagick：

```bash
cd /tmp/gc && "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=1.5 --window-size=1180,940 \
  --screenshot=/tmp/gc/wiring_1770.png --virtual-time-budget=5000 \
  file:///tmp/gc/wrap.html
```

`wrap.html` 是给 SVG 套的一层壳，把画布尺寸和白底写死：

```html
<!doctype html><html><head><meta charset="utf-8">
<style>html,body{margin:0;padding:0;background:#fff}
img{display:block;width:1180px;height:940px}</style></head>
<body><img src="car_wiring.svg"></body></html>
```

| 参数                              | 作用                 | 不加会怎样                                                     |
| --------------------------------- | -------------------- | -------------------------------------------------------------- |
| `--force-device-scale-factor=1.5` | 输出倍率             | 1× 只有 1180×940，大屏上发虚；1.5× → 1770×1410，2× → 2360×1880 |
| `--window-size=1180,940`        | 视口等于 SVG 画布   | 不相等就会被裁掉一块或留白边                                   |
| `--virtual-time-budget=5000`    | 等 5 秒再截图       | 页面还没布局完就拍，可能拍到空白                               |
| `--hide-scrollbars`             | 去掉滚动条           | 滚动条占掉十几像素，图会窄一点                                 |
| HTML 里 `background:#fff`       | 铺白底               | SVG 背景透明，转 PNG 后在深色主题下变成黑块                     |

倍率取值：1× 出 1180×940 偏小；1.5× 出 1770×1410 正好；2× 出 2360×1880 体积涨 34%，README 里看不出区别。

### 为什么不用 ImageMagick

`magick -density 144 in.svg -background white -flatten -strip out.png` 能出图，但**线全没了，只剩元器件方框**。

原因在 MSVG 这个 SVG 解析器：它不处理从父 `<g>` 继承下来的属性。这张图里所有连线都写成

```xml
<g fill="none" stroke-width="2" stroke-linejoin="miter">
  <path d="M300,174 H320 V64 H838 V180 H850" stroke="#dc2626"/>
  ...
</g>
```

`fill="none"`、`stroke-width` 挂在 `<g>` 上，每条 `<path>` 只写了 `d` 和 `stroke`。MSVG 读 `<path>` 时那两个继承属性是空的，于是按默认 `fill:black` 去**填充**路径——一条折线填出来面积是零，线就消失了。而元器件方框每个 `<rect>` 都自己写了 `fill` 和 `stroke`，不受影响，所以剩下的全是空白框。

`cairosvg` 也是同样的表现。判断方法：出图后**数一数有没有线**，别只看"文件生成了、尺寸对"。

要修其实有两种改法：给每个 `<path>` 补上 `fill="none" stroke-width="2"`，或者换成真正完整的渲染器。选了后者——无头 Chrome 走的是 Blink 的完整 SVG 实现，继承、滤镜、字体子集化都对，代价只是装个浏览器（本机已有）。

### 图里画了什么

[`智能小车接线图.png`](./智能小车接线图.png)（1770×1410，191 KB）：

**五个框 + 一个电池盒**，左边 ESP32-S3、中间 TB6612FNG 与 MP1584EN 降压、右边 HC-SR04 和两个马达、右下电池盒。每根线按用途着色，图例在底部：

| 颜色 | 含义                                                 |
| ---- | ---------------------------------------------------- |
| 蓝   | GPIO 信号（AIN1/AIN2/PWMA/BIN1/BIN2/PWMB/Trig/Echo） |
| 红   | 3V3 逻辑电（HC-SR04 的 VCC、TB6612 的 VCC 与 STBY）  |
| 橙   | 电池 6V（电机电源 VM + 降压输入，粗线，大电流）      |
| 绿   | 降压后的 5V（供开发板「5V」脚）                      |
| 黑   | 共地（粗线）                                         |

画的时候有意突出了三件容易接错的事：

- **橙线和红线在图上是分开的两条路**。电机吃电池 6V，逻辑吃开发板 3V3——`VM` 和 `VCC` 是 TB6612 上两个独立引脚。新手常把它们并起来接同一个电源，电机一转就把 3V3 拖垮。
- **橙线和绿线也是分开的两条路**。电池 6V 出来后分成并联两路：电机直连 `VM`，只有开发板那一路过降压模块。电机不走降压——两个 TT 马达同时启动的堵转电流会超过 MP1584EN 的 3A，过流保护一打嗝，正是"电流供不出"那个坑。
- **GND 五点共地**画成一条粗横线把所有框串起来：电池负极、降压 GND、开发板 GND、驱动 GND、HC-SR04 GND。漏接的话 GPIO 的高电平对驱动模块没有参考，信号是浮的，表现是"电机不动且测距恒为 0"。

> 这张图是**接线图**不是**原理图**：画的是"哪个引脚连哪个引脚"，不含电阻电容——因为这辆车本来就没用（见 §三）。要出 PCB 得用 KiCad 画真正的 schematic。

## 三、README 该按什么顺序组织

指南给的模板：

```
# 项目名称 / ## 简介 / ## 硬件清单 / ## 电路图 / ## 代码说明 / ## 测试结果 / ## 踩坑与解决 / ## 下一步
```

照模板给自己这辆车写了一份。写下来最大的体会不是"模板对不对"，而是**顺序不能随便换**——这个顺序对应读者的决策链：

| 顺序                 | 读者此刻的问题   | 答不上会怎样               |
| -------------------- | ---------------- | -------------------------- |
| 简介（一句话 + GIF） | 这东西能干嘛     | 后面全不想看               |
| 硬件清单             | 我要买多少钱的料 | 无法评估要不要复现         |
| 电路图               | 线怎么接         | 卡住，动手的人直接关页面   |
| 代码说明             | 逻辑怎么组织     | 接好了也不知道为什么这么写 |
| 测试结果             | 真的能跑吗       | 不敢信                     |
| 踩坑与解决           | 我会踩同样的坑吗 | 复现时重踩                 |
| 下一步               | 还在维护吗       | 判定为死项目               |

**简介必须带图。** 一段纯文字的简介，读者要读完 200 字才知道这是"会自己躲墙的小车"；一张 GIF 是 2 秒。

**"踩坑与解决"要写因果，不要写现象。** `传感器读数乱跳 → 换了个传感器` 没有信息量；`读数乱跳 → 测距周期 100ms 而 pulseIn 超时设的 30ms → 车反应迟钝，把超时压到 6ms` 才有用——前者别人照做也不知道为什么，后者能迁移到别的场景。

## 六、踩的坑

| 现象                                  | 原因                                     | 解决                                        |
| ------------------------------------- | ---------------------------------------- | ------------------------------------------- |
| SVG 里的中文渲染成一堆方框            | `font-family="Helvetica"` 没有汉字字形 | 改`PingFang SC`                           |
| 电路图渲染出来只剩方框、线全没了         | MSVG 不继承父 `<g>` 的 `fill`/`stroke-width`，`<path>` 退回默认 `fill:black` 填充，折线面积为 0 | 换无头 Chrome 渲染（Blink 的 SVG 实现完整）；或给每个 `<path>` 补 `fill="none"` |
| 透明底 SVG 转 PNG 后在深色背景发黑       | PNG 保留了透明通道                       | HTML 壳里 `background:#fff`              |
| 电路图默认渲染出来 1180×940 偏小发虚     | 默认倍率 1×，等于 SVG 画布本身           | `--force-device-scale-factor=1.5` 出 1770×1410 |
| `palettegen` 之后体积翻了 1.6 倍    | 抖动打上噪声点，LZW 压不动               | 4 秒动作片段不需要那份保真，用无 palette 版 |
| Fritzing 里找不到器件                 | 库里没有 ESP32-S3 和 TB6612FNG 模块封装  | 手写 SVG，引脚名可跟代码交叉核对            |
