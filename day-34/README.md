# Day 34 — 黑白判定与丢线处理

第 2 周第 4 天。昨天五路 AO 合成一个 `pos`，横扫一圈单调、中间准、两端压，看着能用了。但 `pos` 有一个致命的盲区：**三种"根本没有线"的情况，它全部读出 0，也就是"线正在正中间"。** 今天决定"看不见线"时车该怎么办——指南说这件事比 P 参数更容易翻车，今天之后就知道为什么。

## 一、`pos` 会在什么时候撒谎

拿昨天实测的标定表（白 1425~1672、黑 3719~3802）和 Day 32 的悬空读数（~2550）算一遍：

| 工况 | 五路 AO 大致长什么样 | 每路 n | Σn | Σ(w·n) | `pos` | 车会怎么想 |
|---|---|---|---|---|---|---|
| 压线（0 站） | 白 白 **黑** 白 白 | 0 0 1 0 0 | 1.0 | 0 | **0** | 线在正中间（对） |
| 全白（偏出阵列） | 全白 | 0 0 0 0 0 | 0 | 0 | 兜住了 | 没线（对，靠 `SUM_MIN`） |
| **全黑** | 全黑 | 1 1 1 1 1 | 5.0 | **0** | **0** | **线在正中间（错）** |
| **悬空无纸** | 全 ~2550 | ~0.45 ×5 | ~2.2 | ~0 | **≈0** | **线在正中间（错）** |

两种错法，根子是同一个：**权重 `w = −2/−1/0/+1/+2` 加起来恰好是 0。**

- **全黑**：五路 `n` 全是 1，`Σ(w·n) = 0`、`Σn = 5`，`pos = 0/5 = 0`。阵列盖在一大片黑上（冲出赛道、压到测试纸的 ② 全宽黑块），车认定自己完美对准。
- **悬空**：这是更阴的一种。Day 32 量过，什么都没有时 AO ≈ 2550——**落在白（~1500）和黑（~3800）正中间**。于是每路 `n ≈ 0.45`，`Σn ≈ 2.2`，远大于昨天的 `SUM_MIN = 0.5`；而五路一样亮，`Σ(w·n)` 还是 0。车被抬起来、冲过桌面上的缺口、骑到一块反光的地砖上，都会得到"线在正中间、放心开"。

昨天用 `SUM_MIN = 0.5` 只堵住了"全白"一种。它是拍出来的数——五路全白时 Σn≈0、一路压线时 0.6~1.0，0.5 卡中间——可悬空的 2.2 大摇大摆从它旁边走过去。所以今天换判据。

## 二、DO 上场：把"在不在"交给硬件

模块上 DO 是 AO 过了 LM393 比较器之后的电平，板上那颗 **104 电位器就是调它阈值**的。Day 32 说过"今天只要 AO"，因为要看黑白灰的渐变；今天要回答的是另一个问题——**线还在不在**——恰好是 DO 的活。分工就此定下来，后面一直这么用：

> **DO 只回答"在不在"，AO 才回答"在哪"。** 位置值继续用昨天的 AO 加权质心，DO 只做闸门。

### 接线

五路 AO 一根不动，把五路 DO 接上：

| ESP32-S3 | 接到 | 通道 |
|---|---|---|
| 3V3 | 五路 VCC | 同昨天，级联 |
| GND | 五路 GND | 必须共地 |
| GPIO6 / 7 / 8 / 2 / 3 | #0~#4 AO | 同昨天 |
| **GPIO1** | #0 DO | 纯数字输入 |
| **GPIO13** | #1 DO | |
| **GPIO14** | #2 DO | |
| **GPIO21** | #3 DO | |
| **GPIO47** | #4 DO | |

### DO 的五个脚是怎么挑的

纯数字输入，不需要 ADC，所以 ADC 那 20 个脚不用特意留着，只躲这些：

- 0 / 3 / 45 / 46 strapping
- 22~34 在 ESP32-S3-WROOM-1 上没引出（26~32 内部 Flash、33/34 Octal PSRAM），35~37 也是 Octal PSRAM
- 38 彩灯、39~42 JTAG、43/44 USB 串口、48 板载彩灯
- 4/5 超声波、10~17 TB6612、18 舵机（Day 27 云台）、8/9 MPU-6050 的 I2C
- 2/3/6/7/8 已经被五路 AO 占了

数剩下正好五个：**1、13、14、21、47**。GPIO1 是拆掉 Day 12 的电位器、Day 31 的按键之后空出来的，Day 12 在这个板子上用过，确定能当数字输入。

**⚠️ AO 的 0~4 和 DO 的 0~4 必须是同一批模块、同一个左右顺序。** 接反一路，那一路的黑白就和别的路反着来，五路 DO 的组合全是乱的，而且表面上看不出来——只会得到一堆说不通的丢线。

DO 脚开内部上拉（`INPUT_PULLUP`）。LM393 输出是集电极开路，模块板上那颗上拉万一没焊，脚就浮空；加上内部上拉不碍事，两种板子都能读。

### 极性不猜，标定时顺手记下来

哪一级电平代表"压线"，不同板子不一样，说明书不写。所以标定的时候**连 DO 一起采**：按 `c` 记下五路 DO 在白底上的电平，按 `b` 记下在黑底上的电平。两者不同，极性就自己浮出来了；两者相同，说明这颗电位器根本没把黑白分开。

`w` 命令打出的表里，最后两列就是它，最后一列直接给判定：

```
  路  AO脚  DO脚    白底   黑底   量程  建议阈值   DO白  DO黑  电位器
  0   6     1     1672   3802   2130    2737      0     1    已分开
  1   7     13    1526   3775   2249    2651      0     1    已分开
  2   8     14    1497   3782   2285    2640      0     1    已分开
  3   2     21    1448   3786   2338    2617      0     1    已分开
  4   3     47    1425   3719   2294    2572      0     1    已分开
```

（数字是昨天的实测表，先照着看懂格式；今天按完 `c`/`b` 会打出你自己的。）

## 三、阈值定在哪：量出来，不靠"转到差不多"

靶心很明确：**第 i 路的阈值 = (white_i + black_i) / 2**，也就是上表"建议阈值"那一列。离白、离黑各半个量程，两侧余量一样大。

但"转到中点"这件事手做不到——电位器没有刻度，转到位全靠猜。所以今天不猜，**用 `t` 命令把阈值量出来**：

1. 按 `t`，固件进入量测模式，20ms 一帧（比正常的 100ms 快，别错过翻转那一刻）。
2. 把纸从 ① 白底区**慢慢**横扫过 ② 黑块，再扫回来，做两个来回。一颗管子 1 秒左右。
3. 每路 DO 翻转时，固件当场记下那一刻的 AO 并打印：
   ```
   [teach] 路 0  DO 白→黑 @ AO 2681
   [teach] 路 0  DO 黑→白 @ AO 2596
   ```
4. 按任意键收表。

原理很直白：**DO 翻转的那一刻，AO 正好等于比较器的阈值。** 扫过去一次、扫回来一次，就能拿到两个翻点——它们的差就是 LM393 自带的**迟滞**。

```
  路  AO脚  DO脚  下翻点  上翻点  实际阈值   离白   离黑  迟滞  判定
  0   6     1     2681    2596     2638    966   1164    85  OK
```

判定列四种，逐个对应一种错法：

| 判定 | 含义 |
|---|---|
| `阈值掉到白底以下，永远报黑` | 这颗在白纸上也报压线，五路全黑 → 一直丢线 |
| `阈值顶到黑底以上，永远报白` | 这颗在黑块上也报没压线 |
| `余量不足，旁边那侧会误判` | 离白或离黑不到 300 码，桌面反光、纸的深浅一变就翻 |
| `OK` | 阈值落在黑白中间，两侧都还剩半个量程 |

**迟滞要单独看一眼。** 迟滞大意味着黑白交界处有一段 AO 读数，两种答案都对——线半压着一颗管子时，DO 会在"压线/没压线"之间抖。Day 24 避障用的 15/25 双阈值迟滞，在这里是 LM393 白送的，只是没法调。

### 为什么不用软件阈值

在 AO 上比大小一样能做二值化，而且能精确放到中点、能跟着标定值自动更新。今天仍然用 DO，理由是另外两条：**不占 ADC、不占 CPU**（五路 `digitalRead` 比五次 `analogRead` 加归一化便宜一个量级），以及**阈值固定在硬件里**，不依赖白底表还准不准。代价是不可编程、每颗要单独转、还要提防接反。Day 35/36 的控制量继续用 AO 的 `pos`，所以这个代价不咬人。

## 四、丢线状态机

```
FOLLOW ──五路全白 or 五路全黑──▶ LOST ──又看见线──▶ FOLLOW
  │                                │
  │                                └──连续丢线 500ms──▶ STOP ──连续看见线 300ms──▶ FOLLOW
```

| 状态 | 动作 | 彩灯 |
|---|---|---|
| `FOLLOW` | `pos` 照算，方向照给 | 绿=居中 / 红=偏左 / 蓝=偏右 |
| `LOST` | **`pos` 保持上一帧的值**，只记丢线了多久 | 白 |
| `STOP` | 停，不再输出方向；每秒再上报一次 | 红闪（250ms） |

三个设计点：

**① "全黑"和"全白"一样是丢线。** 这是昨天 `SUM_MIN` 漏掉的那半边。五路全压线时分两种：真的一大片黑（冲出赛道），或者五颗管子全盖在同一根粗线上——后者 `pos` 恰好 0，车会笔直扎进去。两种都必须当"看不见"处理。

**② 500ms 是这么来的。** 车大约 300mm/s，100ms 挪 30mm。"线抖了一下"只会丢一两帧（100~200ms），"真冲出赛道"是永远。500ms 落在两者之间。**这个数今天是推理出来的，Day 35 装车量到真实速度必须回来重定**——它是唯一一个今天拍不了脑袋的常数。

**③ 从 `STOP` 恢复要连续看见线 300ms。** 否则车停在丢线边界上，DO 一抖就 `FOLLOW`、一抖又 `STOP`，来回抽搐。Day 24 的 `COMMIT` 状态是同一个思路：认定一个结论之后，先强迫自己走一段再改。

## 五、上机步骤

硬件和昨天完全一样，只多五根 DO 线；模块的高度、间距、对齐都不动。

1. 接线上电前万用表通断档确认五路 VCC/GND 没短路，**再确认 0 号在最左、AO 和 DO 没接反**。
2. 烧录，打开串口监视器（115200）。桌面铺白纸或测试纸 ① 区，按 `c`；推到 ② 全宽黑块，按 `b`。**先看 `w` 表最后一列——五路都得是"已分开"。** 哪一路是"没分开"，就是那颗电位器没调或接错了。
3. 按 `t`，把纸从 ① 横扫到 ② 再扫回来，做两个来回，按任意键收表。五路的判定列都该是 `OK`。不是 `OK` 的，转那颗电位器再按 `t` 重来——**转之前先记下现在转到哪了**，104 电位器一圈能转三百多度，转晕了回不去。
4. 按 `p` 开曲线模式，用串口绘图器看 `pos` 和"压线路数×250"两条线。横扫时应当看到：压线路数在 0~5 之间起伏，`pos` 跟着平滑走；**`pos` 塌到 0 而压线路数是 0 或 5 的那一刻，就是丢线**。
5. 测三种工况（见下）。每换两三个站位回 ① 区按 `w` 核对，白底 3 分钟能漂 250 个码，漂了重按 `c`，黑底跟着重按 `b`。

## 六、三种工况 ⏳

指南要求"压线 / 偏出 / 静止无纸，确认判定不打架"。先算清楚每种该出现什么，再上机对。

| 工况 | 怎么造 | 五路 DO | `pos` | 该走的状态 |
|---|---|---|---|---|
| 压线 | 纸停在 0 站（黑条压在 2 号上） | `[0 0 1 0 0]` | ≈0 | `FOLLOW`，绿灯 |
| 偏出 | 纸推到 ±45 站，黑条整个出了阵列 | `[0 0 0 0 0]` | 保持上一帧 | `LOST` 白灯 → 500ms 后 `STOP` 红闪 |
| 静止无纸 | **把模块抬离桌面**（别用裸桌面——桌面有纹路、有色差，不是可信基准） | `[0 0 0 0 0]` 或 `[1 1 1 1 1]` | 保持上一帧 | `LOST` → `STOP` |

"静止无纸"这一行是今天最该盯的。Day 32 量到悬空 AO ≈ 2550，而五路建议阈值是 2572~2737——**悬空只比阈值低 22~187 个码**。所以：

- 电位器转得偏上（阈值 > 2550）→ 悬空落在白侧 → 全白 → 丢线
- 电位器转得偏下（阈值 < 2550）→ 悬空落在黑侧 → 全黑 → 丢线

**两条路都通向丢线。** 这不是巧合：只要阈值确实落在白和黑之间（`t` 命令的 `OK` 判定保证了这点），悬空这个中间值就必定被劈到其中一边，而两边都是丢线条件。反过来，昨天纯用 AO 时同一个悬空读数给出 `Σn ≈ 2.2`、`pos ≈ 0`——**这就是 DO 今天真正买到的东西。**

要一并记下来的：

- 三种工况的 DO 组合和 `pos`，各自抄一行
- 从 `LOST` 到 `STOP` 实测过了多久（该是 500ms 上下；差得多就是 `loop()` 被别的东西拖慢了）
- 把纸抽走再慢慢推回来，看它停稳之后能不能自己恢复 `FOLLOW`，恢复前等了多久（该是 300ms 上下）
- 停在丢线边界上（±45 站附近）DO 有没有抖——抖就是迟滞太小，或者黑条边缘离最外那颗管子太近

## 七、与《逐日指南》的出入

| 指南 | 实际 | 为什么 |
|---|---|---|
| "五路全部超阈值（全白）或全部未超（全黑）" | 照做，并且先量出每路的阈值落在哪 | 指南没说阈值怎么定。电位器没有刻度，"转到差不多"没法复现也没法判断对错，`t` 命令把翻点测出来才有判据 |
| "丢线时沿用 Day 24 的状态机思路" | 三状态 `FOLLOW`/`LOST`/`STOP`，另加 300ms 恢复消抖 | Day 24 是四状态避障；今天没有轮子，动作只剩"保持 `pos`、记时长、超时停并上报"，所以状态更少 |
| "测三种工况" | 三种都测，其中"静止无纸"用抬离桌面而不是裸桌面 | Day 33 已经立过规矩：桌面有纹路有色差，不是可信基准 |
| 引脚没指定 | 五路 DO 取 GPIO1/13/14/21/47 | 纯数字脚，只躲 strapping / 未引出 / JTAG / USB / 已占用，数剩下正好五个 |
