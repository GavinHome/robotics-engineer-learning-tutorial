# Day 34 — 黑白判定与丢线处理

第 2 周第 4 天。昨天五路 AO 合成一个 `pos`，横扫一圈单调、中间准。但 `pos` 有个致命盲区：**三种"根本没有线"的情况，它全部读出 0，也就是"线正在正中间"。** 今天决定"看不见线"时车该怎么办——指南说这件事比 P 参数更容易翻车。

## 一、`pos` 会在什么时候撒谎

拿昨天实测的标定表（白 1425~1672、黑 3719~3802）配 Day 32 的悬空读数（~2550）算一遍：

| 工况 | 每路 n | Σn | Σ(w·n) | `pos` | 车会怎么想 |
|---|---|---|---|---|---|
| 压线（0 站） | 0 0 1 0 0 | 1.0 | 0 | **0** | 线在正中间（对） |
| 全白（偏出阵列） | 0 0 0 0 0 | 0 | 0 | 兜住了 | 没线（对，靠 `SUM_MIN`） |
| **全黑** | 1 1 1 1 1 | 5.0 | **0** | **0** | **线在正中间（错）** |
| **悬空无纸** | ~0.45 ×5 | ~2.2 | ~0 | **≈0** | **线在正中间（错）** |

两种错法根子是同一个：**权重 `w = −2/−1/0/+1/+2` 加起来恰好是 0。**

- **全黑**：五路 `n` 全是 1，`Σ(w·n) = 0`、`Σn = 5`，`pos = 0`。阵列盖在一大片黑上（冲出赛道、压到 ② 全宽黑块），车认定自己完美对准。
- **悬空**：更阴的一种。什么都没有时 AO ≈ 2550——**正落在白（~1500）和黑（~3800）中间**。于是每路 `n ≈ 0.45`、`Σn ≈ 2.2`，从昨天那个拍出来的 `SUM_MIN = 0.5` 旁边大摇大摆走过去。车被抬起来、冲过桌面缺口、骑到反光地砖上，都会得到"线在正中间、放心开"。

`SUM_MIN = 0.5` 只堵住"全白"一种，而且本身是拍出来的数。所以今天换判据。

## 二、DO 上场

模块的 DO 是 AO 过了 LM393 比较器之后的电平，板上那颗 **104 电位器就是调它阈值**的。Day 32 只要 AO 是因为要看黑白灰的渐变；今天要回答"线还在不在"。分工就此定下来：

> **DO 只回答"在不在"，AO 才回答"在哪"。** 位置值继续用 AO 加权质心，DO 只做闸门。

### 接线：昨天的线一根不动，只加五根 DO

| ESP32-S3 | 接到 | 说明 |
|---|---|---|
| 3V3 / GND | 五路 VCC / GND | 昨天那两根，不动 |
| GPIO6 / 7 / 8 / 2 / 3 | #0~#4 AO | 昨天那五根，不动 |
| **GPIO1** | **#0 DO** | 最左那颗 |
| **GPIO13** | **#1 DO** | |
| **GPIO14** | **#2 DO** | |
| **GPIO21** | **#3 DO** | |
| **GPIO47** | **#4 DO** | |

**⚠️ DO 的 0~4 必须和 AO 的 0~4 是同一批模块、同一个左右顺序。** 接反一路，那一路的黑白就和别的路反着来，五路 DO 的组合全是乱的，而且表面上看不出来——只会得到一堆说不通的丢线。

这五个脚是这么剩下的：0/3/45/46 strapping、22~37 在 WROOM-1 上没引出或归 Flash/PSRAM、38 彩灯、39~42 JTAG、43/44 USB 串口、48 板载彩灯、4/5 超声波、10~17 TB6612、18 舵机、8/9 MPU-6050、2/3/6/7/8 五路 AO——扣掉正好五个。GPIO1 是拆掉 Day 12 电位器、Day 31 按键后空出来的，这个板子用过，确定能当数字输入。

DO 脚开内部上拉（`INPUT_PULLUP`）：LM393 输出是集电极开路，模块板上那颗上拉万一没焊，脚就浮空。

### 极性不猜，标定时顺手记下来

哪一级电平代表"压线"，不同板子不一样，说明书不写。所以标定的时候**连 DO 一起采**：按 `c` 记五路 DO 在白底上的电平，按 `b` 记在黑底上的电平。两者不同，极性自己浮出来；两者相同，说明这颗电位器根本没把黑白分开——`w` 表最后一列直接给这个判定。

## 三、阈值定在哪：量出来，不靠"转到差不多"

靶心：**第 i 路阈值 = (white_i + black_i) / 2**，离白离黑各半个量程。但电位器没有刻度，"转到差不多"没法复现也没法判断对错。所以 `t` 命令把阈值**测**出来：

1. 按 `t`，固件进量测模式，20ms 一帧（比正常的 100ms 快，别错过翻转那一刻）。
2. 把纸从 ① 白底区**慢慢**横扫过 ② 全宽黑块，再扫回来，两个来回。一颗管子 1 秒左右。
3. 每路 DO 翻转时固件当场记下那一刻的 AO：
   ```
   [teach] 路 0  DO 白→黑 @ AO 2681
   [teach] 路 0  DO 黑→白 @ AO 2596
   ```
4. 按任意键收表。

原理一句话：**DO 翻转的那一刻，AO 正好等于比较器的阈值。** 两个翻点之差就是 LM393 自带的**迟滞**——迟滞大意味着黑白交界处有一段 AO 读数两种答案都对，线半压一颗管子时 DO 会抖。Day 24 避障那对 15/25 双阈值，在这里是白送的，只是没法调。

判定列四种，逐个对应一种错法：

| 判定 | 含义 |
|---|---|
| `阈值掉到白底以下，永远报黑` | 白纸上也报压线，五路全黑，一直丢线 |
| `阈值顶到黑底以上，永远报白` | 黑块上也报没压线 |
| `偏低 N 码（n=0.xx），往上调` | 阈值偏白侧。n 越小，"压线"覆盖的灰度带越宽 |
| `偏高 N 码（n=0.xx），往下调` | 阈值偏黑侧。真压线时 DO 可能还不认 |
| `OK（n=0.xx）` | 阈值离靶心不到 1/6 量程 |

**`已分开` 不等于 `阈值在中间`。** 这是今天最容易搞混的一处：`w` 表最后一列只比对 `DO白` 和 `DO黑` 两个电平，只要电位器的翻转点**不恰好等于白底或黑底**，它就写"已分开"。而那个区间宽 2000 多码——阈值贴在白底旁边（n=0.1）、贴在黑底旁边（n=0.9）、正在中间（n=0.5），**三种情况全都显示"已分开"**。所以"已分开"只是最低门槛：说明这颗电位器确实调过、极性没接反；阈值具体调到哪，只有 `t` 知道。实测五路全是"已分开"，而五路的 n 全在 0.1 附近（见 §六）。

在 AO 上比大小一样能做二值化，还能精确放到中点、跟着标定值自动更新。今天用 DO 是另外两条理由：**不占 ADC、不占 CPU**（五次 `digitalRead` 比五次 `analogRead` 加归一化便宜一个量级），**阈值固定在硬件里**，不依赖白底表还准不准。代价是不可编程、每颗要单独转、要提防接反；Day 35/36 的控制量继续用 AO 的 `pos`，这个代价不咬人。

## 四、丢线状态机

```
FOLLOW ──五路全白 or 五路全黑──▶ LOST ──又看见线──▶ FOLLOW
  │                                │
  │                                └──连续丢线 500ms──▶ STOP ──连续看见线 300ms──▶ FOLLOW
```

| 状态 | 动作 | 彩灯 |
|---|---|---|
| `FOLLOW` | `pos` 照算，方向照给 | 绿=居中 / 红=偏左 / 蓝=偏右 |
| `LOST` | **`pos` 保持上一帧**，只记丢线多久 | 白 |
| `STOP` | 停，不再输出方向；每秒再上报一次 | 红闪（250ms） |

**① "全黑"和"全白"一样是丢线。** 这是昨天 `SUM_MIN` 漏掉的半边。五路全压线时分两种：真的一大片黑（冲出赛道），或五颗管子全盖在同一根粗线上——后者 `pos` 恰好 0，车会笔直扎进去。

**② 500ms 是这么来的。** 车大约 300mm/s，100ms 挪 30mm。"线抖了一下"只丢一两帧（100~200ms），"真冲出赛道"是永远，500ms 落在两者中间。**这个数今天是推理出来的，Day 35 装车量到真实速度必须回来重定。**

**③ 从 `STOP` 恢复要连续看见线 300ms。** 否则车停在丢线边界上，DO 一抖就 `FOLLOW`、一抖又 `STOP`，来回抽搐。Day 24 那个强制前进 300ms 的 `COMMIT` 是同一个思路。

## 五、上机步骤

模块的高度、间距、对齐和昨天完全一样，**测试纸还是昨天那张定位版**，不用重打。

1. 加五根 DO 线。上电前万用表通断档确认五路 VCC/GND 没短路，**再确认 0 号在最左、AO 和 DO 没接反**。
2. 烧录，打开串口监视器（115200）。纸放到 **① 白底标定区**，按 `c`；推到 **② 全宽黑块**，按 `b`。**先看 `w` 表最后一列——五路都得"已分开"**，哪路"没分开"就是那颗电位器没调或接错了。但"已分开"只是最低门槛：它只说阈值没掉出 [白, 黑] 这个宽 2000 多码的区间，**不说阈值在中间**，n=0.1 和 n=0.5 都显示"已分开"。
3. 按 `t`，**先确认串口冒出三行 `[teach]` 提示**——没冒出来就是没进量测模式，后面的表全是空的。进了就在 ① ② 之间慢慢横扫两个来回，按任意键收表。五路判定都该是 `OK（n=0.xx）`，xx 在 35~65 之间。报"偏低/偏高"的，按它给的码数转那颗电位器再按 `t` 重来——**转之前先记下现在转到哪了**，104 电位器一圈三百多度，转晕了回不去。
4. 按 `p` 开曲线模式，串口绘图器看 `pos` 和"压线路数×250"两条线。横扫时压线路数在 0~5 之间起伏、`pos` 平滑走；**`pos` 塌到 0 而压线路数是 0 或 5 的那一刻，就是丢线**。
5. 测工况（下节）。其中"压线居中"要用定位版的第 9 站：拿模块沿那根竖条左右慢慢推，五路 DO 应该只有 2 号亮（`[0 0 1 0 0]`），`pos` 从负穿过 0 到正。每换两三个站位回 ① 区按 `w` 核对，白底 3 分钟能漂 250 个码，漂了重按 `c`，黑底跟着重按 `b`。

五路 `DO白=0`、`DO黑=1`，极性一致，**没有接反**。量程 2126~2334，和昨天 2200 上下的估计对得上。

#### 量程多少算正常

**2000~2400 是正常值**，实测两轮分别落在 2126~2334 和约 1971~2225。但要说清楚：量程只回答"黑白拉得开不开"，**不回答"阈值调到哪了"**——量程 2200 完全正常，阈值照样可以偏在 n=0.10，这次五路正是这样。判定"符合要求"看的还是 `t` 的 `OK（n=0.35~0.65）`。

量程能告诉三件事：

**① 五路量程要互相接近。** 相差不超过三四百码，说明五颗管子高度一致、对齐没歪。某一路明显小一截，就是那颗的问题：脏了、高了、或者老了。

**② 黑底不能打到 4095。** 4095 是 ADC 天花板，打满说明真实黑值比 4095 还高，这时候算出来的靶心偏低，会照着个假中点去调。第一轮那张表五路黑底全是 4095，那是 `b` 还没按、固件用默认占位值，不是真测到 4095；按了 `b` 之后是 3784~3875，没饱和。

**③ 量程掉到 1500 以下就要查。** 按 Day 32 的高度曲线，白底读数随高度暴涨（3cm=1499、4cm=2145、5cm=2705），黑底基本不动（≈3800）。所以模块一抬高，白底就往黑底贴，量程被直接压缩——5cm 时只剩约 1100。量程突然变小，先量高度，再看纸够不够黑、管子脏不脏。

漂的也基本都是白底：两轮之间白底从 1578/1658/1499/1596/1675 变成约 1701/1828/1666/1666/1741（路1 涨了 170 码），黑底只动了十几码。**量程的变化几乎全是白底贡献的，所以每轮调电位器前都要重按 `c`**，黑底可以少按几次。

#### 黑白之间该是个什么关系

没有固定比例。两轮实测的 black/white 比值是 2.1~2.5，但这是结果不是规律，换个高度、换张纸就变了。该看的是**量程**——因为阈值住在量程中间，DO 这个闸门能干的全部事都被量程框住：量程 2000 时中点两侧各 1000 码，量程 1000 时各 500 码。而白底 3 分钟能漂 250 码，量程 1000 时一次漂移就吃掉半个余量，`OK` 判定（离靶心不超过 1/6 量程）根本守不住。所以"白 = 1000 时黑该在 3000~3400"，指的是量程 2000~2400，不是某个比值。

更实用的一条：**黑底基本不动，白底才是变量。** 两轮之间白底动了 +66~+170 码，黑底只动 +12~+53；再叠上 Day 32 的高度曲线（白底 5cm=2705、4cm=2145、3cm=1499、2cm=527，一路能跑两千多码），白底是唯一在大幅移动的那个。所以给定黑底被按在 ≈3800 附近：

> **量程 2000~2400 ≡ 白底落在 1400~1800**

后者才是该盯的数字。白底爬过 1800 = 模块高了或环境光亮了 = 量程在缩；白底掉到 1400 以下 = 模块贴太近，量程变大，这个方向不伤身，但五路高度容易不一致。黑底只要没打到 4095（ADC 饱和）就不用管。

#### 差几百码为什么就不能用

"偏低 800 码"听着像个精度问题，其实不是——**它把裕量全挤到了会漂的那一侧**。拿路0 算（白 1578、黑 3867、阈值 1899）：

| | 离白 | 离黑 |
|---|---|---|
| 阈值 1899（现在） | **321** | 1968 |
| 阈值 2722（中点） | 1144 | 1145 |

中点是把裕量对半分的**唯一**选择：事先不知道哪侧会漂，对半分就是让最坏情况最大的那个解（maximin）。偏 800 码等于押注"白底漂不过 321 码"，而这个注已经输了——日志里路4 `raw 2031` 就报了压线，它白底才 1675，只高了 356 码，**一片浅灰就被当成了线**。

白底能漂多少是实测的，不是估计：两轮标定之间白底动了 +66~+170 码；Day 32 的高度曲线更狠，白纸 3cm=1499、4cm=2145，**模块抬高 1cm 白底涨 646 码**。所以阈值 1899 配上 4cm 高度，白纸上 AO 直接顶穿阈值 → 五路全报"有线" → 丢线停车，日志里那段 `raw 2000~2100` 正是这么停的。

至于"五路全都差几百码，是不是别的原因"：同型号同批次的模块电位器都停在出厂位置，就会长这样。但五颗的值没挤在一起（1853/1867/1900/1927/1977 散了 110 码），**撞同一个电气上限会堆在同一个数上**，所以不是量程不够，是五颗各自都没拧够。

反过来，几百码的偏差**有**能用的时候：高度锁死、光照固定、纸固定，白底只漂几十码，那离靶心偏 300 也够用。所以判据不该写成"离靶心 ±1/6 量程"，该写成**"离白底至少留够白底可能漂移的几倍"**。今天那个 1/6 量程只是它的一个代理值——换算过来就是"离白底 ≥ 1/3 量程"，这样写意思更准，因为靶心会跟着白底跑，白底才是变量。

### 电位器实际阈值：五颗全部偏低约 800 码

`t` 一共扫出 43 个翻点。**DO 翻转那一刻的 AO 就是阈值**，两个方向合起来取中位数：

| 路 | 翻点数 | 实测阈值 | 靶心 | 偏低 | n |
|---|---|---|---|---|---|
| 0 | 11 | 1899 | 2722 | **823** | 0.14 |
| 1 | 7 | 1853 | 2721 | **868** | 0.09 |
| 2 | 7 | 1900 | 2666 | **766** | 0.17 |
| 3 | 10 | 1933 | 2735 | **802** | 0.15 |
| 4 | 10 | 1964 | 2752 | **787** | 0.13 |

换新版固件后又量了一轮，五路中位数 1920/1867/1927/1977/1977，和上表只差 13~44 码——**"偏低 800~950 码"这个结论是稳的**。但那轮的散布到了 476~1011（上一轮只有 30），中位数可信、单个翻点已经不能看，原因就是扫得太快。

#### "往上调"不是物理方向

判定列写的"往上调"指的是**让阈值这个数字变大**（1920 → 2796）。电位器往哪个方向转能让它涨，固件不可能知道——104 电位器三根线怎么接、焊在板子上什么朝向，每块板都不一样。所以方向要试出来：

1. 先记住路0 电位器现在转到哪了（拍照，或记槽口朝向）。
2. 转一个明显的量，约 45°，一个方向。
3. 按 `t` 重扫，只看路0 的"实际阈值"：比上次大就是方向对，小就反过来。

五块是独立的板，理论上不保证同向，但通常是同一种焊法，一颗试出来基本都能用。欠的码数占量程 35~42%，别一次转到位，分三四次、每次约 40°，转完重扫看"偏低 N 码"缩到多少。转过了（阈值冲到黑底以上）会变成"永远报白"，能发现、能转回来，没有硬件风险。

#### 调之前先重新标定

两轮 `t` 之间靶心从 2722/2721/2666/2735/2752 漂到 2796/2813/2755/2778/2812，涨了 43~92 码；反推路1 的白底已经从 1658 漂到约 1828，阈值 1867 只比白底高 39 码。所以每轮调整前都按 `c` 再按 `b`，让靶心是新鲜的，否则会照着个移动的靶子调。

**五颗全落在 n = 0.09~0.17 而不是 0.5**，而 `w` 表五路全都写着"已分开"。这两件事同时成立，就是 §三 那条提醒的实证。后果在日志里到处都是：

```
[0 0 0 0 1] n=1 | raw 1397 1551 1544 1869 2031 | pos  +737 停车
```

路4 raw 2031，只比白底 1675 高 356 码（n≈0.17），DO 已经说"压线"。**一片浅灰就被当成了线。** 更要命的是这段：raw 一直 2000~2100（白纸上空约 4cm，Day 32 曲线上 4cm=2145），五路 DO 全报压线 → `n=5 全黑` → 丢线 → 停车。**模块悬在白纸上空 4cm，被判成"盖在全宽黑块上"。**

#### 拧了十几次，读数为什么不动

反馈"第一个（路0）怎么调都达不到要求"。但数据上**不是路0 一路坏，五路全一样**：偏低 766~868 码，路0 的 823 还是五路中间那个。所以先别看"哪一路偏"，看"读数动没动"。

新版固件那两轮 `t` 之间，五路阈值只走了 1899→1920、1853→1867、1900→1927、1933→1977、1964→1977，全部只有 13~44 码；同一段时间靶心自己涨了 43~92 码。**两个数字一样大**——拧 1/4 圈电位器本该是几百码的变化，十几下只换来 20 码，说明调整基本没落到读数上：要么每次只蹭了一点点，要么拧到了机械尽头，要么拧的不是管这条路的那颗。

分开这三种原因只要一个动作：把路0 那颗电位器拧到一头，按 `t` 记下"实际阈值"；再拧到另一头，按 `t` 再记一次。这两个数就是这颗电位器的**真实量程**，和靶心一比就知道属于哪种：

| 两头读数 | 原因 | 怎么办 |
|---|---|---|
| 两个数一样 | 拧错颗，或电位器虚焊/坏 | 路0 是 AO=GPIO6、DO=GPIO1，不一定是左手边那颗模块。拧另一颗，看哪个数在动 |
| 都到不了 2796 | 电位器量程不够，拧永远没用 | 这是模块分压电阻定的。改高度把中点挪进量程（见下） |
| 能跨过 2796 | 之前只是没拧够 | 按"一圈多少码"算着拧 |
| 某一头 `t` 报"掉到白底以下/顶到黑底以上" | 量程比黑白区间还宽 | 不是量程问题，是没拧够，往反方向继续 |

顺带一条手法：**一次拧 1/4 圈（90°）再 `t`，别一点点蹭。** 1/4 圈才看得出往哪边是"往上"，也才测得出一圈值多少码——要补 876 码，一圈给 1600 码就拧 0.55 圈，不用试十几次。

如果真是量程不够（电位器最高只到 2500 左右），出路是**把模块压低**：按 Day 32 曲线白底 3cm≈1500、2cm≈530，压到 2.5cm 白底约 1000，中点从 2722 降到约 2400，就落进电位器够得着的地方。但黑底在低压高度下会不会跟着变、五路高度还一不一致，都得重测——压完必须重按 `c`/`b` 再 `t`，靶心是旧的就没法判。

#### 最后是怎么过的：电位器没拧，是模块压低了

按"压低"这条路走，五路判定全 `OK`：

| 路 | 白底 | 黑底 | 量程 | 靶心 | 实测阈值 | n |
|---|---|---|---|---|---|---|
| 0 | 1016 | 2956 | 1940 | 1986 | 1701 | 0.35 |
| 1 |  765 | 3386 | 2621 | 2075 | 1887 | 0.42 |
| 2 |  535 | 3482 | 2947 | 2008 | 1939 | 0.47 |
| 3 |  829 | 3522 | 2693 | 2175 | 1931 | 0.40 |
| 4 |  875 | 3244 | 2369 | 2059 | 2057 | 0.49 |

但真正该看的是**电位器到底动没动**。三次 `t` 的实测阈值排在一起：

| 路 | 3cm 第一轮 | 3cm 第二轮 | 压低后 |
|---|---|---|---|
| 0 | 1899 | 1920 | 1701 |
| 1 | 1853 | 1867 | 1887 |
| 2 | 1900 | 1927 | 1939 |
| 3 | 1933 | 1977 | 1931 |
| 4 | 1964 | 1977 | 2057 |

三轮全部落在 50 码以内，而同一段时间白底从 1578~1675 掉到 535~1016、黑底从 3784~3875 掉到 2956~3522。**阈值几乎没动，动的是白黑两条线。** 所以"拧了十几次没反应"不是电位器量程不够，是那十几次根本没拧到这颗电位器上（拧错颗、或每次只蹭了一丝）。之前"五颗全部偏低 800 码"的结论要改口径：不是电位器坏了，是**模块太高，把中点抬到了 2700 以上，而电位器停在出厂位置约 1900**。压到约 2cm，白底掉到 535~1016，中点降到 2000~2175，正好落进电位器现有范围，一颗都不用拧。

代价是量程散开了：3cm 时五路量程 2126~2334（相差 208），压低后 1940~2947（**相差 1007**）。原因是这个高度上读数对高度极敏感——Day 32 曲线上 2cm=527、3cm=1499，1cm 就差 972 码，五路高度差一丝就被放大成几百码。最弱的是路0：量程 1940 最小，阈值 1701 离白底只剩 685 码；按 2cm 附近的斜率，1mm 高度误差约 100 码，**路0 只有 7mm 的高度容差**。Day 35 装车一震就可能越界，然后路0 开始误报"压线"。

这一轮散布 310~554（上一轮只有 30），说明扫得偏快，中位数可信但单个翻点不能看。

#### 旧固件的判定会放行三路

拿这套实测数算**改版前**的判据（离白或离黑不到 300 码才算不合格）：

| 路 | thr | 离白 | 旧判定 | 实际 |
|---|---|---|---|---|
| 0 | 1899 | 321 | **OK** | 偏低 823 |
| 1 | 1853 | 195 | 余量不足 | 偏低 868 |
| 2 | 1900 | 401 | **OK** | 偏低 766 |
| 3 | 1933 | 337 | **OK** | 偏低 802 |
| 4 | 1964 | 289 | 余量不足 | 偏低 787 |

**三路拿 `OK` 放行。** 300 码在 2200 量程里只占 14%，这个门槛抓不住 n=0.15。现在改成看**离靶心多远**：允许偏 1/6 量程（n 偏离 0.5 不超过 ±0.167），超了直接报"偏低 823 码（n=0.14），往上调"——连偏多少、往哪边转一起给出来。

#### 扫快了，翻点会跑偏几百码

路0 出现 `黑→白 @ 1660` / `白→黑 @ 2212` 这一对，和其余 9 个（1879~1909）差 240~310 码。原因是量测模式 20ms 一帧：**AO 在两次采样之间就穿过了阈值**，记录到的是穿越后那一帧的值，所以下落时记偏低、上升时记偏高。两者平均 `(1660+2212)/2 = 1936` 倒还落在 1900 附近，但单拿这一对当迟滞就会报出 552——而真实迟滞只有 5 码左右（看 `1903→1908`、`1853→1853` 那些对）。

所以固件改成**收集全部翻点取中位数**，离群点拉不动结果；表里"散布"列报最大翻点减最小翻点，慢慢扫应该只有几十码（那才是 LM393 自带的迟滞），到几百码就说明那一轮扫快了、这一行的阈值别太当真。

第一轮 `t` 没跑成的原因是固件只认小写 `t`，串口监视器里按大写 `T` 静默无响应，一个字都不回。已改成大小写都认——**但更该记住的是这个教训：交互命令没有回音，就等于没有执行**，后面所有的表都可能是空的。

四种工况到此全通了。做法是拿模块沿第 9 站那根竖条左右慢慢推（普通模式，不开 `t`）：五路 DO 全程 `[0 0 1 0 0]`——**只有 2 号压线，`n=1`**，`pos` 从 −114 连续走到 +64，在 `[0 0 1 0 0]` 中间穿过 0。

`[0 0 1 0 0]` 而不是 `[1 1 1 1 1]`，正是 §一 那张表的第一行：8mm 的条配 15mm 间距，条心压在阵列中点时只有 2 号盖得住，1 号和 3 号中心离条边 11.5mm，一根都亮不起来。所以"压线居中"和"压大片黑"的 DO 组合天生不同，`n=5 全黑` 那条丢线判据不会把它误吃。

同一张纸、同一个 ① ② 区，白底不可能自己涨 1300 码。按 Day 32 曲线（白纸 2cm=527、3cm=1499、4cm=2145）反推，这几路的实际高度已经是 2.3cm（路0/3/4）到 3.2cm（路2）——**压低那一轮的高度没能保持住，五路现在不在一个平面上**，路2 最高。后果直接写在余量列里：路2 白侧只剩 88 码、黑侧 53 码，合起来 141 码的窗口。按 Day 32 的斜率（2~3cm 约 970 码/cm），**1.4mm 的高度误差就能让路2 在白纸上误报"压线"**。所以最弱的那一路不是标定时判的路0（685 码），是路2。

## 七、与《逐日指南》的出入

| 指南 | 实际 | 为什么 |
|---|---|---|
| "五路全部超阈值（全白）或全部未超（全黑）" | 照做，并且先把每路阈值落在哪量出来 | 指南没说阈值怎么定。电位器没有刻度，"转到差不多"没法复现也没法判断对错，`t` 命令测出翻点才有判据 |
| "丢线时沿用 Day 24 的状态机思路" | 三状态 `FOLLOW`/`LOST`/`STOP`，另加 300ms 恢复消抖 | Day 24 是四状态避障；今天没有轮子，动作只剩"保持 `pos`、记时长、超时停并上报"，所以状态更少 |
| "测三种工况" | 全白 / 全黑 / 悬空 / 压线居中四项全通，压线居中是补测的 | 第一轮横扫做成了上下提拉模块，纸没在阵列下横向动；改成沿定位版第 9 站横推，`[0 0 1 0 0]`、`pos` 穿过 0 |
