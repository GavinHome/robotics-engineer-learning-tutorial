## 第1周：中断与循线机器人（Day 31-38）

### Day 31：中断——反应计时游戏
**目标**：理解轮询和中断的区别；编码器读数必须用中断，今天先把中断吃透

**任务**：
1. 用现有件搭反应计时：按键 + 外接 LED（GPIO2）
2. LED 随机延迟后亮起（`random()` 加 `randomSeed(analogRead(...))`），按键停止计时，毫秒级输出到串口
3. 按键用 `attachInterrupt()` 边沿触发，**不用** `digitalRead()` 轮询
4. 记录"轮询版"和"中断版"的最短可测反应时间差异

**代码参考**：
```cpp
const int BTN = 1;
const int LED = 2;
volatile bool pressed = false;
unsigned long t0, t1;

void IRAM_ATTR onPress() { pressed = true; }  // ESP32 中断处理函数必须在 IRAM

void setup() {
  Serial.begin(115200);
  pinMode(BTN, INPUT_PULLUP);
  pinMode(LED, OUTPUT);
  attachInterrupt(digitalPinToInterrupt(BTN), onPress, FALLING);
  randomSeed(analogRead(1));
  delay(random(2000, 5000));
  digitalWrite(LED, HIGH);
  t0 = millis();
}

void loop() {
  if (pressed) {
    t1 = millis();
    digitalWrite(LED, LOW);
    Serial.printf("reaction = %lu ms\n", t1 - t0);
    pressed = false;                 // 清标志
    delay(200);                      // 消抖
    delay(random(2000, 5000));
    digitalWrite(LED, HIGH);
    t0 = millis();
  }
}
```

**要弄清的三个坑**：中断里不能 `Serial.print` / `delay`；共享变量要 `volatile`；ESP32 的中断处理函数要加 `IRAM_ATTR`。

**输出**：两个版本的最短可测反应时间对比 + 中断三坑的记录

### Day 32：TCRT5000 数据手册与单个读数
**目标**：照第 1 月 Day 17 的老办法——先读手册，再接线

**任务**：
1. 读 TCRT5000 规格：发射管恒流、接收管对 650nm 红外敏感；**黑色吸光 → 反射弱 → 接收管电流小 → 输出低**；白色反之
2. 单模块接线：VCC 3.3V/5V、GND、AO → ADC 脚、DO → GPIO（先用 AO，模拟量能看出渐变，不急着二值化）
3. 分别正对黑线、白底、抬起离桌面 5cm，记录三段 AO 值
4. **离桌面 5cm 的读数最关键**——它决定了车会不会因为颠簸误判；不行就降高度或加遮蔽

**输出**：黑 / 白 / 悬空三段 AO 值表 + 模块固定高度结论

### Day 33：五路与位置值
**目标**：从 5 个数变成 1 个"线在哪"的数

**任务**：
1. 五个模块并排装到底盘前缘，间距 ≤ 线宽；先不装车，在工作台上跑
2. 每个读 AO 并各自标定黑白阈值（**逐个标定**，五个体制不会完全一样）
3. 合成位置值：加权质心 `pos = Σ(weight_i × value_i) / Σ(value_i)`，中点为 0
4. 用一张画了黑线的纸手动横扫，看 `pos` 是否从 −1000 平滑走到 +1000

**输出**：`pos` 标定曲线 + 五个模块各自的阈值

### Day 34：黑 / 白判定与丢线处理
**目标**：决定"看不见线"时车该怎么办——这件事比 P 参数更容易翻车

**任务**：
1. 设定丢线条件：五路全部超阈值（全白）或全部未超（全黑）
2. 丢线时先沿用 Day 24 的状态机思路：维持上一帧方向 + 记丢线时长
3. 丢线超过阈值就停并上报，而不是继续乱转
4. 测三种工况：压线 / 偏出 / 静止无纸，确认判定不打架

**输出**：丢线判定逻辑 + 三种工况的实测结果

### Day 35：开环巡线
**目标**：先不用控制律，让车跟着 `pos` 走，看清"哪偏哪纠"的方向对不对

**任务**：
1. 五个模块 + 底盘 + TB6612 在这天成车；`pos < 0` → 左偏 → 左轮减速（或右轮加速）
2. 用固定 duty 差，不用 `map()` 调光那套线性假设——车轮的响应是非线性的，今天先把方向搞对
3. 录一段直道 + 一个 90° 弯，看它在哪里丢线
4. 记录"开关逻辑"最明显的毛病：到线附近来回摆

**输出**：开环巡线视频 + 丢线位置记录

### Day 36：P 控制
**目标**：把方向误差变成连续的转向量——这也是本项目第一个闭环

**任务**：
1. `turn = Kp × pos`，映射到左右轮 duty 差
2. `Kp` 从小到大试 5 档，每档录一段；预期小 `Kp` 修正无力、大 `Kp` 来回摆
3. 找出"能跟上但不摆"的 `Kp` 作为工作点
4. 加基础前进 duty 与转向 duty 分离：**前进量不能随误差消失而停**，否则车会踉跄

**输出**：5 档 `Kp` 的现象表 + 选定的工作点

### Day 37：加入 D 项
**目标**：完成原始计划的"P 之后加 D"，让摆振停下来

**任务**：
1. `d = Kd × (pos − pos_prev) / dt`，只对**误差的变化率**起作用
2. D 项单独试：只要 D、不要 P，看车还能不能巡线——（结论：不能，D 是阻尼不是纠偏）
3. P + D 一起调，观察摆振幅度的衰减
4. **D 项是噪声放大器**：把 AO 读数噪声与 D 项输出放一张图，说明为什么不能盲目加大 `Kd`

**输出**：仅 P / P+D 的摆振对比 + 噪声放大证据

### Day 38：第 1 周项目——调参对比视频
**目标**：完成原始计划明确要求的"拍摄调优不佳和调优正确的对比视频"

**任务**：
1. 同一段赛道，录三段：开环 / P 过大 / P+D 调好
2. 三段用同一速度、同一电池，保证可比
3. 用 ffmpeg 压成 GIF 或裁成 15 秒，命名清晰
4. 写进 `day-38/README.md`：每个参数的现象、最终取值、**为什么是这个值**

**输出**：三段对比视频 + 调参与取舍记录

## 第2周：MPU-6050 → 可信角度（Day 39-40）

> 原计划这里排 7 天（Day 39-45）。压缩依据：MPU 在平衡车里只干一件事——给角度环一个不漂移的俯仰角。围绕这一件事组织两天、一天一个 README；原 Day 43（Python 可视化）与 Kalman 挪进阶。

### Day 39：裸读 + 校准
**目标**：不装库、照数据手册把 MPU-6050 读准、校准平——"可信角度"的地基，一个 README 收掉

**实验 1：裸读 I2C**（原 Day 39）
1. 手册只查三件事：`WHO_AM_I`（0x75，应回 0x68）、`PWR_MGMT_1`（0x6B，写 0 唤醒）、加速度配置寄存器（0x1C，选 ±2g）
2. 用 `Wire` 直接读，**不引入 Adafruit_MPU6050**；先读 `WHO_AM_I` 校验地址没错再往下
3. 换算：±2g 量程 16384 LSB/g；与第 1 月用库读出的值逐位对比

**实验 2：零偏与标度**（原 Day 42）
1. 静止采样 2000 次求均值 → 零偏写进常量 → 平放读数归零
2. 竖放 / 倒放验标度（应为 ±90°）
3. 记录"不校准自平衡车会怎么表现"——静差会让车永久偏向一侧

**输出**：裸读 vs 库读对比数据 + 校准前后静止零位表 + 竖放 90° 验证

### Day 40：互补滤波 → 静止 60 秒漂移 < 1°
**目标**：先看两种失效，再一次调完 α，当天验收

**实验 1：两种失效模式**（原 Day 40）
1. `pitch = atan2(-ax, sqrt(ay²+az²))` 静止 60 秒曲线——加速度计静止也在飘
2. 陀螺仪积分 `pitch += gyr_y × dt` 静止 60 秒曲线——短时准、长时单向漂
3. 两条曲线放一张图：这就是"必须融合"的实感证据

**实验 2：互补滤波 + 定 α**（原 Day 41 + 44）
1. `angle = α × (angle + gyr × dt) + (1 − α) × accel_angle`
2. α 四档（0.90 / 0.95 / 0.98 / 0.995）**一次调完**：各 60 秒静止 + 一次 30° 抬手
3. 验收：三种姿态（平放 / 微倾 / 手持微抖）静止 60 秒最大偏离 < 1°；不过就查零偏、`dt` 是否用 `millis()` 差值、α 选错

**输出**：失效对照图 + 四档 α 的静止漂移与动态延迟表 + 验收数据

## 第3周：编码器 → 可信转速（Day 41-42）

> 原计划 6 天（Day 46-51）。编码器在平衡车里只干一件事——给速度环一个不受电池电压影响的转速。同样两天收掉；原 Day 50（位置环 + I 项 + 精确转一整圈）是月度里程碑原话，挪进阶，平衡车站稳后补半天即可。

### Day 41：认识编码器 + 脉冲→转速
**目标**：从"这是什么"到"能读出可信的 rpm"

**实验 1：从脉冲到角度**（原 Day 46）
1. 读所购编码器电机规格：**每转脉冲数（ppr）× 减速比 = ticksPerRev**，分清"电机侧"和"轮子侧"
2. A/B 两相接线（上拉），A 相 `RISING` 中断计数；电机仍由 TB6612 驱动
3. 手把轮子精确转一圈，核对计数与标称值 ×3 次——不吻合就是倍频/减速比理解错了

**实验 2：从脉冲到转速**（原 Day 47）
1. B 相判向：`ticks` 可正可负，正转 +1、反转 −1
2. 差分采样算 `rpm = ticks差 / ticksPerRev × 60 / 采样间隔秒`（不用累计值）
3. 同 duty 测 3 次看离散度；分辨率下限 = `60 / ticksPerRev / 采样间隔`，想清楚它由什么决定

**输出**：手转一圈核对表 ×3 + rpm 离散度 + 分辨率结论

### Day 42：开环为什么不可靠 + P 速度环
**目标**：先量化开环的病，再用闭环治好它

**实验 1：占空比 ≠ 转速**（原 Day 48）
1. 固定 duty 记 rpm，扫 duty 100→255 画曲线
2. 换一节电压不同的电池（或串电阻模拟压降）重扫一遍
3. 两条曲线一张图：**同一 duty 下转速随电压变化**——开环调速不可靠的量化证据；找出明显偏离线性的 duty 区间

**实验 2：P 速度环**（原 Day 49 + 51）
1. 增量式 `duty = duty_prev + Kp × error`，采样 100ms（`dt` 用 `millis()` 差值），duty 夹 0–255
2. `Kp` 从小到大阶梯，**一次调完**，记录过冲/振荡
3. **换电池再测：目标转速守不守得住——闭环的意义在这一刻才成立**
4. 串口指令 `f 200`（目标 200rpm）/ `s`（停）；记录闭环前后目标 200rpm 的误差对比

**输出**：两种电压的 duty→rpm 曲线 + 闭环前后误差表 + 调参记录

## 第4周：自平衡机器人（Day 43-46）

> 原计划 7 天（Day 52-58）。这是全月唯一不许压缩部分的做法：MPU 和编码器省下的天数全给"站起来"。Day 45 独占整天调角度环，站不住 30 秒就一直调——平衡车没有确定答案，调参时间不许省。

### Day 43：原理 + WiFi 遥测
**目标**：纸面想清楚 + 把遥测链路架好（平衡车拖不住 USB 线，没有遥测只能瞎调）

**实验 1：纸面想清楚**（原 Day 52 + 原 Day 45 的采样率分配）
1. 倒立摆：竖直是不稳定平衡点，**任何偏离都会自我放大**——控制和循线不同，控制的是"不要倒"不是"去哪里"
2. 两条环的职责：角度环决定要不要走，速度环决定走多快（速度环输出折算成**目标角度的偏移**）；平衡环优先级 > 位置环
3. 采样率分配：姿态 10ms 级、转速 100ms 级，写清依据

**实验 2：WiFi UDP 遥测**（新增）
1. ESP32-S3 自带 WiFi：把帧日志（angle / gyro / rpm / duty / K 值）UDP 广播出去
2. 电脑端 `nc -ul 115200` 接收存档——跑完全程再分析，不用盯着车
3. **在现有循线车上先验通**：Week 1 欠的地面跑直接复用这套遥测

**输出**：两环框图 + 输入输出表 + 遥测链路演示

### Day 44：装车 + 角度环首战
**目标**：硬件整备一次到位，然后让角度环跑第一版

**实验 1：换装与供电复核**（原 Day 53）
1. 装编码器电机 + 轮子；编码器接 Day 41 用过的脚，电机仍由 TB6612 驱动
2. **供电复核**：万用表串电池测双电机同时启动的峰值电流；6V 电池盒压降 > 0.5V 就上锂电池或加容
3. MPU-6050 装高处、近轮轴中垂面、远离电机（最大振动源）；上电前通断档查短路

**实验 2：角度环第一版**（原 Day 54）
1. `duty = Kp_ang × angle + Kd_ang × gyro`（速度环先不接）
2. 符号校对：`angle > 0`（前倾）→ 前进；先手扶小角度试探，再首松手
3. 记录失败模式：**冲出去**（Kp_ang 太小或方向反）还是**直接倒**（太大）——它指出下一步往哪调

**输出**：峰值电流实测 + 压降判定 + 第一版失败模式判定

### Day 45：让它站起来（独占整天）
**目标**（原 Day 55）：全月最难的一步，只做这一件事

1. `Kp_ang` 从极小开始，每次加一点；站不稳先查三件事：角度符号方向、`dt` 抖动、MPU 是否被电机干扰
2. 站住 5 秒记一笔，做成"能站几秒"的阶梯表
3. 到**能站 30 秒**，`Kp_ang` / `Kd_ang` 各记一个工作值
4. **有余力才接速度环**（原 Day 56）：编码器读实际转速，`Kp_spd` 折算成目标角度偏移——站桌上不跑偏

**输出**：能站立时长的阶梯表 + 两个 `K` 的工作点

### Day 46：遥控 + 月度验收
**目标**：给平衡车一个可操作的形态，然后逐条对里程碑打勾

**实验 1：遥控与整定**（原 Day 56 / 57）
1. 复用第 1 月 Day 27-28 的手机面板，只留前进 / 后退 / 停止三键
2. 三环联调：遥控指令 → 速度目标 → 角度偏移 → 电机 duty；推一下能回正

## 附录：常见问题与排障

### 编码器

**Q: ticks 数不对，差很多或差一半**
- 减速比与编码器 pp 数弄混：标称的脉冲数通常是**电机侧**，除以减速比才是轮子侧
- A 相单沿计数只拿到 1/4 分辨率：要四倍频得同时读 B 相，或在硬件上两相都中断
- 接线松动或没加上拉：GPIO 悬空在电机旁最容易乱跳，务必上拉 + 尽量屏蔽

**Q: 一开电机 ticks 就狂跳**
- 电机是巨大噪声源。编码器线远离电机线，加 100nF 去耦，或在代码里加软件滤波（连续 N 次同值才认）

**Q: 转速曲线开始振荡，duty 上下跳**
- `Kp` 过大，或采样间隔不固定。`dt` 必须用 `millis()` 差值实时算，不能写成常量

### 姿态融合

**Q: 静止也漂移**
- 零偏没校：静止采 2000 次求均值再减掉
- `dt` 用了固定值：积分项必须乘真实 `dt`
- 加速度计被振动干扰，选错 `α`

**Q: 一动就跟不上，角度迟钝**
- `α` 太低，过度信任加速度计。加速度计不该信"快"的那部分

**Q: MPU-6050 一接电机就乱**
- 电机振动通过底盘直接传到传感器。软隔离（海绵/减震垫）+ 远离电机安装

### 自平衡

**Q: 一松手就冲出去**
- `Kp_ang` 太小或角度反了。先用极小的 duty 试探方向

**Q: 站一下就开始大幅摆**
- `Kd_ang` 不足或 D 项把噪声放大了。先把陀螺仪降采样或低通，再加 D

**Q: 车能平衡但不听遥控**
- 速度环输出没接进角度目标，或速度环优先级盖过了角度环

**Q: 平衡了十几秒突然倒**
- 电池压降导致 duty 饱和，或电机持续堵转过热。看 Day 53 记的压降数据

### 焊接与调试

**Q: 焊点不牢、冷焊**
- 烙铁温度不足或焊面氧化；焊前镀锡，焊后用放大镜检查

**Q: 上电无反应**
- 万用表通断档查电源短路，这是唯一手段；别反复上电
