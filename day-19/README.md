这是第一次真正"做功"—— 前面 18 天的输出全是电平、脉冲、报文，今天输出的是**机械转动**。也是第一次遇到 GPIO 搞不定的负载，得靠驱动芯片。

## 二、为什么不能拿 GPIO 直驱电机

三个理由，一个比一个硬：

**① 电流不够。** ESP32-S3 单个 GPIO 最大持续电流约 **40mA**，整片芯片合计也才几百 mA。TT 马达空载就要 **100~200mA**，堵转时能到 **1A 以上**。差一个数量级。

**② 会烧 GPIO。** 电机是**感性负载**。电流突变时（尤其是断电瞬间），电感产生反电动势 `V = −L·di/dt`，电压尖峰可以冲到电源电压的数倍，直接击穿 GPIO 的 ESD 结构。这不是"转得慢"的问题，是**物理损坏**。

**③ 不会换向。** GPIO 只能输出 0 / 3.3V。要让电机反转，得把两端电压**对调** —— 单个 GPIO 做不到，需要两组开关交叉连接，也就是 H 桥。

> 📌 记住这个分工：**GPIO 只负责发逻辑电平（3.3V / 几 mA），大电流开关交给驱动芯片。** 后面所有"MCU 驱不动"的场景（电机、继电器、舵机、灯带）都是同一个套路。

## 三、H 桥与 TB6612FNG

### H 桥为什么能换向

四个开关接成"日"字形，电机竖在中间：

```
        VM
       ┌────┴────┐
    ┌──┴──┐   ┌──┴──┐
    │ S1  │   │ S3  │
    └──┬──┘   └──┬──┘
       │    电机   │
    ┌──┴──┐   ┌──┴──┐
    │ S2  │   │ S4  │
    └──┬──┘   └──┬──┘
       └────┬────┘
        GND
```

- 闭合 **S1 + S4**：电流从左到右 → **正转**
- 闭合 **S2 + S3**：电流从右到左 → **反转**
- 全部断开：电机两端悬空 → **滑行**（靠惯性转一会儿）
- **S1 + S2 同时闭合**（或 S3+S4）：电机两端接同一电位 → **短路制动**，转子动能被迅速耗掉 → **刹车**

**绝对不能同时闭合 S1+S3 或 S2+S4** —— 那等于把电源正负极直接短接，叫"直通"（shoot-through），瞬间大电流烧管子。驱动芯片内部有死区逻辑防这个，自己用分立元件搭桥时才需要格外小心。

### TB6612FNG 真值表

一个芯片里有两套 H 桥（A 通道、B 通道），本项目只用 A 通道。每个通道三根控制线：`IN1` / `IN2` 定方向，`PWM` 定速度。

| IN1 | IN2 | PWM | 输出 | 模式 |
|:---:|:---:|:---:|---|---|
| 1 | 0 | 1 | OUT1=H, OUT2=L | **正转** |
| 0 | 1 | 1 | OUT1=L, OUT2=H | **反转** |
| 1 | 1 | 1 | OUT1=L, OUT2=L | **刹车**（两端短接到地） |
| 0 | 0 | x | 双高阻 | **滑行**（自由转动） |
| x | x | 0 | 双高阻 | **滑行** |

> ⚠️ **"刹车"和"滑行"在中文里经常被混着说，硬件行为完全不同**：
> - `IN1=IN2=1` 才是刹车，电机迅速停住
> - `IN1=IN2=0` 是滑行，电机靠惯性再转一会儿才停
>
> 《逐日指南》的参考代码把 `AIN1=LOW; AIN2=LOW` 注释成"刹车"，实际是滑行 —— 见 §十。

### PWM 调速调的是什么

H 桥输出端不是连续可调电压，只有"通"和"断"。PWM 靠**快速开关**让电机两端得到**平均电压**：

```
duty = 180 / 255 ≈ 70.6%
平均电压 ≈ 3V × 0.706 ≈ 2.12 V
```

电机是惯性负载，5kHz 的开关频率远快于机械响应，它"感受"到的就是这个平均值。

频率不能随便选：

| 频率 | 后果 |
|---|---|
| 太低（几十 ~ 几百 Hz） | 能听见啸叫，力矩脉动明显，转速不稳 |
| **5kHz（本项目）** | 安静，MOSFET 开关损耗可接受 |
| 太高（>100kHz） | 开关损耗大、发热，还容易被线缆辐射出去干扰别的电路 |

本项目沿用 Day 10 呼吸灯的 `ledcAttach(PWMA, 5000, 8)`：**5kHz / 8 位分辨率 / duty 0~255**。

### 开环调速的局限（重要）

本项目只能做**开环**调速：代码只管发 duty，不知道电机实际转多快。

```
同样的 duty，转速却会随这些因素变化：
  • 电池电压（2 节 5 号越用越没劲）
  • 负载大小（撞到障碍物 vs 空转）
  • 两个电机之间的个体差异
```

底盘套件里的 TT 马达**没有编码器引线**（码盘要另配光电对管，套件不含），所以 Day 19 / Day 21 都只能是开环。闭环测速得加编码器，是 Day 28 前后的内容。

## 四、接线

```
        TB6612FNG 模块            ESP32-S3 / 电源
   ┌───────────────────┐     ┌──────────────────┐
   │  VM       ●───────┼─────┼── 电池盒 + (3V)  │
   │  GND      ●───┬───┼──┬──┼── GND            │
   │  VCC      ●───┼───┼──┼──┼── 3V3            │
   │  STBY     ●───┼───┼──┼──┼── 3V3            │
   │  PWMA     ●───┼───┼──┼──┼── GPIO12         │
   │  AIN2     ●───┼───┼──┼──┼── GPIO11         │
   │  AIN1     ●───┼───┼──┼──┼── GPIO10         │
   │  AO1      ●───┼───┼──┘  │  板载 RGB: GPIO48│
   │  AO2      ●───┼───┘     │                  │
   └───────────┼───┼─────────┘
               └───┴──── 电机两端（不分极性）
```

模块本体与丝印见 [`TB6612FNG-2.png`](./TB6612FNG-2.png)：`VM / GND / VCC / STBY / PWMA / AIN1 / AIN2 / AO1 / AO2` 一组是 A 通道，另一组 B 通道（`BO1 / BO2` / `BIN1 / BIN2 / PWMB`）本项目空着不接。电机实物见 [`TT马达.png`](./TT马达.png)。

三条容易踩的线：

**① GND 必须共地。** 电池负极、ESP32 GND、模块 GND 三者连到一起。不共地的话，GPIO 发出去的"高电平"在驱动芯片眼里没有参考点，整块芯片不工作。**这是今天最重要的一根线。**

模块上有多个 GND 焊盘，板内是同一个网络，电气上完全等价。手上有 ESP32 GND 和电池负极两处要连，最省事的做法是**一个 GND 引脚接 ESP32、另一个 GND 引脚接电池负极**，剩下的空着；三个全接也无害。

**② VM 和 VCC 是两路独立电源。**

| 引脚 | 接什么 | 电流 |
|---|---|---|
| **VM** | 电池盒 +（3V，只装 2 节） | 电机电流，几百 mA ~ 1.2A（模块丝印：工作电流 1.2A / 峰值 3.2A） |
| **VCC** | ESP32 3V3 | 只有逻辑电流，几 mA |

**电池盒只装 2 节（3V）**，这是套件 TT 马达的额定电压。装 4 节给到 6V 就是超压一倍：同样负载下电流也跟着翻倍，电机温升大、寿命骤减，减速齿轮也会提前磨损。

> ⚠️ VM = 3V 比 VCC = 3.3V 略低，属于边界情况。TB6612FNG 的 VM 最低工作电压约 2.5V，芯片本身能撑住；但如果实测电机无力、模块发烫，或者逻辑不响应，就把 **VCC 也改接到 3V 电池正极**，让逻辑电平和 VM 同源。

所以 ESP32 的 3V3 引脚扛得住 —— 大电流全部从 VM 走电池，不经过开发板。

> 📌 部分 TB6612 模块板载 LDO，只喂 VM 就能自己产生逻辑电压；本项目模块的丝印 / 焊盘以实物为准。稳妥做法就是上面这样 VCC 单独接 3V3，两种模块都对。

**③ STBY 直接接 3.3V 常高。** 芯片始终使能，省一个 GPIO。代价是想让整块驱动"断电待机"时代码里没有办法，得手工拉低这根线 —— 本项目用不到待机，省下来更划算。

**电机接线不分极性**：AO1 / AO2 反接只会让转向反过来，不会烧东西。转向不符合预期就把电机拔下来对调。

AO1 / AO2 是模块一端的 2P 螺丝端子，松开螺丝 → 把电机两条裸线头插进孔里 → 拧紧。两侧金属片**彼此不连通**（AO1 和 AO2 是两个独立接点），别把一段导线同时搭上去 —— 那就等于把电机两端短接成刹车状态。

一条电机回路要分清三样东西，别拧错螺丝：

| 位置 | 是什么 | 作用 |
|---|---|---|
| 模块上的 **AO1 / AO2** | 2P 螺丝端子 | **接线的地方**，松/紧这两个 |
| 马达侧面的**金属小片** | 电机本体的电极 | 电从这儿进出电机，焊线或直接夹线 |
| 黄色外壳上那**两颗螺丝** | 马达的**结构紧固螺丝**（固定前后壳） | 纯机械件，**与接线无关，别拧** |

三样东西的实物对照见 [`TT马达.png`](./TT马达.png)。

> 选 GPIO10 / 11 / 12：避开 ESP32-S3 的 strapping 引脚（0 / 3 / 45 / 46）和 SPI Flash / PSRAM 占用的 26~37，也不碰 USB 的 19 / 20。

## 五、实验 1：正反转 / 刹车 / 滑行

[`实验1-电机正反转.ino`](./实验1-电机正反转/实验1-电机正反转.ino)

演示序列每 2 秒切一段：**正转 → 刹车 → 反转 → 刹车 → 滑行**，循环。灯色对应当前模式。

代码核心就是把真值表翻译成 `switch`：

```cpp
case M_BRAKE:                       // 两端同时拉低 = 短接制动
  digitalWrite(AIN1, HIGH);
  digitalWrite(AIN2, HIGH);
  ledcWrite(PWMA, 255);             // PWM 必须非 0，否则又退回高阻滑行
  break;
case M_COAST:                       // 两端都断开 = 自由转动
  digitalWrite(AIN1, LOW);
  digitalWrite(AIN2, LOW);
  ledcWrite(PWMA, 0);
  break;
```

> ⚠️ 刹车那行 `ledcWrite(PWMA, 255)` 是关键：`PWM = 0` 时输出端是高阻，与 IN 无关。所以"IN1=IN2=1 但 PWM=0"依然是滑行。**刹车 = 短接 + 有驱动能力**，两个条件都要满足。

### 怎么"看"出四种模式的区别

| 模式 | 灯色 | 电机表现 | 串口 |
|---|---|---|---|
| FWD 正转 | 🟢 绿 | 持续同方向转动 | `{"mode":"FWD","duty":180}` |
| REV 反转 | 🟠 橙 | 持续反方向转动 | `{"mode":"REV","duty":180}` |
| BRAKE 刹车 | 🔴 红 | **立刻停住**，用手拧不动 | `{"mode":"BRAKE","duty":255}` |
| COAST 滑行 | 🔵 蓝 | 靠惯性再转一会儿才停，用手能拧动 | `{"mode":"COAST","duty":0}` |

**刹车和滑行的区别要用手去确认**：刹车段电机停下的瞬间用手指去捻轴，能感到明显的阻力；滑行段一捻就跟着转。这一下就能把两个词彻底分开。

### 状态机写法

实验用 `millis()` 非阻塞节流，而不是 `delay(2000)`：

```cpp
if (millis() - modeStart < HOLD_MS) return;
modeStart = millis();
```

理由和 Day 18 一样：`delay()` 会堵住整个 `loop()`，板载 RGB 动画和串口输出全都跟着卡。用时间戳比较，切换动作只在一瞬间完成，其余时间循环是空的。

## 六、实验 2：PWM 调速

[`实验2-PWM调速.ino`](./实验2-PWM调速/实验2-PWM调速.ino)

固定正转方向（`AIN1=HIGH, AIN2=LOW`），duty 从 **220 渐变到 255**，到顶匀速 1 秒，再渐变回 220，循环。

- 步长 5，每步 40ms → 单向约 **0.3s**（220 → 255）
- 起转点实测落在 **180~220**（§八 第 1.5 步），所以起点就必须 ≥220，从 120 起爬会先在死区里白响 1.1 秒
- 串口同步打印 duty、百分比、对应平均电压
- 板载 RGB 亮度跟随 duty，方便和串口数字对照

```cpp
Serial.printf("{\"phase\":\"%s\",\"duty\":%d,\"pct\":%.1f,\"vavg\":%.2f}\n",
              PHASE_NAME[phase], duty, duty * 100.0 / 255.0,
              VM_VOLT * duty / 255.0);
```

输出长这样：

```
{"phase":"UP","duty":220,"pct":86.3,"vavg":2.59}
{"phase":"UP","duty":225,"pct":88.2,"vavg":2.65}
...
{"phase":"HOLD","duty":255,"pct":100.0,"vavg":3.00}
```

> `vavg` 按 `VM_VOLT = 3.0` 算，是**理论平均值**。实际电池用旧了会低于 3V，这个数只表示 duty 与电压的对应关系，不代表实测电压。

### 为什么从 120 起步而不是 0

因为 duty 太小电机根本不动。**死区**：驱动力矩必须先克服静摩擦和转子轴的摩擦，才会开始转。

死区高度由**平均电压**决定，不由 duty 数字决定 —— 把电池从 6V 换成 3V，同样的静摩擦就需要约两倍的 duty。6V 盒子上 duty 60 能起转，3V 盒子上得 220，具体值取决于电池新旧和轴的松紧。

```
duty 0   → 220：电机不动（静摩擦没被克服）
duty 220 → 255：电机越转越快，大致线性
```

这条是开环调速最现实的限制 —— **"duty = 0 到 起转点"这一段是浪费的**，代码以为在调速，实际什么都没发生。真正可用的只有起转点以上的那一段。

> ✅ 2026-09-20 实测（VM = 3V）：`DRIVE_DUTY = 180`（2.12V）电机只嗡嗡响不转，`220`（2.59V）正常起转。**本板的起转点落在 180 与 220 之间。** 3V 下最宽的那段可用区间是从 220 才开始。

> 📌 想测出这块板子的确切启动阈值，见 §十一 的死区扫描。

### 第 1.5 步：第一次上机实际结果（2026-09-20）

按 3V 接线（VM 接 2 节 5 号，GND 三处共地）后：

| 现象 | 实测值 | 判断 |
|---|---|---|
| RGB 循环彩灯 | 红/橙/绿/蓝正常轮换 | ESP32 在跑，代码没问题 |
| **AO1 / AO2 电压** | **1~2V** | ✅ 正常，是 PWM 平均值 |
| 电机 | **嗡嗡响，不转** | ❌ 平均电压 2.12V < 启动阈值 |
| 电池 3V 直供电机铜片 | 正常转动 | ✅ 电机本身没坏 |

**结论：驱动链路是通的，卡在 duty 不够。** `DRIVE_DUTY = 180` 在 6V 下是 4.24V，在 3V 下只剩 2.12V，低于 TT 马达带减速箱的启动阈值。

**改成 220 后四种模式全部验证通过**：2.59V 起转，绿灯同向、橙灯反向、红灯立刻停住（见 [视频](./实验1-电机正反转.MOV) 与 [串口截图](./实验1-串口打印.png)）。串口每 2 秒一行 JSON，`ain1` / `ain2` 与灯色一一对应，与真值表完全一致。

**教训：duty 该设多少不能只看百分比，要乘 VM。** 同一个 70.6%，在 6V 和 3V 下是两个完全不同的世界。3V 系统里"能用的 duty 区间"被死区从上面吃掉一大截 —— **这块电机在 3V 下的起转点落在 180 与 220 之间**（2.12V ~ 2.59V）。

### 第 2 步（实验 2：PWM 渐变）

| 检查项 | 预期 | 实测 |
|---|---|---|
| duty 120 起 | 电机是否已转动？记录实际启动 duty | ❌ 不转，只嗡嗡响（< 起转点 180~220） |
| duty 220 → 255 | 转速单调上升，无抖动、无尖叫 | ✅ 转起来了，肉眼接近匀速 |
| duty 255 匀速 1s | 转速稳定 | ✅ |
| duty 255 → 220 | 转速单调下降，直到停住 | ✅ 减速后未停即回升，形成连续循环 |
| 噪声 | 5kHz 应基本听不到啸叫 | ✅ 无啸叫 |
| RGB 亮度 | 跟随 duty 同步变化 | ⏳ |

见 [`实验2-PWM调速.MOV`](./实验2-PWM调速.MOV) 与 [`实验2-串口打印.png`](./实验2-串口打印.png)。

`START_DUTY` 最终取 **220**。3V 下若从 120 起爬，每循环前 1.1 秒（duty 120→220，平均电压 1.41V→2.59V）都落在死区里，电机只响不转 —— 这不是故障，是平均电压还没克服静摩擦。代价是 220 起只覆盖 duty 轴最后 14% 的区间，**3V 下最宽的可调区间被死区从下面吃掉了**。

方向固定正转：`AIN1` 恒高、`AIN2` 恒低，实验 2 永远不会反向（反向要动这两根，属实验 1）。

转速并非匀速，是 220 →255（约 0.23s）→ 匀速 1s → 255→220（约 0.23s）的循环。因为只有 7 步、步长 5/255 = 2%，体感就是匀速，真实曲线只能从串口的 `duty` / `pct` / `vavg` 看。

**"减速到停"这一段在 3V 下永远看不到。** 原设计是渐变回起点直到电机停住，但 `START_DUTY` 被死区顶到了 220 —— `P_DOWN` 一回到 220 就立刻切回 `P_UP`，电机始终在起转点之上，只会持续转。想看"越转越慢最后停"，前提是起点低于起转点，而 3V 下起转点是 220，起点只能 ≥220。这是死区对演示完整性的直接破坏，比掉转速更隐蔽。

**串口暴露了代码里看不到的两件事**

① **HOLD 段串口会静默约 1 秒**。duty 到 255 后进 `P_HOLD`，此时 duty 不再变化，`if (duty != printedDuty)` 把重复行全过滤掉了 —— 所以从 `duty:255` 到下一行 `DOWN, duty:250` 的空档正是匀速那 1 秒。实测 12:03:37.588 → 12:03:38.681，间隔 1.09s。

② **爬一步实际约 33ms，不是设定的 40ms**。`STEP_MS = 40` 是两次 `loop()` 的最小间隔，`Serial.printf` 本身还要花几毫秒，且 `millis()` 的调度粒度让它略短。220→255 七个台阶实测约 0.23s。想做精确时序别指望 `millis()` 节流加串口打印的组合。

完整一个循环：220→255（0.23s）+ 匀速（1.09s）+ 255→220（0.23s）≈ **1.55s**。

### 第 3 步（开环漂移验证）

同一个 duty = 200，分两次记录转速感受：

| 条件 | 预期 |
|---|---|
| 新电池 | 较快 |
| 电池用一会儿后重测 | **明显变慢**，而代码一个字节都没改 |

这一步能亲手证明 §三 末尾那句"开环不知道实际转速"。

## 九、出了什么问题 & 怎么修

✅ 已实测：第一次上机的核心问题是「电机嗡嗡响但不转」，根因是 3V 供电下平均电压掉进死区，见第 1.5 步。下表是按原理预判的高频问题，供后续对照查询。

### 通用症状表

| 症状 | 原因 | 修复 |
|---|---|---|
| **电机完全不转，串口正常** | ① 没共地 ② STBY 没接高 ③ VM 没电 | 共地是首要怀疑对象；量 VM-GND 应为电池电压 |
| 电机只往一个方向转 | IN1 / IN2 有一根没接或接错 | 对照 §四 逐根核对 |
| `IN1=IN2=1` 时电机还在滑行 | PWM = 0 | 刹车必须 `ledcWrite(PWMA, 非0)` |
| duty 很小电机不动 | 死区（正常现象） | 提高起始 duty，见 §六 |
| **电机嗡嗡响但不转** | 平均电压低于启动阈值：duty 180 × VM 3V ≈ 2.12V，掉进死区 | 提 duty 到 220 以上；或确认 VCC / STBY 有 3.3V、AO1/AO2 端子拧紧 |
| **AO1/AO2 只测到 1~2V** | 不是故障 —— 万用表跟不上 5kHz，读的是 PWM **平均值**：3V × 180/255 ≈ 2.12V | 正常值。若读 0V 才是没输出，3.3V 才是常通 |
| 电机嗡嗡响但不转 | 堵转 / 电压过低 / 负载卡死 | 断电，用手捻轴确认能自由转动 |
| **实验 2 烧录后"一直"响不转** | 代码上不可能：duty 每 40ms +5，1.1s 内必穿过起转点。实际是 `START_DUTY` 太低、爬坡全程落在死区，或 IDE 里打开的不是最新代码 | 把 `START_DUTY` 提到 220；同时看串口 `duty` 有没有一路上涨 —— 停在 120 说明烧的是旧代码，涨到 255 还不转才是物理问题（端子松 / 掉压 / 带负载） |
| 驱动芯片烫手 | 长时间堵转 / 直通 / 散热不够 | 立即断电；查 IN1 IN2 是否同时为高且 PWM 非 0 之外的异常组合 |
| 电机转速忽快忽慢 | 电池内阻大、电流不足 | 换新电池；电池盒弹簧接触也要查 |
| 上电时 ESP32 重启 | VM 的电流窜扰逻辑电源 | 确认 VM 与 VCC 没有接反；共地可靠 |
| `ledcSetup` 编译报错 | 用了旧 API | 改 `ledcAttach(pin, freq, res)`，见 §七 |
| 换向后电机"咯噔"一下 | H 桥死区 + 机械间隙，正常 | —— |

### 共地为什么是头号嫌疑

```
ESP32 GND ──┬── 模块 GND
            └── 电池负极

少了任何一根，模块的"地"和 ESP32 的"地"就不是同一个电位。
GPIO 输出 3.3V 是相对 ESP32 地，模块看到的是另一个值，
IN1 / IN2 的电平判定就全乱了 —— 表现就是"代码明明在跑，电机没反应"。
```

## 十、与《逐日指南》的出入

| 指南原文 | 本 README | 理由 |
|---|---|---|
| VCC → 5V（逻辑） | **接 3V3** | ESP32-S3 GPIO 输出 3.3V 逻辑，VCC 与 GPIO 同电位最稳 |
| STBY → GPIO16 | **直接接 3.3V 常高** | 省一个 GPIO；本项目不需要驱动芯片待机 |
| `ledcSetup(0, 5000, 8)` + `ledcAttachPin(PWMA, 0)` | **`ledcAttach(PWMA, 5000, 8)`** | Core 3.x 已删除旧 API |
| 刹车：`digitalWrite(AIN1, LOW); digitalWrite(AIN2, LOW);` | **`AIN1=HIGH, AIN2=HIGH` + PWM 非 0** | 两端拉低是**滑行**不是刹车，见 §三 真值表 |
| AIN1/AIN2 → GPIO10/GPIO11，PWMA → GPIO12 | ✅ 沿用 | 避开 strapping 与 Flash/PSRAM 引脚 |
| 转速渐变 | ✅ 沿用 + 串口输出 duty/百分比/平均电压 | 延续 JSON 输出约定 |
| 接线示意图 | ✅ 用文字拓扑图 | 保持仓库纯文本风格，图片只放实测截图 |

> 原则：**能省的元件就省。** 一根电机、一个驱动模块、一个电池盒，零电阻零电容零二极管，全部直接连。

## 十一、选做 / 进阶

以下都是**非必须**的补强项，按兴趣挑。

### 本日可做的待办

- ⏳ **死区扫描**：duty 从 0 开始每 200ms +1，串口打印当前值，肉眼记录电机从第几个 duty 开始转动。这是开环调速最实用的一个常数 —— 之后所有调速代码都该从它起步，而不是从 0 起步。
- ⏳ **实测 B 通道**：TB6612FNG 有两路，B 通道接第二个电机（`BIN1/BIN2/PWMB`），Day 21 小车必然用到。今天先按 A 通道的写法复制一份，确认两路互不干扰。
- ⏳ **补拍接线与实测截图**：电机四种模式的灯色、渐变时的串口输出。

### 进阶方向

- ⏭️ **PWM 频率对比**：改成 20kHz 再跑一遍，对比啸叫和力矩脉动。顺带观察 MOSFET 温度变化。
- ⏭️ **S 形加减速曲线**：现在 duty 是线性变化，起步/停止会有冲击。改成"慢-快-慢"的梯形或 S 曲线，机械更柔。
- ⏭️ **差速转向**：两个电机用不同 duty 实现转弯（左轮 duty 高、右轮 duty 低 = 右转）。Day 21 小车的核心控制逻辑，可以先在桌面空转验证。
- ⏭️ **编码器闭环测速**：码盘 + 光电对管接到 GPIO 中断，测出真实 RPM，再用 PID 稳住。需要额外买对管模块。
- ⏭️ **电流检测**：TB6612FNG 的 AO 端可采样电阻电压换算出电流，用于堵转保护和力矩估算。对照模块丝印"工作电流 1.2A / 峰值电流 3.2A"，可以判断手上的电机余量还有多少。
